## ⑤ X/Twitter 格局与可入库性

> **一句话诚实结论:AI 编程好内容不是「只在 X」。** X 是最快的**发现/讨论/风向层**,但真正成体系、可入库的深度内容,绝大部分以 **YouTube 大会演讲 + 播客**的形式活在 X 之外。X 更像「演讲的索引/入口」,不是内容本身。

**证据**:X 上跑量最大的 AI 编程帖,形式就是**「搬运层」账号把别处长演讲剪成短片 + 一条 thread 引流**(实拉到的高热帖:「Boris Cherny 10 分钟演讲比 500 刀课还值,今天就看」50 万浏览;「造 Claude Code 的工程师放了个 28 分钟视频…看完再读指南」67 万浏览)——本质是演讲的索引。头部个人(Simon Willison、swyx、Theo、Gergely)的深度身体都在**会议演讲/播客**上,X 只是短 take + 引流链接。

**可入库性逐类**:
- **X 文字 thread → ❌ 吃不了**(无音频;对应的博客也是纯文本,同样不在「转写」管道射程)。
- **X Spaces(直播音频)→ 🔶 技术可行但性价比低**:仅主持人开录才有回放、30 天后消失、无官方稿(得走自家 VAD+ASR);且【未验证】**没搜到固定的、录制的 AI 编程 Spaces 节目**,这圈 Spaces 更像临时 AMA。不建议当主力。
- **X 视频/演讲片段 → ⚠️ 多是 YouTube/会议长演讲的剪辑**:别吃 X 那份,**顺藤解析回源头 YouTube/会议长视频**再喂管道。

**落地建议(agent 判断,非事实)**:不要建「原生吃 X」的能力(投入产出差)。把 X 当**侦察/线索层**——盯一份 AI 编程账号清单 → 他们剪/链的演讲播客 → 解析回源头(YouTube/播客 RSS)→ 走现有管道。真正的增量是**定向抓 AIE CODE 这类「纯 coding-agent 演讲合集」**,但这会撞上你们记录在案的 **YouTube 云端抓取障碍**(见 `调研-内容获取可行性.md`;现管道靠 Mac mini 巡航下 YouTube 音频再上云,不是加个 RSS 就行)——这条得先解。
