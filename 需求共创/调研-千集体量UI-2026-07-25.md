## 一、无封面 + 大体量文字站:卡片怎么不单调、上千条怎么收敛

抓了 15 个站(Stratechery / Every.to / Astral Codex Ten / Slate Star Codex / The Browser / Platformer / Hacker News / Longform / Marginal Revolution / Paul Graham / Simon Willison / gwern / kottke / Wait But Why / Daring Fireball)。

### 直接可迁移的做法(每条注明出处)

1. **一句话 dek + 完整长日期,当封面图的替身**
   [Stratechery /category/articles/](https://stratechery.com/category/articles/) 【实测】超大标题 + 完整长日期(`Monday, July 20, 2026`,不是 7/20)+ 一句 dek + 分隔线,**整页 9 个 `<img>` 全是 logo/图标**。长日期本身是一块灰色排版元素,给标题当基座。
   [Platformer](https://www.platformer.news/) 【实测】更进一步:dek 尾巴塞 `PLUS: …` 把当期次要话题也带上,一张卡两个钩子。

2. **一行「非内容型小徽章」制造彩色纹理** —— 无图站的视觉噪点全从这来
   【实测】Stratechery:`Listen to Podcast` / `Watch on YouTube` 带图标行动标签 · [The Browser archive](https://thebrowser.com/archive/):`Free` 权限徽章 + `2 min read` 阅读时长 · Platformer:付费锁图标 · [Hacker News](https://news.ycombinator.com/):来源域名 + 点数 + 提交者 + 评论数(**三条元数据全是「别人怎么看」而不是「内容讲什么」**)。

3. **条目版式异构,一千条别长一个样**
   [Simon Willison](https://simonwillison.net/) 【实测】流里三种版式交替:引用型(`div.quote` = 引文 blockquote + 出处人名)、链接型(`div.blogmark` = 加粗标题 + 带内链评论 + 内嵌 blockquote)、笔记型。同一列自然起伏。
   → **对本站直接可用:把「金句突出型」做成一种独立卡片版式**,隔几条出现一次。

4. **标题长度可以为排版而改写**
   [gwern.net](https://gwern.net/) 【实测】页面源码里留着作者自述注释(`<!-- NOTE: this </index> page rewrites titles… -->`):这个索引页会**改写标题让它变短、长度接近**,好让多列排版形成均匀文字块,理由明写是为第一次来的读者的第一印象。中文没有词间空格,长短不齐更扎眼。

5. **每个筛选入口挂条数;长尾标签设阈值 + 留「Show all」逃生口**
   [Longform /sections](https://longform.org/sections) 【实测】18 个大类全带条数(Crime 2212、Arts 1672、Fiction 1209…);[Longform /tags](https://longform.org/tags) 顶部写 **"Showing 758 tags with 10+ posts. Show all."**;另有 `/archive` 门户页只三行:`Publications 1468 / Writers 6650 / Tags 11199`。
   Simon Willison 首页顶部一行热门标签带条数:`On webassembly 129 / openai 434 / anthropic 315 …`。
   → 条数一举两得:给陌生人「这站有多厚」的证明,给站主「哪个主题攒够了」的判断。

6. **「start here」要写成有旁白的路线,不是一个 best-of 列表** —— 三种成本档位都有样本
   [Slate Star Codex /top-posts/](https://slatestarcodex.com/top-posts/) 【实测·最完整】不是列表是**一篇导读散文**:先按「你受不受得了长文」分流,再按主题分段,每段先说「我为什么写这个领域」,每篇给一句话说明。
   [Paul Graham articles](https://www.paulgraham.com/articles.html) 【实测·极简版】页面第一句就是「不确定读哪篇就试这三篇」,HTML 里还留着被注释掉的旧推荐 → **这份名单是手工换的**。
   [gwern.net](https://gwern.net/) 【实测】`Popular` 与 `Notable` **并排两栏** = 大家爱看 vs 我认为重要。

7. **首页可以完全不放文章列表**
   [The Browser](https://thebrowser.com/) 【实测】首屏顺序:一句话定义 → 订阅按钮 → "Join 150,000+ delighted readers" → 名人推荐语 → **一段明写的选稿标准**("Would we go out of our way to recommend the piece to friends? … Will it still be worth reading a month or a year from now?")→ 四条卖点 → 「Read a sample edition」。全站 8051 篇一篇不在首页露面。
   [Platformer](https://www.platformer.news/) 【实测·折中版】首屏一句话**同时说清主题和更新节奏**:"News at the intersection of Silicon Valley and democracy. On Monday, Tuesday, and Thursday at 5PM Pacific."

### 【抓不到】
- Marginal Revolution:curl 两次均 **403**(换 UA/Accept/gzip 无效),只能靠 WebFetch 拿正文,卡片标记级证据缺失。
- 移动端全部是 **CSS/标记级证据,不是渲染实测**(Browser 工具被策略拦截,无法真机截图)。凡写断点/media query/viewport 的是【实测·读源码】,写「多列→单列」的是【推断】。
- Longform `Best Of` 各年份页猜的 URL 返回 404,**内部长什么样没验到**。
- Every.to 全量归档页没找到(`/archive` 返回 200 但正文空)。
- ⚠️ Longform(2024-06 停更)、SSC(2021 后不更)是**已冻结归档站**,设计反映 2021–2024 做法,非 2026 新界面。

## 二、上千集播客库:怎么让人不被淹死

抓了 8 个(Lex Fridman / Huberman Lab / Tim Ferriss / Acquired / a16z / Podcast Notes / Snipd / 小宇宙 web)。

### 直接可迁移的做法

1. **全量列表做成零图纯文本行,图片配额全砸首屏精选**
   [Lex Fridman /podcast/](https://lexfridman.com/podcast/) 【实测·DOM 逐字】整页三个 `<h3>`:`Latest Episodes`(4 条,带图)/ `Some Select Recent Episodes`(人工精选,带图)/ `All Episodes`(**497 条 `div.episode-item`,该区块内 `<img>` 计数 = 0**)。
   → 本站没有单集封面,**这不是妥协而是正解:别去凑图,承认列表是文本**。

2. **文本行第二字段用「人 + 头衔」,不要用日期** ← 直接支持本轮拍板 #6
   【实测】Lex 每行第二行 = `嘉宾名 - 嘉宾头衔 - Video|Episode|Transcript`,例 `Anthony Kaldellis - Historian`、`Jensen Huang - CEO of NVIDIA`。上千条时日期几乎零区分度。
   反向印证:[小宇宙 web](https://www.xiaoyuzhoufm.com/podcast/60de7c003dd577b40d5a40f3)【实测·解析 `__NEXT_DATA__`】声动早咖啡 `episodeCount: 1021`,列表行**不渲染封面**,靠「时长 · 相对时间 · 播放数 · 评论数」四件套顶住 → **无图列表必须有一行密集元数据,只留标题会塌**。

3. **首屏必须有人工精选,而且拆成两条不同的路**
   【实测】四个高集数站四个都有,**且全是人工手挑,没有一个用算法热门榜**:
   - [Acquired](https://www.acquired.fm/episodes):`Must-Listen`(必听)+ `Niche Gems`(冷门佳作)+ `Interviews` 三条 playlist 并列
   - [Tim Ferriss](https://tim.blog/podcast/):`Featured interviews` = 15 张嘉宾插画肖像格
   - [Huberman Lab](https://www.hubermanlab.com/all-episodes):`Essentials`(既是卡片 chip 又是筛选项)
   - Lex:`Some Select Recent Episodes`
   - [gwern](https://gwern.net/) 同理:`Popular` / `Notable` 并排

4. **筛选器和卡片用同一套词**
   [Huberman](https://www.hubermanlab.com/all-episodes)【实测·DOM】六个筛选 checkbox(`Guest Episode / Solo Episode / Essentials / AMA / Guest Series / Journal Club`),同一个词又以 `chip-category` 徽章印在每张卡上 → 用户扫几张卡就学会了这套分类,再用筛选器零学习成本。

5. **文末给两种「下一步」,不要只给一种**
   【实测】Acquired:`more in the series`(同系列)+ `you may also enjoy`(相似)**双出口**;Huberman:`Related episodes` ×3 + `Find more content about <主题>`;Podcast Notes:`More Notes on these topics`。
   → 读完一篇的人分两类:想顺着这个主题挖下去 vs 想换个口味,**同一个出口喂不了两种人**。

6. **金句位置有两种被验证的做法,二选一**
   [Tim Ferriss 单集页](https://tim.blog/2015/08/18/the-evolutionary-angel-naval-ravikant/)【实测】**一句大字 pull quote 放在正文最前面**当钩子。
   [Podcast Notes 单条笔记](https://podcastnotes.org/art-of-manliness/beyond-midlife-myths-why-middle-age-can-be-your-prime-time-margie-lachman-on-the-art-of-manliness-with-brett-mckay/)【实测】反过来:**不做独立引用块**,引语嵌在 bullet 文本里加引号,只靠加粗打头的要点分层。
   → 前者适合「先勾住陌生人」,后者适合「已经在读的人不被打断」。

7. **搜索做语义 + 索引正文,结果能挂回母集**
   [Huberman]【实测·读 JS】用 Meilisearch 且开了 **hybrid 语义检索**(`searchOptions.hybrid = { embedder: 'hubermanlab' }`),索引 `name` + `description`;结果卡带 **`From Episode` + 母集标题**,把片段挂回整集。
   Podcast Notes 单开 [/ai-search/](https://podcastnotes.org/ai-search/) 当 Premium 卖点;Snipd 卖点是全文转写搜索 + `Chat with Episodes`。
   → **三家精华类产品都把这个当付费点,而本站天然就有完整中文长文语料。**

### 🔴 对「按人物」这一层的直接回答
【实测】**8 个站里 0 个做了独立的嘉宾索引页/嘉宾墙。** 人物只以三种形态出现:
① Lex:嘉宾名+头衔当列表行主字段(列表本身即人名录);② Tim Ferriss:首屏 15 张人工挑的嘉宾肖像;③ Huberman / Podcast Notes:嘉宾名塞进标题字符串,靠搜索兜底。
(Podcast Notes 的 `A-Z All Categories` 500+ 是按**节目**分,不是按嘉宾。)
→ **本站已有的实体页/人物页没有先例可抄,属原创设计,要当假设验证,不能当既定最佳实践。**

### 【抓不到】
- **Listen Notes**:403 + Cloudflare 人机验证页,**未实测**(不绕验证码)。
- **Lenny's Podcast**:301 跳 Substack,纯客户端渲染,curl/WebFetch 只拿到订阅墙;archive API 取不到 podcast 类型;浏览器工具被策略拦截。**未实测,不下任何结论**(注意:这正是本站的主力源)。
- 手机端差异除 Huberman(`col-lg-4/col-sm-12`、筛选条 `overflow:auto; scrollbar-width:none` 横滑)和 Lex(无响应式栅格类)外,**其余站未测**。
- Podcast Notes 付费墙的免费/付费划线规则、Huberman 完整转写是否全付费:**未验证**。

## 三、第二层收敛的实例、静态站 faceted 方案、Quartz v5 定制上限

### 3.1 第二层收敛实例

**[Maggie Appleton /garden](https://maggieappleton.com/garden) — 三轴正交,最接近本站需要**【实测·扒 HTML】
- 一级 = 内容类型(导航 8 项)→ 二级 = **三个正交轴同时筛**:`Topics` 38 个 / `Growth Stages`(Seedling / Budding / Evergreen 成熟度)/ `Types`(Essays / Notes / Patterns / Talks / Podcasts / Smidgeons / Now Updates)
- 机制:Astro 站,**165 条全部渲染进 HTML**,每条 `.grid-item` 带 `data-topics` / `data-type` / `data-growth-stage`;筛选是**约 15 行内联 JS**,只给不匹配元素加 `filtered-out` class。三轴 AND,轴内多选 OR。**零索引、零请求。**
- 代价【实测】:该页 HTML **319 KB**(约 1.9 KB/条)。

**[ssp.sh/brain](https://www.ssp.sh/brain/) — Quartz 站上真做了双轴 facet**【实测】
- sitemap 506 页,搜索索引 761 条。一级 = 8 主题大类 → 二级 = 手写 MOC 枢纽页 + 搜索框内双轴 facet(`filter-source`: All/Blog/Brain;`filter-date`: Any time/This year/Last 2 years)。
- **他换掉了 Quartz 自带搜索**,自建 `searchIndex-v2.<hash>.min.json`。实测下载:**4.93 MB 原始 / 1.73 MB gzip**。
- ⚠️【实测】他的标签卫生塌了:236 个 tag 中 **116 个只出现过一次**,且 `data engineering` 与 `Data Engineering` 大小写分裂成两类。

**[gwern.net/index](https://gwern.net/index) — 纯层级,不做筛选**【实测】一级约 30 主题段 → 二级段内嵌套小标题;另有 tag 目录树 [/doc/index](https://gwern.net/doc/index) 自报 **525 个 tag**,路径深达 4–5 层(`ai/nn/transformer/gpt/2/fiction`)。**无任何筛选/排序 UI。**

**[Andy Matuschak notes](https://notes.andymatuschak.org/) — 反例**:明确不做索引导航,只给一个入口 note。规模与目的不同,不可复制。

**[turntrout.com](https://turntrout.com)**【实测】sitemap 只有 **160 页**(不是上千);[仓库](https://github.com/alexander-turner/TurnTrout.com) 2026-07-24 仍在推,自建 `AllPosts.tsx` / `AllTagsContent.tsx` / `TagContent.tsx`,**无 facet 筛选**。它证明的是「Quartz 能被改到面目全非」,**不是「扛得住上千页」**。

### 3.2 静态站 faceted 方案现状

**[Pagefind](https://github.com/Pagefind/pagefind)(5358 star,2026-07-23 仍在推)是唯一开箱即用的完整 facet 方案**【实测·读官方文档源码 `docs/content/docs/js-api-filtering.md`】:
- 索引期在 HTML 上打 `data-pagefind-filter="author"` 之类属性
- ✅ **空查询纯浏览**(本站最需要):文档明写传 `null` 即可 —— `pagefind.search(null, { filters: { author: "CloudCannon" } })`
- ✅ **facet 实时计数**:`pagefind.filters()` 返回每值条数;结果里另有 `filters`(叠加后剩几条)/ `totalFilters`(换成此筛选剩几条)/ `unfilteredResultCount` → **就是「点一个标签,其它标签实时显示剩余数量」**
- ✅ 完整布尔 `all/any/none/not`,可嵌套;索引按字母分片懒加载

### 3.3 Quartz v5 定制上限 —— ⚠️ 先纠正本项目一条过期前提

【实证】`GET api.github.com/repos/jackyzha0/quartz` → **`"default_branch": "v5"`**(12850 star,2026-07-24 仍在推),tag `v5.0.0` 存在。
→ **本项目 CLAUDE.md「Quartz 定制全部收进独立组件,不散改 fork(v5 太新,留合并余地)」的前提已过时。**
⚠️ 陷阱:GitHub **Releases 页最新条目仍是 `v4.0.8`(2023-08-21)** —— v5 没发 Release 对象,只有 git tag + 文档。**查 Releases 会得到假阴性。** 官方公告在 `docs/getting-started/whats-new.md`。

v5 是一次重架构:`quartz.config.ts` + `quartz.layout.ts`(TS)→ **`quartz.config.yaml`(YAML)**;单体仓库 → 约 50 个 `@quartz-community/*` 独立插件包;要求 **Node ≥ 22**。

| 需求 | v4 | **v5**【实测】 |
|---|---|---|
| **自己写首页组件**(不走 markdown) | 官方无机制,[issue #1116](https://github.com/jackyzha0/quartz/issues/1116) 给的是「组件内按 slug 提前 return null」的绕路;社区 PR #1835 未合并 | ✅ **一等公民**:Page Type 插件(`quartz/plugins/types.ts`)有 `match` / `generate`(可造无 md 源文件的虚拟页)/ `frame`(`default`/`full-width`/`minimal`)/ **`body` 直接吃你的组件** |
| **去掉 explorer / graph / bases** | 改 fork | ✅ **改 YAML 即可**:三者在默认配置里都是插件条目,`enabled: false`。按页类型保留用 `layout.byPageType.<type>.positions.right: []` |
| **首页无侧栏** | 改 layout | ✅ `frame: full-width` |
| **卡片流读 frontmatter** | 官方无卡片布局,[issue #1986](https://github.com/jackyzha0/quartz/issues/1986) 维护者倾向「等 Obsidian Bases」,提问者自述 CSS hack 很 hacky | ✅ 组件拿得到 **`allFiles: QuartzPluginData[]`**,文档原文说它就是 "Useful for doing page listings" |

**实例佐证**【实测】turntrout.com 的 fork 里 `quartz/components/` 只剩 21 项,**`Explorer.tsx` / `Graph.tsx` 根本不存在**(v4 原版 32 项含二者)—— 彻底删掉可行且有人在生产跑。

### 3.4 🔴 三个必须知道的坑

1. **Bases 解决不了读者侧筛选** —— 直接推翻本项目 C10 的「三视图页签」路线作为收敛手段
   【实测·插件文档原话】base 视图是**构建期烘焙的服务端渲染 HTML,不在客户端更新**;客户端交互只有**切换视图页签**和**表格列排序**。**筛选谓词由作者在构建期写死。** 要给读者多选筛选就得为每种组合预生成一个 view → **组合爆炸**。
   → Bases 给的是**作者**一门查询语言,不是**读者**一个筛选器。

2. **Quartz 内置搜索是上千条时的真实成本(不是构建时间)**
   【实测】它把**每页全文明文**塞进单个 `static/contentIndex.json`,客户端整包下载后在浏览器重建 FlexSearch 索引。**v5 未改此设计。** 实测各站:

   | 站点 | 页数 | 原始 | gzip |
   |---|---|---|---|
   | jzhao.xyz(作者自己的园子) | 793 | 2.57 MB | 0.94 MB |
   | turntrout.com(长文) | 160 | 2.82 MB | 0.96 MB |
   | ssp.sh(自建 v2 索引) | 761 | 4.93 MB | 1.73 MB |
   | **aarnphm.xyz(自定义剔除 content)** | **1878** | **1.17 MB** | **0.16 MB** |

   → 1000 页 stock Quartz 约 **2–5 MB 原始 / 0.6–1.7 MB gzip**,长文站更高。**本站是长文站。**
   **解法有实证先例**:剔掉 `content` 字段。拿 ssp.sh 那 761 条真实数据实算:全量 5.01 MB / 1.73 MB gzip → **仅 facet 字段 0.11 MB / 0.023 MB gzip,gzip 后小 76 倍**;外推 1000 条 = 2.28 MB vs **30 KB**。

3. 🟡 **标签卫生是第二层收敛的真正杀手,不是技术** —— ssp.sh 实测 236 tag / 116 个只用一次 / 大小写分裂。
   → **本站二级维度必须是受控词表(封闭枚举),不能让 GLM 流水线自由生成。** 本项目 8 大类词表 + `validateExtract` 硬卡的纪律**正好是对的**,二级维度要照搬这套。
