[[GrokBot|GrokBot]] 有一个杀手级功能：每个[[连接器|连接器]]——不管是 Gmail、Slack 还是 [[MCP|MCP]]——都能同时挂多个账号。如果你像主播一样有四个邮箱、七个 Slack 工作区，一个[[智能体|智能体]]就能遍历所有这些账号帮你干活。

Claude 没做到，Codex 也没做到 <button class="pd-ts" data-t="05:04" data-who="嘉宾" data-en="even if it's the same service. ## GrokBot 的好用与不好用

好用的地方全在连接器和简洁度。主播的做法是按角色建智能体——产品经理、数据分析师、交易台、财务、家庭管理——每个角色配它需要的工具和指令 <button class="pd-ts" data-t="10:10" data-who="嘉宾" data-en="A couple of use cases that I think you could use GraphBot for. Again, I like to make my agents have roles. So I made a PM one." aria-label="回原文"></button>。[[多智能体|多智能体]]策略配上多账号连接，是企业场景的真正卖点 <button class="pd-ts" data-t="04:52" data-who="嘉宾" data-en="This is something that Codex has not figured out. Claude has not figured out. No one seems to figure out that I have There's approximately a dozen email address" aria-label="回原文"></button>。

不好用的地方也源于简洁。你选不了模型，没有类似 sole.md 那样的细粒度配置控制，不能"像捏泥巴一样"塑造你的智能体 <button class="pd-ts" data-t="08:25" data-who="嘉宾" data-en="The other thing I don't like about GrokBot is you don't get to pick what model you're working with. You really actually don't get to have that sort of like sole.md control" aria-label="回原文"></button>。

它跑在第三方系统上，不在你本地机器上 <button class="pd-ts" data-t="09:00" data-who="嘉宾" data-en="OpenClaw or Hermes or any of those is a little bit more like that. And then, of course, it doesn't run on my machine. I don't have control over it." aria-label="回原文"></button>。还有一个很主观但很关键的问题：不管底层用的是 Grok 还是别的什么，输出的语气充满典型的 AI 味——糟糕的产品命名、永远不会说的话——跟精心调过人格的 OpenClaw 比起来，"感觉很差"，不想跟它聊天 <button class="pd-ts" data-t="09:16" data-who="嘉宾" data-en="I would say just related to that, the last thing that I don't love about GrokBot is whatever model it's using, and maybe it's Grok, maybe it sounds a lot like Claude Slop, is I just know vibes." aria-label="回原文"></button>。

## Origin：智能体原生的 GitHub 替代品

[[Origin|Origin]] 是 [[Cursor|Cursor]] 发布的 [[GitHub|GitHub]] 竞争者，还在 early beta 阶段。核心思路是"智能体原生的代码托管"：保留所有 Git 原语——代码、diffs、pull requests——但 UI 和交互方式是为智能体协作设计的，特别是 Cursor Cloud 智能体、桌面应用和 CLI <button class="pd-ts" data-t="12:53" data-who="嘉宾" data-en="which is, of course, the right primitive for something that is code hosting. Now, the whole value proposition that Cursor has put in front of us in terms of why they should build a GitHub replacement is they are basically building" aria-label="回原文"></button>。智能体可以在 PR 里回复评论、被指定为审查者 <button class="pd-ts" data-t="14:01" data-who="嘉宾" data-en="It has pull requests, which you can see. Agents can reply to comments. They can be assigned as reviewers, all those sorts of things." aria-label="回原文"></button>。

实际体验呢？目前对 GitHub 仓库的导入基本就是 GitHub API 的封装，界面重新设计过，有一些智能建议，但功能比 GitHub 少，深度绑定 Cursor 生态 <button class="pd-ts" data-t="15:03" data-who="嘉宾" data-en="What I would say is with the GitHub integration, it's really, it seems like it's just a wrapper on the GitHub API. So yes, in theory, this has been kind of redesigned." aria-label="回原文"></button>。

如果你已经在 GitHub 上有大量投入——自动化流程、Actions、代码所有者规则——现在没有足够的理由迁移过来 <button class="pd-ts" data-t="16:54" data-who="嘉宾" data-en="But again, if you have invested deeply in GitHub, which everybody has," aria-label="回原文"></button>。主播测试时还赶上 GitHub 大故障，导入本身就遇到了问题 <button class="pd-ts" data-t="14:29" data-who="嘉宾" data-en="Very smart. Was not smart to release this the day that GitHub had a major outage, or maybe it was genius to release this the day that GitHub had a major outage." aria-label="回原文"></button>。结论是：愿景能看到，地基在打，但"开箱即用没给我带来惊喜" <button class="pd-ts" data-t="18:05" data-who="嘉宾" data-en="They just want to get their claws in me and then really wow me with this experience. But out of the box, I'm not yet feeling the vision, although I'm excited to see how this plays out." aria-label="回原文"></button>。

## Grok 4.6 模型实测

主播用自己的 How I AI Vibebench 做了盲测，覆盖 PRD 撰写、原型设计、测试设计、线框图、技术变更、对话体验。评分权重是 70% 主播主观品味 + 30% 用 GPT-5.5 做的 LLM 评判 <button class="pd-ts" data-t="19:32" data-who="嘉宾" data-en="I want to talk about the How I AI Vibe Review for anybody who is new. Whenever a new model comes out, I do a couple things. I test PRDs," aria-label="回原文"></button>。

总分上，[[Grok 4.6|Grok 4.6]] 和 GPT 5.6 sol 并列第一，击败了 Claude Sonnet 5 和 Opus 5 <button class="pd-ts" data-t="20:55" data-who="嘉宾" data-en="And interestingly enough, Grok 4.6 is right up there with my favorite 5.6 soul beating out both Sonnet 5 and Opus 5 on the Claire Index." aria-label="回原文"></button>。但拆开看很有意思：把主播品味去掉，LLM 评委讨厌 Grok、偏爱 Claude Opus 和 Sonnet <button class="pd-ts" data-t="25:08" data-who="嘉宾" data-en="Now, what's really funny about this, again, this is 70% my taste, 30% the LLM as a judge. If you take my taste out of it, The LLM hates Grock and it loves Claude Opus." aria-label="回原文"></button>——说明 Grok 4.6 的优势很"人味"。

具体到任务：PRD 直接撰写仍是 5.6 最强，写作干净、全面、适度技术化 <button class="pd-ts" data-t="21:25" data-who="嘉宾" data-en="Now, if you look at the overall recommendation by task, you'll see that 5.6 is my favorite direct writer on PRDs. I just like the clean way of writing." aria-label="回原文"></button>；技术 Bug 分类 LLM 评委给了 Opus 5 最高分 <button class="pd-ts" data-t="21:44" data-who="嘉宾" data-en="And so I rated those quite highly. Opus 5 got graded by the LLM as a judge as the best implementer for a technical like bug triage problem." aria-label="回原文"></button>；开放智能体闲聊体验，Sonnet 5 继续无敌 <button class="pd-ts" data-t="21:56" data-who="嘉宾" data-en="And then absolutely zero surprise. I continue to like Sonic 5 for an open claw agent. Chit chat experience." aria-label="回原文"></button>。

设计环节最说明问题。有明确艺术指导时，5.6 sol 依然最强，执行复杂 UI、做到"技术上完整但不令人眼花缭乱"没人比得过它 <button class="pd-ts" data-t="23:04" data-who="嘉宾" data-en="And when following art direction, I still like 5.6 Sol. Okay, so let's see what it actually shipped. So first question I was trying to answer in this benchmark is," aria-label="回原文"></button>。

但当模型被给自由度自己做设计决策时，主播最喜欢的反而是 Grok 4.6 的方案 <button class="pd-ts" data-t="22:24" data-who="嘉宾" data-en="I like 5.6, but when given broad decisions to make its own design decisions, I like Grok 4.6. Now, I suspect that this is because I can just spot GPT and Claude Slopp a mile away." aria-label="回原文"></button>。原因很直白：GPT 5.6 永远选森林绿，Claude 永远选棕-棕褐-橙配色，看一眼就知道是 AI 做的。Grok 4.6 不走这条路，像个"新鲜空气" <button class="pd-ts" data-t="22:32" data-who="嘉宾" data-en="but when given broad decisions to make its own design decisions, I like Grok 4.6. Now, I suspect that this is because I can just spot GPT and Claude Slopp a mile away." aria-label="回原文"></button>。

## 本集带走

- **多账号连接是 GrokBot 的真正杀手锏**：同一个服务（Gmail/Slack）挂多个账号，一个智能体遍历所有数据——这个体验 Claude 和 Codex 都没提供。
- **按角色设计智能体，而不是按功能**：想"我需要什么样的队友"，然后给那个队友配工具和指令，比反过来想更自然 <button class="pd-ts" data-t="10:20" data-who="嘉宾" data-en="I'm making a family one. I think just thinking that way, what kind of teammate do I want? And then giving that teammate the tools it needs and giving it" aria-label="回原文"></button>。
- **GrokBot 不适合想要深度自定义的人**：选不了模型、没有细粒度配置、跑在第三方——它面向"想要简单好用"的用户，不是"想要捏泥巴"的用户 <button class="pd-ts" data-t="08:25" data-who="嘉宾" data-en="The other thing I don't like about GrokBot is you don't get to pick what model you're working with. You really actually don't get to have that sort of like sole.md control" aria-label="回原文"></button>。
- **Origin 愿景好但太早**：智能体原生代码托管的思路对，但当前就是 GitHub API 封装 + 重设计 UI，对已深度嵌入 GitHub 的团队没有迁移动力 <button class="pd-ts" data-t="15:03" data-who="嘉宾" data-en="What I would say is with the GitHub integration, it's really, it seems like it's just a wrapper on the GitHub API. So yes, in theory, this has been kind of redesigned." aria-label="回原文"></button>。
- **Grok 4.6 的设计输出有辨识度优势**：不是因为技术更强，而是因为它不陷入 GPT 的森林绿和 Claude 的棕橙配色套路——在自由设计场景下，"不像 AI 做的"本身就是竞争力 <button class="pd-ts" data-t="22:32" data-who="嘉宾" data-en="but when given broad decisions to make its own design decisions, I like Grok 4.6. Now, I suspect that this is because I can just spot GPT and Claude Slopp a mile away." aria-label="回原文"></button>。
- **模型评测里"人味"和"LLM 评判"可以完全相反**：同一个评测，去掉人味后 LLM 评委讨厌 Grok、偏爱 Claude——说明纯靠 LLM-as-judge 会漏掉人类真正在意的维度 <button class="pd-ts" data-t="25:08" data-who="嘉宾" data-en="Now, what's really funny about this, again, this is 70% my taste, 30% the LLM as a judge. If you take my taste out of it, The LLM hates Grock and it loves Claude Opus." aria-label="回原文"></button>。
