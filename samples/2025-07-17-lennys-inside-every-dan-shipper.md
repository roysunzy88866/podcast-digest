一个15人的公司，跑着每日通讯、四款产品、一个咨询业务——产品团队里没有人手写一行代码。这不是预言，是 [[Dan Shipper|Dan Shipper]] 的 [[Every|Every]] 现在的真实状态 <button class="pd-ts" data-t="01:03" data-who="Dan Shipper" data-en="Dan is the co-founder and CEO of Every, which is a company that is at the very bleeding edge of what is possible with AI. Their team of just 15 employees has built and shipped four different products." aria-label="回原文"></button>。

## 产品团队不写代码，在干什么

Every 的工程师不写代码，他们做的事情本质上是：写需求文档（PRD），然后让 [[Claude Code|Claude Code]] 去执行。工作流是这样的——用自然语言描述想构建的东西，通过内部积累的[[提示词|提示词]]库把它打磨成结构化的 PRD，然后喂给 Claude Code，[[智能体|智能体]]去写代码、提 pull request，人来做代码审查 <button class="pd-ts" data-t="42:29" data-who="Dan Shipper" data-en="So an example is, in a Claude Code world, where you're not coding a lot, you end up spending a lot of time essentially typing PRDs. Like, &quot;Here's a document with exactly the stuff that I need to do,&quot; right?" aria-label="回原文"></button>。

[[Cora|Cora]] 团队只有两个人，Kieran 和 Nityesh，加上 15 个 Claude Code 实例 <button class="pd-ts" data-t="41:46" data-who="Dan Shipper" data-en="That's the team, yeah. Well, with Cora, it's Kieran, Nityesh, and 15 Claude Code instances, so it's more powerful than you think. I love that." aria-label="回原文"></button>。Cora 是一个 AI 邮件管家产品，刚公开发布时已经有 2500 个活跃用户，数百万封邮件从中流过，全部投入（含薪资）大概只花了 30 万美元 <button class="pd-ts" data-t="28:39" data-who="Dan Shipper" data-en="We just launched Cora publicly on the day that we're recording this, which is really awesome. Congratulations. Thank you." aria-label="回原文"></button><button class="pd-ts" data-t="67:21" data-who="Dan Shipper" data-en="Like Cora, I think all in to build Cora, we've spent maybe 300K, Maybe. That's crazy because- And that includes salaries?" aria-label="回原文"></button>。

但这有个前提：这些人仍然懂代码。Dan 强调，他们不是不会写代码的人，而是有编程能力、但选择不手写的人 <button class="pd-ts" data-t="54:08" data-who="Dan Shipper" data-en="Yeah, this is what I was going to ask. Which is a different bar, and I think for a long time it's going to be valuable to know how to code for a long time, but this is a progression that is not a new progression." aria-label="回原文"></button>。

他打了个比方——就像当年脚本语言（Python、JavaScript）出现时，真正厉害的程序员仍然要懂底层的 C 语言；英语现在是编程栈的最上层，懂底下几层仍然会显著加速你 <button class="pd-ts" data-t="54:24" data-who="Dan Shipper" data-en="Which is a different bar, and I think for a long time it's going to be valuable to know how to code for a long time, but this is a progression that is not a new progression." aria-label="回原文"></button>。离"完全不懂代码的人独立做出一个真正的 SaaS 产品"还非常远 <button class="pd-ts" data-t="56:00" data-who="Dan Shipper" data-en="So hey, we have this idea we want to bring someone on to actually lead it. Very far. Not within sight, but there's a lot of things that could be products that are a level down from that I think that you could do almost now." aria-label="回原文"></button>。

## 复合工程：每一轮工作都让下一轮更轻松

Cora 团队发明了一个原则叫"[[复合工程|复合工程]]"（compounding engineering）：每一轮工作，都要让下一轮工作变得更简单 <button class="pd-ts" data-t="41:58" data-who="Dan Shipper" data-en="This is just, again, a glimpse into the future. One of the things that we do that I think is really cool, and they basically invented this, I had nothing to do with this, is they invented the idea of compounding engineering." aria-label="回原文"></button>。

具体做法是：他们不在 Claude Code 里每次从零开始写 PRD，而是花时间写一个提示词，能把他们零散的想法自动转成结构化的 PRD。这个提示词存到 GitHub 上共享，以后每次写需求都更快 <button class="pd-ts" data-t="42:52" data-who="Dan Shipper" data-en="Or you could spend a little bit of time being like... There's a sort of platonic ideal of a PRD. And what I'm going to do is write a prompt that can take my rambling thoughts and then turn that into a PRD." aria-label="回原文"></button>。他们还在 Claude Code 里建了一整套斜杠命令库，就是可复用的提示词模板 <button class="pd-ts" data-t="43:55" data-who="Dan Shipper" data-en="What they're using a lot of is Claude Code. So you can do slash commands in Claude Code, which are repeated prompts that you're doing. Got it." aria-label="回原文"></button>。

不只是提示词，连文案审查都自动化了。主编 Kate 以前要花每天几个小时做文字编辑，确保所有内容符合 Every 的风格。

现在他们把风格指南做成提示词，工程师 Nityesh 用 Claude Code 写了一个命令：扫整个代码库里的文案，按风格指南自动修改，然后直接提 pull request 发给 Kate 审批 <button class="pd-ts" data-t="35:04" data-who="Dan Shipper" data-en="So one thing that we did, Nityesh, who's one of the engineers on Cora, built a Claude Code command that just uses that prompt, and checks through the entire code base for all the copy edits, and then creates a pull request on GitHub, and then sends the pull request to Kate." aria-label="回原文"></button>。工程师在用他们想要的风格写营销文案，而主编只需要点一下合并。

## 多智能体协作：不同智能体有不同"品味"

Cora 团队不是只用 Claude。他们同时用一堆 Claude Code 实例，外加三个其他智能体——一个叫 Friday，一个叫 Charlie <button class="pd-ts" data-t="44:24" data-who="Dan Shipper" data-en="... where they can share it with each other. Another thing that they do, which I think is very cool, is they use a bunch of Claudes at once, but then they're also using three other agents." aria-label="回原文"></button>。Charlie 住在 GitHub 里，收到 pull request 时可以 @ 它来做检查 <button class="pd-ts" data-t="44:53" data-who="Dan Shipper" data-en="They did an S-tier through F-tier of AI agents, which I think is so funny. And one of the things I really like about Charlie is that it lives in GitHub, so when you get a pull request, you can just be like, at Charlie, &quot;Can you check this out?&quot;" aria-label="回原文"></button>。

为什么要同时用好几个？Dan 说，不同智能体有不同"个性"和风格，就像不同人有不同品味。

[[ChatGPT|ChatGPT]] 的风格偏简洁、极简、专业；Claude 是另一种感觉。Kieran 作为资深 Rails 开发者，对代码的风格很敏感，他会根据任务性质选择不同智能体 <button class="pd-ts" data-t="45:15" data-who="Dan Shipper" data-en="It's like different people that have different perspectives and have different taste. Kieran, he's one of those serious Rails-files, who they just love Rails, and they love the way that Rails feels, and so I think he has a real sensitivity to... Okay, this agent, ChatGPT for example, it feels very terse, and minimal, and professional, and it has a particular kind of style that maybe he likes." aria-label="回原文"></button>。这不是"一个智能体统治一切"，更像组建一个各有专长的团队 <button class="pd-ts" data-t="46:31" data-who="Dan Shipper" data-en="I think there really is. It's definitely not one agent to rule them all at all. So interesting." aria-label="回原文"></button>。

## AI 运营主管：让自动化不依赖当事人

Every 设了一个专门岗位——AI 运营主管，Katie Parrott。她的职责不是自己做业务，而是发现团队里谁在重复做什么事，然后把它自动化 <button class="pd-ts" data-t="30:18" data-who="Dan Shipper" data-en="Okay, so a couple of things. One, and I think everyone should do this, is we have a head of AI operations. I sit with her once a week." aria-label="回原文"></button>。

Dan 每周跟她碰一次，每当发现自己或别人在重复做某件事，就加到待办清单里，她就去建提示词、建工作流 <button class="pd-ts" data-t="30:24" data-who="Dan Shipper" data-en="One, and I think everyone should do this, is we have a head of AI operations. I sit with her once a week. And every time I'm doing something repetitively, we put it in a to-do list." aria-label="回原文"></button>。关键在于：做业务的人不用自己花时间去搞自动化，否则他们会倾向于用老方法——"我已经在救火了，哪有时间去试一个可能不工作的新方式" <button class="pd-ts" data-t="30:44" data-who="Dan Shipper" data-en="If you're working in a job all day, you're fighting fires, and you're like, &quot;Okay, am I going to do this in the way that I know how or am I going to do it in the new way that might not work?&quot;" aria-label="回原文"></button>。

Katie 的背景也值得注意：她之前在 Animalz（一家顶级内容营销公司）做，非常注重流程，同时本身是很好的写作者，而且对 AI 极度兴奋、爱折腾 <button class="pd-ts" data-t="33:20" data-who="Dan Shipper" data-en="She still does that, but she also spends a lot of time doing the AI operation stuff. And then before that, she worked at Animalz, which is a content marketing agency, one of the top content marketing agencies." aria-label="回原文"></button>。Dan 说，这个岗位最核心的特质就是"想折腾、想构建东西"，加上一定的流程思维，如果还理解所服务业务的技艺就更好了 <button class="pd-ts" data-t="34:00" data-who="Dan Shipper" data-en="At minimum, you really just want someone who's just like, &quot;I want to tinker. I want to build stuff.&quot; There's also people who have a little bit more of that process orientation." aria-label="回原文"></button>。

但建了不用也白搭。他们还必须推动行为改变——比如让主编 Kate 养成习惯，每次收到文案先问一句"你过提示词了吗" <button class="pd-ts" data-t="32:27" data-who="Dan Shipper" data-en="The trick is it's not just building that. You also have to get Kate to be like, &quot;Did you put this through the prompt yet,&quot; anytime someone gives her something. So there's a little bit of behavioral update too that has to happen, which I think is a really interesting organizational challenge." aria-label="回原文"></button>。

## 一句话预测：CEO 自己用不用 AI

Every 的咨询业务去年做了大约 100 万美元，今年可能翻倍 <button class="pd-ts" data-t="70:05" data-who="Dan Shipper" data-en="It'll probably double this year. Last year we did about a million. Maybe it'll be more this year." aria-label="回原文"></button>。他们帮大公司做 AI 采用，流程是：先调研组织里各团队在做什么、有哪些重复任务，出一份报告（还附带一个可以跟所有访谈记录对话的聊天机器人），然后针对每个团队定制四周培训——不是泛泛地教 AI，而是给每个人"你在这个具体场景下用这个具体提示词" <button class="pd-ts" data-t="70:19" data-who="Dan Shipper" data-en="But yeah, basically people are like, can you come help us learn how to do this? So what we do is we spend some time going and researching your organization. So we go in and try to understand what are all the different teams doing, what are the repetitive tasks, some of the stuff we were talking about earlier." aria-label="回原文"></button>。

Dan 被问到"什么决定了一家公司能不能成功采用 AI"，他的回答非常直接：CEO 自己用不用 ChatGPT <button class="pd-ts" data-t="72:03" data-who="Dan Shipper" data-en="Companies, all that kind of stuff. To your second question, which is, &quot;What separates the good companies from the bad, or the companies that end up adopting this?,&quot; I think the number one predictor is, &quot;Does the CEO use ChatGPT?,&quot; or insert your own chatbot." aria-label="回原文"></button>。

如果 CEO 天天在用、觉得这是最酷的东西，所有人都会跟上。如果 CEO 说"这是给别人用的"，那要么没人推动，要么 CEO 因为没有直觉而设定完全不切实际的期望，然后失望 <button class="pd-ts" data-t="72:25" data-who="Dan Shipper" data-en="If the CEO is in it all the time, being like, &quot;This is the coolest thing,&quot; everybody else is going to start doing it. If the CEO is like, &quot;I don't know, this is for someone else,&quot; no one else is going to be able to lead that charge, and they're either going to have ... Either they're going to be negative on it, and so definitely no one's going to do it, or they're going to have way unrealistic expectations because they have no intuition for what's possible, and they're just going to get really disappointed." aria-label="回原文"></button>。

他举了一家对冲基金的例子：创始人发了"我们要成为 AI first 公司"的邮件，但邮件里写了一句"我用 ChatGPT 写了这封邮件，你也应该这样" <button class="pd-ts" data-t="73:18" data-who="Dan Shipper" data-en="One of the things that they do, which I think they're basically the model for how to do this, first thing you did, which a lot of CEOs are doing is send the, &quot;We're an AI-first company&quot; email." aria-label="回原文"></button>。然后每周发全员邮件公布 ChatGPT 使用统计、表彰想出新提示词的人，每周开会让人分享用例 <button class="pd-ts" data-t="73:45" data-who="Dan Shipper" data-en="And then, what he does in, I think what a lot of other really cool companies do is they're doing weekly meetings where people share prompts and share use cases." aria-label="回原文"></button>。核心逻辑是：公司里大概 10% 的人是天然早期采用者，找到他们、给他们舞台，他们的经验会自动传染给剩下 80% 愿意跟的人 <button class="pd-ts" data-t="74:00" data-who="Dan Shipper" data-en="Here are the people that came up with a new prompt and contributed to it.&quot; Create this sort of awareness and momentum, because going back to the point I made earlier, about 10% of people are early adopters, those are the people inside of a company that you need to find and highlight because they're going to just go spend all this time figuring out what works, and then all you have to do is translate what they learn into the rest of the organization." aria-label="回原文"></button>。

## Claude Code 对非程序员是被严重低估的工具

Dan 有个反直觉的观点：Claude Code 这种命令行工具，对非程序员来说可能是最被低估的 AI 工具 <button class="pd-ts" data-t="07:16" data-who="Dan Shipper" data-en="Another big hot take, and this is less contrarian and more just, I think, people are truly sleeping on it. I think people are truly sleeping on how good Claude Code is for non-coders." aria-label="回原文"></button>。

大多数人觉得终端很吓人，但跨过这个小门槛之后，你就有了一个能读你本地文件、自主运行很久不跑偏的智能体 <button class="pd-ts" data-t="09:21" data-who="Dan Shipper" data-en="And it can do that for long amounts of time without going off the rails. Interesting. And so there's a small hurdle that non-technical people have to overcome, which is using their terminal and giving commands, but once they get it running, it's just you talk to it in English and ask it to do stuff." aria-label="回原文"></button>。比如他把所有会议记录下载到本地文件夹，让 Claude Code 逐个文件处理（不是一股脑塞进上下文窗口），然后让它在笔记本里记笔记、按待办列表逐项分析，最后汇总回答——比如"我在哪些时刻微妙地回避了冲突" <button class="pd-ts" data-t="08:23" data-who="Dan Shipper" data-en="But non-programmers don't use it because it's intimidating to use the terminal. But for example, you can download all your meeting notes and put it in a folder and just be like, &quot;Okay, I want you to read every single one of my meeting notes and tell me...&quot; Something that I do, for example, is, &quot;Tell me all the time that I subtly avoided conflict.&quot;" aria-label="回原文"></button>。同样的思路可以用来处理大量客户访谈、客户数据 <button class="pd-ts" data-t="11:20" data-who="Dan Shipper" data-en="I had it download a Russian version of War and Peace and the English version, and then start comparing different scenes that I love to tell me about things that I might've missed in the translations, so that you can get as deep and weird and nerdy for whatever subfield you care about as you want to." aria-label="回原文"></button>。

他还拿《战争与和平》做了个实验：让 Claude Code 读前三章，提取所有托尔斯泰描写人物心理的技巧，然后自动生成一份写作指南，再拿俄语版和英语版对比他喜欢的场景，分析翻译中丢失了什么 <button class="pd-ts" data-t="10:41" data-who="Dan Shipper" data-en="And so I just downloaded War and Peace to my computer, which you can do because it's public domain. ## 配置型经济：每个人都在变成管理者

## 本集带走

- **设 AI 运营主管**：找一个人，职责不是做业务，而是发现重复劳动并自动化。核心特质是爱折腾+有流程思维，不必是技术人员。
- **复合工程原则**：每做一轮工作，花一点时间让下一轮更轻松——把重复的提示词存成库、把人工审查流程改成智能体自动跑。
- **CEO 自己必须用**：预测公司能不能成功采用 AI，第一指标就是 CEO 自己用不用。发了"我们要 AI first"的邮件不够，得在邮件里写"这封邮件是我用 ChatGPT 写的"。
- **找到 10% 的早期采用者并给舞台**：每周分享用例、公布使用统计、表彰贡献提示词的人，让他们的经验自动传染给 80% 愿意跟的人。
- **多智能体搭配**：不同智能体有不同"品味"和风格，针对不同任务选不同智能体，而不是找一个"全能"的。
- **入门级不是消失了，是加速了**：用 AI 的新人如果懂得把每次反馈录进提示词、不犯两次同样的错，成长速度可以数倍于前 AI 时代。

  function fmt(s){
