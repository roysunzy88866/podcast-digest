## 集里怎么说它

- **[[2025-09-07-lennys-how-ai-is-reshaping-the-product-role|《PM的生存法则：AI时代别当瓶颈，去抢活干》]]**(20:01起):本集说写 evals 是 PM 需要掌握的关键技能——不是写提示词，而是在 LLM 产出结果后验证它是否真正智能、有没有产生幻觉，通过创建真实的评估来做到
- **[[2025-09-21-lennys-from-managing-people-to-managing-ai-juli|《Julie Zhuo：管理者的核心技能，就是驾驭AI的技能》]]**(13:17起):本集说评测标准之所以重要，是因为它在帮你把成功标准对齐到客观、具体、没有歧义的程度——如果你自己都不清楚成功什么样，prompt 写不出来，团队也带不好
- **[[2025-09-25-lennys-why-ai-evals-are-the-hottest-new-skill|《做 evals 不是写单元测试，是从看数据开始的错误分析》]]**(00:00起):本集说 evals 本质上是对 LLM 应用的数据分析，是一种系统地审视数据、在必要时创建指标以衡量表现并进行迭代改进的方法，而不是单纯写测试。
- **[[2025-10-23-lennys-al-engineering-101-with-chip-huyen|《Chip Huyen：别追 AI 新闻了，真正提升 AI 产品的是这些事》]]**(22:23起):本集给出了务实的投资回报率框架:非核心功能做到足够好就行,但如果是高风险大规模业务或以准确率为卖点的核心功能,就必须严苛对待;核心是覆盖度而非数量
- **[[2026-01-11-lennys-what-openai-and-google-engineers-learned|《AI 产品不能照搬软件老办法：从高控制低自主开始》]]**(33:25起):本集说 evals 这个词已经发生语义扩散——数据标注公司说的 evals 是专家写错误分析笔记，PM 说的 evals 是定义产品行为，有人说的 evals 是跑 LM Arena 看模型排行；强调 evals 只能抓已知的错，不能迷信它能解决一切
- **[[2026-02-19-lennys-head-of-claude-code-what-happens|《Claude Code 负责人：写代码已被解决，下一步是什么》]]**(55:05起):本集说它是 Anthropic 安全三层模型的第二层，在实验室环境里给模型合成情境，看它做不做正确的事
- **[[2026-04-23-lennys-how-anthropics-product-team-moves|《Claude Code 产品负责人:AI 时代 PM 的生存法则》]]**(55:04起):本集将其称为被低估的任务，更多 PM 和工程师应该做。嘉宾认为不需要构建数百个，只要构建 10 个优秀的评估，就能帮团队量化目标、衡量进度和发现缺失。
- **[[2026-06-30-ainativedev-the-tessl-agent-build-your-software-fact|《TESL 智能体：让你的编码智能体自己越用越好》]]**(04:10起):本集提到用评估工具生成假设 PR，在不同模型上跑来量化成本与质量的权衡，以及从真实场景中自动提取评估用例
- **[[2026-07-14-ainativedev-patrick-debois-maps-the-patterns-of-ai-n|《DevOps 之父 Patrick Debois：AI 时代组织比技术更难成熟》]]**(15:31起):本集把它说成验证智能体输出质量的方式，更成熟的做法不只是用 LLM 当裁判，而是建定制化验证工具快速批量确认
- **[[2026-07-15-talks-claude-fable-claude-tag-and-anthropic-s|《把系统提示词删掉八成:Anthropic 团队这样用 Claude 自己造 Claude》]]**(16:48起):本集把它说成:决定能否信任新模型或自动模式的依据,把整套测试跑一遍只要新模型严格优于旧模型就直接替换;难点在于构建高质量评估的技能
- **[[2026-07-24-talks-inside-the-agent-engine-a-langchain-and|《当系统出故障时，让 AI 代替作战室里的 50 个人——Traversal 谈如何造 AI SRE》]]**(20:10起):指评估复杂系统表现;本集说要专挑最难的事故排查做评估,只要在那里跑通能力自然会泛化到日常简单问题上。
- **[[2026-07-26-lennys-anthropics-first-technical-pm-on|《Anthropic 产品负责人:评估是新的 PRD,不反驳你的 AI 才是好 AI》]]**(00:58起):本集把它说成是「新的 PRD」，通过将模糊的用户痛点（如格式错误、幻觉）转化为标准化的数据集，作为 AI 时代产品经理定义工作、衡量产品改进的核心抓手。
- **[[2026-07-28-pg-how-to-build-your-first-eval|《eval 会取代 PRD 吗?AI 产品经理的新工作法门》]]**(02:41起):本集把它说成:在 Gen AI 时代取代产品需求文档(PRD)的最佳方式,本质是一套预先准备好的提示词、答案以及打分方法,用来定义产品行为的边界,离线衡量产品是否会满足用户。
- **[[2026-07-31-a16z-decagons-playbook-for-building-enterpris|《Decagon 的 AI 寺庙:开源、Duet 与护城河》]]**(07:26起):本集说企业自己做开源微调的痛点之一是评估。没法用公开基准集，必须针对自己的特定任务和客户结果高度定制，衡量端到端系统的表现。
- **[[2026-08-04-ainativedev-datadog-deleted-all-its-ai-context-it-wo|《Datadog 4000 人AI赋能实战：删掉上下文反而更好》]]**(02:35起):本集讨论最多、最深入的概念。Datadog 用 Go 自建了 eval 平台，每晚运行一次；第一个应用是重播已知导致事故的 PR 来验证代码审查智能体；正在从真实智能体使用轨迹中自动提取 eval 用例。
- **[[2026-08-19-beyondcoding-how-amazon-turns-real-failures-into-bett|《模型路由为什么还没解决：Amazon Nova 负责人的实话》]]**(09:06起):本集说评估必须扎根于真实失败模式——每次模型失败只要不是一次性问题就建一个评估来衡量；与公共基准不同，评估是最有用的，规模达数百个，饱和了再删
- **[[2026-08-29-yc-max-junestrand-you-need-the-willingness|《Legora：三个非律师如何造出法律AI操作系统》]]**(34:09起):本集称评估新模型和评估新用例的能力是创业公司应建立的核心 IP 和超能力，有了它才能在不同场景间有效路由。他们内部请律师构建用例来跑评估。
