如果[[智能体|智能体]]会点按钮，但它其实“看不懂”屏幕，那它只完成了自动化的一半。这是 [[Amazon AGI Lab|Amazon AGI Lab]] 团队的核心判断。

在这场工作坊上，[[Emile Baizel|Emile Baizel]]（解决方案架构团队负责人）和 Shruti Arora（解决方案架构师）先讲了背景，再带大家实际动手：

用 Chrome 扩展在网页上圈圈点点，让[[编码智能体|编码智能体]]自动改代码、自动验证结果。

## 智能体为什么必须“看懂”屏幕？

“[[计算机使用|计算机使用]]”（computer use）是让智能体在屏幕上执行动作——看到右下角有个蓝色按钮，就点它。

这很强大，但 Emile 指出还有另一半：智能体要真正理解它在屏幕上看到的东西，而不是把屏幕当成一块随便点按的盲板 <button class="pd-ts" data-t="05:46" data-who="嘉宾" data-en="Now, why do we feel there's a need for perception agents? So, for those of you who are not familiar with the term of computer use, that's basically the way for an agent to take an action on a computer screen, right?" aria-label="回原文"></button>。

他举了个例子：

给你看一个 90 年代末的 Yahoo 邮箱界面，你从没用过，却多半能摸索着发出一封邮件——因为人类积累了成千上万小时使用屏幕的经验，凭直觉就知道怎么操作。

他们想让人工智能体达到同样的水平 <button class="pd-ts" data-t="06:24" data-who="嘉宾" data-en="So if I... Showed someone an email client from like the late 90s that was like a Yahoo email client or Hotmail client or something which you've never seen before, you would probably be able to figure out how to send an email from that even though you've never used that client before because we've got this collective understanding of thousands and thousands of hours of using these screens that we kind of intuitively understand how to use these things and that's really where we're trying to get to with these agents." aria-label="回原文"></button>。

还有个现实好处：大量知识工作者的日常，就是在使用一堆根本没有应用程序接口的软件界面。

这些工作之所以还需要人来做，正是因为没有接口可调。智能体如果能像人一样“看”屏幕，就能接手这些工作 <button class="pd-ts" data-t="06:58" data-who="嘉宾" data-en="And the second one is these agents don't require APIs in order to work. So if you think about a lot of knowledge work, it's a lot of humans using screens that just don't have APIs, and that's why there are people who are doing these things." aria-label="回原文"></button>。

## 客户的那句话：50% 的成功率等于零

介绍实验室时，Emile 转述了一位客户的话：「**如果我的智能体只有 50% 的时间能正常工作，那它就等于完全不能用**」<button class="pd-ts" data-t="03:06" data-who="嘉宾" data-en="And we have a great customer quote that said, if my agent works 50% of the time, it doesn't work at all. And that's because you're either not going to run it at all, or if you do run it, you're going to end up debugging it and spending all this time, and you're going to basically do away with all the gains that you're getting from that agent." aria-label="回原文"></button>。

原因很简单：要么你干脆不用它，要么你得不停去调试，把省下的时间又全赔进去。

所以可靠性是他们的第三个重点。

团队在模拟环境里做强化学习来训练模型，训练素材来自外部客户和 Amazon 内部大量做知识工作的团队。

他们对智能体的整体思路有两条：一是把智能体当“队友”而不是黑箱——它要理解你的目标，还能说出自己打算怎么完成；

二是感知，环境不限于浏览器，还包括手机和桌面电脑的各种屏幕。

## 先补课：去年的产品 Nova Act

去年他们发布了第一个产品 [[Amazon Nova Act|Amazon Nova Act]]，一项正式的 AWS 服务。开发者用自然语言就能驱动浏览器完成工作流：

打开网页、导航、搜索、填表单，遇到卡壳或需要人审批（比如报销单）时把人叫进来 <button class="pd-ts" data-t="03:44" data-who="嘉宾" data-en="So Amazon Nova Act. is a first-class AWS service that allows developers to build and run reliable browser-based workflows at scale. So using natural language, you can drive a browser workflow to populate a browser, navigate, search with it, fill out forms, and call a human in the loop if you need a human for a expense report approval or if you get stuck or other things like that." aria-label="回原文"></button>。

主要用途有四类：批量填表单（不用为每个网站写提示词或脚本）、搜索并提取数据、购物，以及质量测试。

今年他们又加上了 MCP 服务器和技能（skill），让其他智能体也能方便地调用 Nova Act，还提供一个无需写代码的演练场。

## 两个开源工具：标注 + 验证

工作坊的主角是两个已开源的“[[感知智能体|感知智能体]]”基础工具。

第一个叫[[视觉标注|视觉标注]]（visual annotation）。它是一个 Chrome 扩展：

你在任意网页上圈选、点选元素或像在地图上钉图钉一样做标记，写下想改什么，点导出就得到一个 JSON 文件和一段提示词，交给你的编码智能体去执行。

Shruti 强调，**这个工具本身不做任何推理，纯确定性输出，不绑定任何模型** <button class="pd-ts" data-t="08:17" data-who="嘉宾" data-en="So important to note, this has nothing to do with inference. This is purely deterministic. It just outputs JSON." aria-label="回原文"></button>。

第二个叫[[视觉验证|视觉验证]]（visual verification）。

你把网站该遵守的设计规范、颜色、字体，以及登录、结账这类用户流程写成描述文件，技能就能代替人去逐项检查网站是否合规，并生成报告。

第一次运行时，它还会先爬一遍网站，自动生成这些流程描述 <button class="pd-ts" data-t="14:29" data-who="嘉宾" data-en="When you run UI verification for the first time, There will be a deep one-level surface crawl that will be done by the UI verification tool on your website to go and check what are the links, what are the content, and based on that, it's going to create these user flows that are in terms of syntax that the UI verification is going to use when it's going to run the verification next." aria-label="回原文"></button>。

## 前端工程师的痛点：几周变几小时

Shruti 让大家代入一个场景：你是前端工程师，按设计团队的 Figma 稿做一个网页，本来要四五周。

做到第三四周，把代码分享给同事看，对方说“这不对劲，标题不该是红色的”，反馈散落在 Slack 和共享文档里，你逐条消化、改代码，一来一回又是好几天 <button class="pd-ts" data-t="10:11" data-who="嘉宾" data-en="Just bear with me. So imagine you are a front-end engineer and you are building a web application. You have a design team and you are taking inspirations." aria-label="回原文"></button>。

有了这两个工具，流程变成：

同事在网页上直接标注“标题改小”“按钮太大”，点一下按钮，**标注自动传给编码智能体改代码，改完自动跑视觉验证、出报告**。

你只需要收集反馈、发给智能体，然后去喝杯咖啡，回来时所有改动已经合并 <button class="pd-ts" data-t="12:37" data-who="嘉宾" data-en="How would that reduce the time? Maybe a few hours, you just start, collect the feedback, send it to your agent, and go for a coffee, break, come back, and all the changes have been merged." aria-label="回原文"></button>。

现场演示中确实如此：

在扩展里点“应用更改”，后台会启动编码智能体（已测试支持 Claude Code 和 Kiro），日志里能看到模型在想什么、在看屏幕哪一块，最后生成验证报告 <button class="pd-ts" data-t="29:30" data-who="嘉宾" data-en="That is the key, the CLI's logs, as well as, and the verification runs. Nova Act has these logs that gives you exactly what the model was thinking and what part of the screen it was trying to make a decision on." aria-label="回原文"></button>。

## 会议室里聊两句，网页就改好了

Amazon 的 Giovanni 带来了更进一步的玩法：把可穿戴设备 B 接入这套流程。

B 是 Amazon 的一款带麦克风和人工智能助手的可穿戴设备，正在聆听时有指示灯提示，对话存在私有云上 <button class="pd-ts" data-t="32:53" data-who="嘉宾" data-en="So it just has a microphone. So you can activate this with the button. And then it's going to listen for your conversation." aria-label="回原文"></button>。

他的组合是：

戴着 B 开设计会议，随口说“标题颜色改成红色”“表情符号从大脑换成机器人”，B 的对话记录通过命令行工具传给感知智能体，几分钟后网页真的改好了，还自动跑完验证 <button class="pd-ts" data-t="34:25" data-who="嘉宾" data-en="Then you just enable your B device. The LED is on. You say something like, oh, I want to change the title color to red." aria-label="回原文"></button>。

## 台下的即兴创意

工作坊留了时间让观众上台演示。

有人现场让智能体把播客页面改成复古红白机风格、加上鸭子笑话，再走完整个验证流程，确认改动真的生效，赢得一台 B 设备 <button class="pd-ts" data-t="37:55" data-who="嘉宾" data-en="So just asked it to turn it retro NES, do some duck jokes, and went back and did the verification funnel. It's probably, that's what I was telling them, it's probably really interesting to me here is to watch this, this great AI said, I made it a duck, you know, I made a duck icon, but often, as everyone here likely knows, is you don't actually see that happen, but then it went through and did the," aria-label="回原文"></button>。

在一家金融公司工作的观众提出，可以用录屏加日志的工具代替 B 作为反馈入口，让非技术同事直接描述“这块应该挪到哪”，智能体照做 <button class="pd-ts" data-t="48:07" data-who="嘉宾" data-en="And what I started to come up with is at the company I'm at, which is a finance company, we have a lot of non-technical people. And not only do we have to get our criteria in, but we also have a lot of UI, UX that" aria-label="回原文"></button>。

还有沃顿商学院的观众想把 B 接入自己的任务管理系统，会议想法自动进收件箱、更新策略 <button class="pd-ts" data-t="44:43" data-who="嘉宾" data-en="All to solve the need of when you're working after you have a meeting of like, what should I be doing right now to tie to my ultimate strategy? So how we imagine this to work with the B device, as Giovanni informed me, there's an MCP, would be," aria-label="回原文"></button>。

## 本集带走

- Amazon AGI Lab 认为智能体不该只会点屏幕，还要像人一样理解屏幕内容，因为大量知识工作使用的软件根本没有应用程序接口。
- 两个开源工具已可用：视觉标注（Chrome 扩展，在网页上圈点描述改动，导出给编码智能体执行）和视觉验证（自动检查网站是否符合设计规范和用户流程）。
- 客户的原话是：智能体只有 50% 可靠就等于不能用，团队为此在模拟环境中做强化学习训练。
- 前端改反馈的流程可以从几天压缩到几小时：标注 → 智能体改代码 → 自动验证出报告，人只需最后看一眼。
- 可穿戴设备 B 被接入了整套流程，开会时随口聊的设计意见，几分钟后自动变成网页上的真实改动。
