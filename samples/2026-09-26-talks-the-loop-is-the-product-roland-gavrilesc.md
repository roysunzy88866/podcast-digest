# 循环就是产品：智能体配方与每瓦特价值

<div class="pd-byl"><b>Roland Gavrilescu</b> · 前 XAI 智能体基础设施工程师 · 2026-09-30</div>

这一集是一个创业演讲。说话的人叫 Roland，他和联合创始人几个月前从 XAI（马斯克创办的 AI 公司）离开，自己做[[智能体|智能体]]基础设施方向的创业。他带来一个面向 2026 年的判断：大家都在谈 auto research（自动化研究），而把它产品化的蓝图归结为三个想法。

## 第一个想法：循环就是产品

行业的叙事一直在迁移：先是一切归结为 RLHF（用人类反馈训练模型），然后模型成了商品、一切都看 harness（围绕模型的[[harness|执行框架]]），现在轮到「[[循环|循环]]（loop）」——你只需要构建循环，不再碰代码。

最生动的例子是一个叫 AJ 的人围绕 ClaudeBot（后来叫 OpenClaw）搭的第一个循环：上 Reddit 找价格和库存、跟汽车经销商谈、让经销商互相竞价压价，再用一个可验证的标准判断价格何时合适，然后锁定成交、拿下那辆车。这是「循环就是产品」的第一个真实案例——本来该直接变成一家创业公司 <button class="pd-ts" data-t="02:14" data-who="Roland" data-en="He followed these four steps. And he's really OpenClaw, the one that did it. Go on Reddit, find prices, find inventory, talk to the dealers, put dealers head to head, and try to figure out how to make them outbid each other." aria-label="回原文"></button>。

为什么循环这么重要？Roland 认为模型本来就是按循环训练出来的——模型调用工具、做出观察，这正是「我们作为人类一直被训练的东西，现在也是作为智能体被训练的东西」<button class="pd-ts" data-t="3:24" data-who="Roland" data-en="It's a terminology coined back in 1970s by the US Air Force, and it's the idea of these jet fighters, how to react in fast-paced environments. If you think of models calling tools and taking observations, it's what we've been trained on as humans but also as agents now." aria-label="回原文"></button>。

关键在于：**信号的质量决定循环的成功率，验证器的质量决定你能否校准这个成功是不是真的** <button class="pd-ts" data-t="4:04" data-who="Roland" data-en="And what matters here is the quality of the signal determines the success rate of the loop, and the quality of the verifier is able to calibrate if that success is actually correct or not." aria-label="回原文"></button>。而在此之上还有第二个循环——把第一个循环末端生成的工件（artifacts）拿回来喂给信号，在上面跑第二个循环，实现持续改进。

> 【背景】OODA 循环（观察—判断—决策—行动）由上世纪 70 年代美国空军提出，描述喷气式战斗机飞行员如何在快节奏环境中反应；播客原文并未提及此概念，此为补充背景。

## 第二个想法：系统蒸馏是模式

所谓[[系统蒸馏|系统蒸馏]]，就是搞清楚第一个循环里什么做对了、什么做错了，并知道怎么在第二个循环里处理这些信息。每个循环都会产生关于 harness、配置、[[评估|评测]]（evals）、模型、资源、工具和环境的有用信息——你要的是让这些信息可移植、可版本化、能随时间演进。

Roland 用研究领域的「数据配方」做类比：RL 之所以运作良好，正是因为人们理解了配方，并持续调整配方去对抗幻觉、奖励作弊（reward hacking，模型钻奖励函数空子的行为）这类问题。但对 harness、对广义的 AI 系统，还没有对应的东西。所以他提出「[[智能体配方|智能体配方]]（agent recipe）」：让你能创建**可复现的前沿 AI 系统**的东西——一条随时间不断变强的护城河，不绑定任何平台或模型提供商，由你拥有、放在你公司里 <button class="pd-ts" data-t="05:51" data-who="Roland" data-en="We think recipes can be applied to this, and we should use the same name. So an agent recipe is really something that enables you to create reproducible Frontier AI systems." aria-label="回原文"></button>。

具体来说，循环的价值就是持续把系统蒸馏成配方：失败模式应该变成 judges 和 evals；重复出现的行为应该变成技能和提示词；用户的挫败感应该变成 harness 的扩展和记忆。最后所有东西装进一个 Git 仓库，作为你构建自我改进系统的持续策略。

他们据此做了早期产品 [[Py.Recipes|Py.Recipes]]，构建在 pie harness 和 Harbor（评测框架）之上，烘焙进 Git 仓库——**由你拥有，但由你的智能体来管理** <button class="pd-ts" data-t="07:28" data-who="Roland" data-en="We baked it into Git repos, so everything could be versioned, and agents would have a way to continuously track how these change and why. And it's meant to be owned by you, but managed by your agents." aria-label="回原文"></button>。一个核心理念是「[[品味|品味]]（taste）」：配方不只是 harness 和模型，而是「你是如何得出这个配方的、为什么」——配方本质上是把制作者的品味编码进智能体的构建方式里。而用别人的配方时，你也应该能把那份品味一并带走。

## 第三个想法：每瓦特有价值工作

衡量进步的分数是 valued work per watt——每消耗一瓦特算力，产出多少有价值的工作。Roland 引证 Cursor 和 Cognition 的路径：从构建最好的产品，到为产品构建最好的 evals，最后基于前两个产物构建最好的模型。

他认为这是今后一切事情的配方，代码只是第一个成功的领域；客户支持、法律、研究都将归结到这个问题：我每瓦特能获得多少价值？第一步是会衡量价值，第二步是知道这个价值拿得划不划算。

从基础 harness 走到前沿只有一条路——上生产环境跑，没开始之前你根本不知道前沿在哪。而最后一步、也是最需要研究的一步是：到了前沿之后如何让它在经济上可行。

微调 API 和抽象好的基础设施都已经在了，缺的只是 know-how：知道怎么把品味固化进 evals、怎么在实验中验证它。evals 不只是测试，它是「创作者的品味」，智能体应该能围绕它复现和自我改进——怎么把一个人作为艺术家或开发者的品味做成任何人都能下载、一对一复刻的东西，没人认真想过。

## 实战演示：人才搜寻智能体

用人才搜寻智能体做例子——招聘这件事高度个人化，重要的不是「什么是好招聘」，而是「谁在主导、他认为什么是好」。起点很简单：一堆工具（web 搜索、LinkedIn）、一堆已被 Codex 和 Claude Code 普及的子智能体、一条系统指令。

第一步是用 Patterns（模式提取）看轨迹（traces）、把共性行为或用户不满聚成类。比如智能体会倾向大量联系大厂员工——而招聘者想要的是隐藏的宝石，不是去挖 John Carmack。

这种行为你从不会想到要事先固化，只有跑了才发现。第二步是校准：构建一个 judge 智能体审视轨迹，精确识别「这单是不是联系了 Google 员工而不是去 GitHub 找隐藏宝石」。关键分工是：**你不需要人来构建 evals，只需要人来校准 evals** <button class="pd-ts" data-t="15:01" data-who="Roland" data-en="You don't need the human to actually build the evals. You need them to calibrate the evals. And agents should be the ones that really take the taste of the maker and put them into code." aria-label="回原文"></button>——智能体才是把制造者的品味写进代码的那个角色。

有了这些就能生成配方候选——那正是你真正想去「品味」的 diff。离线评估集可以建得很好，但真正的检验在上生产：终端用户认不认同你的品味？

用 A/B 测试（比如多臂老虎机场景）验证「我有好品味、用户也认同我有好品味」，验证通过就晋升到下一版配方。秘诀就是一遍又一遍地重复这个循环。

## 本集带走

- **把你自己自动化成更高层级的裁判**：让第二层循环的智能体，把你的判断力应用到你要推向生产的那些智能体上。
- **系统蒸馏速度决定护城河**：持续把品味注入工作智能体、让它们自我验证并协同——做得越快，越快建立起通往垂直 AI 公司的可防御路径。
- **失败模式和重复行为都要「回收」**：失败模式变成 judges 和 evals，重复行为变成技能和提示词，用户挫败感变成记忆和扩展——全部进一个 Git 仓库做版本管理。
- **evals 不是测试，是品味**：人只负责校准 evals（判断对不对），构建 evals 的工作交给智能体。
- **用「[[每瓦特有价值工作|每瓦特有价值工作]]」记账**：先确认产出的工作有价值，再确认经济账划算——价格差距就是用户会从 Claude Code 切换到你产品的理由。
