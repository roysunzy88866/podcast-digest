# 让公司里每个人都能用 AI 做出内部工具

<div class="pd-byl"><b>Garrett Galow</b> · WorkOS 产品团队 · 2026-10-13</div>

AI 时代，“把东西做出来”已经变得很便宜，但“让同事能用上”这件事依然卡住了大多数人。

[[WorkOS|WorkOS]] 的 Garrett 在这场演讲里，讲了一个从销售同事的小工具出发、最终变成公司级平台的故事。

## 一个销售的工具，为什么最后要工程师收尾？

大约半年前，WorkOS 的销售 Perona 快要休产假。

她很出色，想在离开前给团队留点东西，于是用 [[Lovable|Lovable]] 做了一个聊天机器人，取名 Perona GPT——用它自己积累的销售通话和产品知识训练，供同事在她休假期间使用。<button class="pd-ts" data-t="01:15" data-who="嘉宾" data-en="She's an incredible AE, and she wanted to build something to help the rest of the sales team while she was on leave. So she went and built something called Perona GPT." aria-label="回原文"></button>

结果 CEO Michael 第一个去试用，直接被挡在门外：他没有 Lovable 账号，根本进不去。

最后的解决办法是，让应用 AI 团队的两名工程师把工具重写成正式应用，再部署、分发。一个好想法，还是绕回了工程师的工时。

Garrett 的结论是：

做出一个能本地跑起来的东西不难，难的是部署、安全、账号权限这些“上线”环节——非工程师搞不定，工程师也不想每次都从头来一遍。<button class="pd-ts" data-t="02:48" data-who="嘉宾" data-en="It's pretty easy now. But shipping it, making it available, even internally to your company, hasn't really gotten that much easier, right? Where do you deploy this?" aria-label="回原文"></button>

## 他们的答案：一条命令，从建应用到全公司可用

WorkOS 做了两层东西。底层是平台 [[Atlas|Atlas]],负责创建、部署、共享应用；上层是一个命令行工具,叫 [[WOW|WOW]],员工只需要敲一条命令，比如 wow app create。

WOW 会自动检查你的电脑：装没装 Git、登录 GitHub 没有、密钥管理工具 [[Doppler|Doppler]] 配好没有——不管你是不是工程师，它把开发环境一次性配齐。<button class="pd-ts" data-t="06:05" data-who="嘉宾" data-en="The WoW CLI lets you run things like WoW App Create. What it does is that you name the app, it scans your machine and says, okay, do you have Git installed? Are you logged into GitHub?" aria-label="回原文"></button>

然后它会用模板建好代码仓库、推送、部署，几分钟内你就能拿到一个本地跑起来的应用。

之后打开 [[Claude Code|Claude Code]],用一句话描述你想要什么，它就开始帮你填内容。

这个工具通过公司的设备管理推送到每台电脑，员工入职第一天就有。

## 安全和分发，才是真正的门槛

Atlas 的设计遵循三个原则。

第一，基础设施隐形。应用实际跑在 [[Cloudflare|Cloudflare]] 的开发者平台上，计算、数据库、键值存储都是自动配好的。

如果哪天换成别家，使用者完全不用知道，也不用关心。<button class="pd-ts" data-t="12:32" data-who="嘉宾" data-en="So we have this shared domain that whatever your app is called, you get that host name underneath workos.tools. So you don't have to worry about where is the app going to be available, how does it get, you know, do people get access." aria-label="回原文"></button>

第二，默认安全。所有应用自动挂上公司的 [[Okta|Okta]] 单点登录，外人打不开。API 和 Slack 机器人有专门的令牌认证。

所有请求都有日志可审计，密钥统一放在 Doppler,不会有人把 API 密钥误提交进代码仓库——这是很多内部工具最大的隐患。

第三，人人可发现。应用一上线就自动挂在一个共享域名下，同事在 Slack 里点开链接就能用，不需要任何人点“共享”。

## 不是玩具：每周 330 万次请求

这些应用不只是小看板。

内部登记表显示，公司累计推送了 278 个应用，一周内有 330 万次请求流经这些应用，其中既有页面工具，也有 API 和 Slack 机器人。<button class="pd-ts" data-t="08:41" data-who="嘉宾" data-en="So anytime you push an app with WoW, we actually log into this internal registry. So you can see we have 278 apps that have been pushed, 21 that had a deployment done today." aria-label="回原文"></button>

举两个例子。产品营销的 Connor 每月要做内部通讯，以前要把更新整理一遍，再分别排成 Slack 和邮件两种格式。

现在有个应用把所有产品更新聚合在一起，可以直接排版、预览、发送。

Garrett 自己则做了一个更新日志工具：任何同事都能起草产品更新，草稿自动发到 Slack 通知他审核，审核通过一键发布到官网。<button class="pd-ts" data-t="10:13" data-who="嘉宾" data-en="And so I built a tool that basically allows anyone at our company to draft these changelogs, and so someone can come in. Ooh. I gotta refresh my auth." aria-label="回原文"></button>

## 最重要的数字：37% 的应用没有工程师参与

在持续维护和使用的约 60 个应用里，37% 的代码提交记录里完全找不到工程师——全程是业务同事自己和 Claude 完成的。<button class="pd-ts" data-t="14:56" data-who="嘉宾" data-en="And I think the most important metric is our goal was enable non-engineers to build and deploy apps. And out of our apps, out of these 60 apps, 37% of them have been built without any engineers in any of the commits." aria-label="回原文"></button>

对 Garrett 来说，这才是真正的成功标志：再也不会有人跑来说“能不能帮我迁移/维护一下市场部的工具”。

另一件事也在推动普及：

公司定期举办全公司参加的 [[Claude 日|Claude 日]]，一天的黑客马拉松，刻意让非工程师坐在键盘前动手写，工程师只在旁边答疑、解卡。

市场和销售的很多点子就是这么冒出来的。<button class="pd-ts" data-t="04:52" data-who="嘉宾" data-en="Turns out we basically had sort of a forcing function to gather feedback, which is we started doing these company-wide Claude days. Basically, it's a single-day hackathon where everyone pairs up into teams and builds an app." aria-label="回原文"></button>

## 还没做完的事

下一步，他们想做更细的权限控制——现在默认全员可见，但有些敏感数据的应用需要按角色限制访问。

还想让应用更方便地接入公司数据，比如一句话就能加上 Snowflake 的访问权限，不用自己管 API 密钥。

以及原生集成 Slack,让应用部署的同时自动装成一个 Slack 应用。

Garrett 的总结很直接：**AI 解决了“建造”的问题，但要让它成为人人可用的平台，还差一层像 Atlas 这样的东西**。<button class="pd-ts" data-t="16:36" data-who="嘉宾" data-en="They basically still took engineers to build and maintain, and it sort of limited the tools that we could build. For us, AI solved the build problem, but we needed more in order to make this a ubiquitous platform for our team." aria-label="回原文"></button>

> 【背景】WorkOS 是一家为企业软件开发者提供企业级登录、权限管理等基础设施的公司；演讲中提到的 Okta、Cloudflare、Doppler 分别是身份认证、云部署和密钥管理服务。

## 本集带走

- AI 让“做出来”变便宜了，但部署、安全、分发仍是普通人上线的真正门槛
- WorkOS 用 Atlas 平台加 WOW 命令行工具，让员工一条命令就能建好并部署内部应用
- 默认接入公司单点登录、统一密钥管理和请求日志，安全不需要使用者操心
- 每周 330 万次请求流经这些内部应用，持续维护的约 60 个应用中 37% 完全由非工程师独立完成
- 让非工程师动手、工程师只做教练的黑客马拉松，是推广这种文化的有效方式
