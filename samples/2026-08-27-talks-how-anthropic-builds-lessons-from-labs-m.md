# Instagram 联合创始人聊 AI 时代怎么「不合常理」地写代码

这一集的主角是 [[Mike Krieger|Mike Krieger]]——[[Instagram|Instagram]] 联合创始人，如今在 [[Anthropic|Anthropic]] 带领实验室团队。他在台上聊了一个很有意思的转变：他现在会让 [[Claude|Claude]] 干完活之后，「能不能解释得再简单点，就当我比你笨一点，因为我需要你把这个给我拆解一下」——因为模型已经「比我聪明得多」。

## 从「拆解任务」到「描述目标」

Mike 说，加入 Anthropic 头两年他做 CPO,只能周末拼命用模型，FOMO 越来越强，最后干脆转成一线 IC。角色一变，工作范式也变了：过去是「我有一个想法，先在脑子里拆解、逐步迭代」；现在是「我描述目标，你去干，然后我们聊聊你发现了哪些权衡、提出了哪些问题，再看落在哪里」。核心是从任务委派转向表达最终状态，让它自己去搞定。

## 「不合常理」地用模型

主持人问他在提示词上如何更雄心勃勃，他借用了大会报纸上那句「要不合常理」(be unreasonable):行业要教会人们更大胆地使用模型。他举例：一个非技术同事说内部产品不好用，他的回应不是自己动手，而是「你为什么不问问 Claude?」

他最「不合常理」的一次操作：一个用 Python 写的实验室项目，因为发现 [[Claude Code|Claude Code]] 用 Bun(一个 JavaScript 运行时)部署方案更好，他直接让模型把整个代码库迁到 TypeScript——在 2010 年代的工程标准下这是蠢主意，「谁会去迁移几百、几千行代码？」但他搭了一个动态工作流环境，让它周末不停验证、复查、两边代码对照，周一回来就得到了一个迁移完成、可部署的版本。

至于能不能照搬到整个 Instagram(他顺口提到 Instagram 全是 Python,现在据说正靠模型往 PHP 转)，他分享了个经验：当年 Python 3 出来时他们做了 MonkeyType,捕获生产环境实际用到的运行时类型再映射回代码库——用 LLM 做语言转换时同样可以更多依赖生产数据、跑分段测试。最难的是「找到能增量开始的边界，而不是试图一口吞下整个海洋、一夜全换」。

## tag:Anthropic 内部真正的写代码方式

如今他 60% 以上的代码由模型写出，主要靠 [[tag|tag]](一个在 Slack 里委派任务给 Claude 的工具)。他透露 Anthropic 内部交互式迭代用 Claude Code,但大部分使用其实是「通过 tagging 委派」。

tag 最有趣的是多人协作性——他类比 Midjourney 当年大家都在 Discord 上互相看到怎么用，这直接拉高了使用的大胆程度：他看到有人 tag Claude 说「你不只修这个 bug,你现在负责代码库的这一部分，监控这个反馈渠道、主动接任务、修掉它们，API 变了也要处理」，他才意识到自己「一直把它当作 Slack 里美化版的 Claude Code 在用，完全低估了它」。更高级的用法是把它当真正的队友：持有上下文、有记忆、能主动行动——这改变了 Anthropic 内部的运作方式，变成多人、异步、主动的协作。

被问 code review 瓶颈时他很坦率：仍然卡，而且「更像是瓶颈在于人类甚至无法完全构思我们正在做的事情」——有 PR 大到像「2,000 天的代码量」，根本没法逐行看。所以他们开始改发 Claude Code artifact:解释、变更意图、所做的权衡。

「讨论意图和权衡，然后在生产环境中衡量，这是我们的方向」。他自己收到 PR 也不逐行 review,而是把「我会问的问题」丢给 Claude 去调查——Claude 驱动、人类主导的 review。

## Labs 的组织方式：双周「坚持还是转向」

Labs 的节奏是每两周评审一次，每个项目都面临「坚持还是转向」，甚至关停——几乎每轮都会关项目，做多了大家就不再觉得「我的项目被关 = 我失败」。因此组织架构不能绑死在项目上，否则等于每两周重组一次。

他们的做法是：每个 bet(赌注)临时抽调产品、边缘团队等成员组成小组，设一个 bet 负责人，但**他不管理任何人**——工程经理的角色变成确保每个人分到最感兴趣、最能发挥的事。只有当产品跑出持久生命力(如 [[Claude Design|Claude Design]],六月做了大版本、开始为它专门招人)才固化为正式团队。松散，直到固化。

## 该删掉什么：Fable 替观众提的问题

主持人转述了让 Fable 自己生成的问题：「你在 AI 里会删掉什么？」Mike 说 Anthropic 有个 Slack 频道叫 Project Unship(项目下架)，专门问「现在产品里有什么该删」。

他们最近下线了 styles——使用率低、运作方式刻板，skills 明显更好。他的观点是：「必须愿意把上一代 AI 的基本构件下架，或用下一代的东西取代它们」。而最大的产品问题是他自己产品的碎片化：要求用户区分写代码、协作办公、聊天，「普通人根本没法解释为什么这些界面全都不一样」，它们还互不打通、不能互相委托——他吐槽在 CoWork 里规划得清清楚楚，最后还要「生成一段文字粘贴进 Claude Code」是「2020 年的工作流，不该再存在」。

## 对初创企业：依然非常看多

面对「Anthropic 明天发几个 markdown 文件就能摧毁我行业，为什么不直接放弃加入 Anthropic」的尖锐提问，他回应：模型让实验更简单、让小团队更快，这恰恰催生下一代[[初创公司|初创公司]]。大厂产品必然「受制于已有的整合、围绕自身优势来做」，而痴迷于某个垂直领域或某群你深度了解的用户，是任何实验室都到不了的理解深度。

「一个四五人、痴迷于某个问题的团队，仍会比同样这些人待在任何受制于复杂性的组织里移动得更快」。关键洞察是：「写代码从来都不是限制性的环节」——真正的门槛是空间和用户理解。金融领域他也看到机会：模型即时生成分析/仪表盘的灵活性，与可验证性、审计日志、数据溯源之间需要找到切分线，现有系统对[[智能体|智能体]]工作负载不灵活，「技术栈两端都有机会」。

## 心理健康：情绪说出来，然后问「我们怎么办」

最后聊[[职业倦怠|倦怠]]。他说现在 AI 行业的强度比 Instagram 时代高好几倍——那时一年操心一次 WWDC、三四个月一次对手发布；现在 Anthropic 每周全员会都有一页「本周 AI 大事(才到周三)」的幻灯片。

他的两条自用方法：一是真正留出休息时间——「没有任何一份工作重要到你不能离线几天」，倦怠了恢复要很久；二是体育圈那句话：「你永远不会像你最好的一场比赛那么好，也永远不会像你最差的一场比赛那么糟」——内化了「完了完了/我们又行了」这个循环永远在转，就知道事情从来没那么糟。而对他帮助最大的一条教练建议是：**你有的感受，团队其他人多半也有**。

他几个月前真的一场会就这么开场：「我很难过、我很沮丧，我真希望这件事能成」——这为其他人说出情绪留出了空间，然后才能一起问「那我们打算怎么办？」

## 本集带走

- **表达目标，不要拆解任务**：把「描述最终状态 + 让它自己干 + 事后对权衡」当默认工作范式，交互式高带宽场景才用 Claude Code 这类工具。
- **敢下「不合常理」的指令**：整库语言迁移、让非技术同事直接找 Claude 改产品——先按新规则想「现在可不可行」，别按 2010 年代直觉否决。
- **把模型当有记忆、能主动的队友，不是聊天窗口**：让它负责代码库的一部分、监控反馈渠道、主动接任务；别人的大胆用法是最好的学习素材。
- **大 PR 不逐行看，看意图和权衡**：分享变更解释与取舍，在生产环境验证，而不是指望人类读完两千天的代码量。
- **组织要松散直到产品跑出来**：项目按 bet 临时组队、双周「坚持还是转向」、负责人不管理人；有生命力的产品再固化成正式团队。
- **写代码从来不是成败关键**：空间理解、用户理解、快速迭代才是——小团队依然比大组织快，初创仍值得做。
- **情绪说出来**：自己先示弱，团队才敢说真话；从「我们都有情绪」出发，比从假装没事出发解决问题容易得多。
