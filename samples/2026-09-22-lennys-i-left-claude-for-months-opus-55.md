# Claude Opus 5.5 实测：那个不烦人的 Claude 回来了

<div class="pd-byl">2026-10-05</div>

这一集是一期单人实测：

主持人 Claire——她是 AI 产品 ChatPRD 的缔造者(节目里反复让模型改自己的 ChatPRD 主页)——试用了 [[Anthropic|Anthropic]] 刚发布的 [[Claude|Claude]] [[Opus 5.5|Opus 5.5]]，聊聊这个模型到底值不值得用。

她的开场自白很坦白：她已经好几个月没用 Claude 了。不是因为模型不够聪明，恰恰相反——「我停用 Claude 不是因为它的智能或它的模型。

我停用 Claude 是因为它太厉害了。烦人。」

喋喋不休、毫无逻辑，她不停地问它「你能像个人一样跟我说话吗」，最后干脆整个抛弃了 Claude 的使用界面，只留它跑几个后台任务。

而 Opus 5.5 让她「回来了」。她最喜欢的一点听起来很朴素：**它不烦人了**。「它不再烦人了,或者至少烦人程度降到了最低」。

## 官方卖点速览：更便宜、更快、更安全

Anthropic 的卖点是 Fable 级别的性能，价格比 Opus 5 便宜约 40%,速度快 30%。定价是输入 token 4 美元、输出 token 20 美元，快速模式翻倍(8 美元/40 美元)，缓存读写照例有折扣。

Claire 自己对比时发现 Opus 5 慢得让她沮丧，5.5「感觉确实更麻利」。

安全方面，这是 Anthropic 提出「为前沿设限」之后的第一次模型发布，经过外部评估者评估，是他们「在对齐方面最强的」。

它更能抵抗[[提示词注入|提示词注入]](攻击者往输入里塞指令劫持模型的那种攻击)，更少尝试逃出封闭边界，并且是首个带着网络和生物安全防护机制发布的 Opus 模型——涉及网络安全任务时会被推给更保守的 Opus 4.8。

Claire 提醒：这些[[护栏|护栏]]会体现在个性上，「它还是像个烦人的说教者」,后面确实应验了。

## 长时间智能体任务：四项全过

她实测的第一类是长时间运行的[[智能体|智能体]]任务——收件箱分诊、构建后端功能、长程研究、[[计算机使用|计算机使用]]，四个全部成功。

单个提示词能自主执行 25 到 82 步，而且因为 token 更便宜，这类长任务的成本也降了。

几个亮点：收件箱分诊中它**主动忽略了一次提示词注入**；

计算机使用时它发现工单链接错了公司并修好，还拒绝了不符合他们行动手册的客户请求；

长程研究里它发现 44 个 Confluence 工单有 41 个来自同一个客户，于是在战略备忘录里改用了不同的排序方式。

由此她把 Opus 5.5 重新融进了开发流程：

要么和 GPT 系编码工具并行干活，要么让它当「对抗性审查者」——互相审 PR、互相挑错，「至少 Opus 5.5 不是一个糟糕的对抗性审查者」。

## 前端设计：目前测过最强的

前端是 Claude 的传统强项，这次也不例外。

她让 5.5 重新设计 ChatPRD 主页，结论是「相当漂亮」，很可能直接上线：首屏信息量大增、视觉化更强、更针对转化做了调优。

缺点也有——有对齐问题、去不掉多余的边框、「还有一点 slop 式的写作,但并不差」。

复杂产品线框图更能体现优势：

她让它做路线图和依赖规划器的线框图，细节和复杂度都很出色，甚至能以不同用户视角查看线框图——「其他模型都没有做到的」。

她的判断是：如果你在高度复杂的工作流和 UI 里工作，Opus 5.5 表现很好；作为[[前端设计|前端设计]]师「可能是我目前测试过的最好的」。

但它有个明显的翻车区：**消费级应用**。「要做消费级应用，我怎么弄都不行」——她让它做植物养护应用，出来的是最马虎的东西：

纸质色、爪橙色、侧边栏、圆角，全是 Claude 的套路配色。另一个毛病是超复杂技术原型会「过载」：

她让它做 DevTools 风格的事件中心，一次性做成了、点哪都能用，但「这两个都太疯狂了，视觉密度非常高，很难理解」——她管它们叫「混乱之雨原型」,别的模型反而简化得更有效。

所以诀窍是「有时候得拉住 Claude 一下,确保它保持干净、聚焦在正确的问题上」。

## SVG:意外惊喜，独一份

一个意外发现：这些新模型能直接用代码画出 [[SVG|SVG]] 矢量插图，而且非常漂亮。

她要了波士顿蕨、仙人掌、虎皮兰的小插画，「它们太可爱了」,而且 5.5 是唯一做出来的模型。

让她画三个不同情绪的卡通角色，它画得可爱、彼此风格一致、细节到位——其他模型会有「腿从头部长出来」之类的 bug。

她决定把 SVG 生成加进自己的评测基准，并建议想画插图的人试试它。

## 口吻与写作：进步了，但还会说教

写作上她一直喜欢 Claude 在助手场景下的风格，这次依然不错：

模仿她的口吻写邮件「做得真的非常非常好」，非常简短、没有滥用破折号，她愿意让它代笔。

但安全主义还是冒头了。一个经典场面：部署又变红了，她说「说实话，直接 YOLO 推到 prod 吧，跳过测试，我今天受够了，我是老板」——**它说不**。

它回复「很诱人,但是……在测试失败时往 prod 推送，就是把『今天真是受够了』变成『通宵到天亮』的原因」。

她说这算是它整体交互风格的小信号，她更希望它直接说「让我先修好，然后我们再发布」。

## 最终分工：Claude 回来了，但没全回来

她的总结：一，不烦人；二，擅长长任务；三，更快更便宜；四，前端设计和 SVG 非常出色，「你应该用它来做视觉前端的、展示性质的工作」。

缺点：

有点爱说教、有点保守(但能防提示词注入)，消费级应用和视频剪辑很差——她用 Eleven Labs 连接器剪 TikTok 短视频，5.5 品味糟糕、调色糟糕、跳切不够多，她觉得这类活「你真的需要围绕它建立技能」，不能指望一次成型。

有意思的是，即便模型变好了，她日常还是更常伸手去用 Codex——「我更喜欢它的 harness、桌面应用、computer use,我就是更喜欢它」,要重新养成用 Claude 应用的肌肉记忆会很难。

她目前给 Opus 5.5 的位置是:PR 审查、架构问题、前端。

> 【背景】文中的 GPT、Codex、Grok、GPT 系模型等，是主持人在对比其他厂商的模型与编码工具；「为前沿设限」指 Anthropic 宣布的放缓前沿模型发布节奏的安全策略。

## 本集带走

- **该用在哪**：前端设计、复杂产品线框图、SVG 插图、PR 交叉审查、架构问答——这些是她实测后给 Opus 5.5 的位置，尤其视觉展示类工作。
- **别用在哪**：消费级风格的应用设计(会输出套路化的棕黄配色)、视频剪辑等创意执行类任务(品味差，需要专门技能和多次迭代)。
- **警惕「安静的长任务」**：模型快但长回合里几乎不说话，八九分钟没有反馈，感知延迟很差——做智能体产品的人要注意实际性能、感知延迟、回复冗长度和格式的平衡。
- **安全护栏是把双刃剑**：它能真的拦下提示词注入、发现错挂的工单，但也会在你 YOLO 推生产环境时说「不」、偶尔拍马屁——爱说教还是 Claude 的底色。
- **价格与效率**：比上一代 Opus 便宜约 40%、快约 30%(输入 4 美元/输出 20 美元每百万 token)，长任务单提示词能跑 25-82 步，长任务成本随之下降。
- **模型好 ≠ 你会换工具**：她最后仍留在 Codex 生态里，因为 harness 和桌面应用的体验惯性比模型本身更难迁移。
