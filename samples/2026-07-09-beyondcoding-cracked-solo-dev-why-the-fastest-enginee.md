It's my coding versus their setups." aria-label="回原文"></button> [[Kitsa|Kitsa]] 是一位同时兼顾 140 个项目的独立构建者，他把工程师分成了两拨：一拨是氛围编码者——往墙上扔东西，希望粘住；另一拨是有工程经验的人，他们驱动[[智能体|智能体]]时产出能好 20 倍，因为他们已经知道要去哪 <button class="pd-ts" data-t="02:32" data-who="Kitsa" data-en="So I don't like the term. ## Police 文件：把挫折变成规则

Kitsa 为自己写了一套叫"police script"的东西，本质上是用人驱动的 linter——ESLint 和 TypeScript 检查抓不到的那些规则，他用 LLM 来兜底 <button class="pd-ts" data-t="04:56" data-who="Kitsa" data-en="The LLM is not going to magically extract your knowledge from your brain and you will inevitably end up frustrated unless you turn that knowledge into rules and what do we call this like when you have a combination of like ESLint and TypeScript checks and a bunch of other rules like I've written something for myself called like a police script okay which is like rules and things that ESLint that linters cannot catch because linters have a limit what they can do what they cannot do" aria-label="回原文"></button>。每次被智能体气到，他就把那条规则加进 [[police 文件|police 文件]]。

智能体每完成一轮工作，自动启动自我纠正：先跑 TypeScript 纠正，再跑 linter，再跑格式化，最后跑 police 检查。发现 30 个 police 错误？

启动子智能体逐个修。目标是每一轮结束都归零——零问题、零警告、零类型错误 <button class="pd-ts" data-t="05:17" data-who="Kitsa" data-en="So we have all of these police files and the agent basically when it's done, it's auto-kicking another session of like correcting itself. It's like, okay, let me correct TypeScript, then let me correct the linter, let me run the formatter, and finally let me do the police check." aria-label="回原文"></button>。

大多数人不这么做，他们可能每天或每周才检查一次，那就太晚了。你需要每一轮都做 <button class="pd-ts" data-t="05:37" data-who="Kitsa" data-en="Zero issues, zero warnings, zero errors, zero type problems, and then you'll be happier. Most people don't have this loop, like a genetic loop to make sure that... And many people do it like maybe every day or every week or every month, and then it's too late." aria-label="回原文"></button>。

这套东西的核心认知是：LLM 不会神奇地从你大脑里提取知识，除非你主动把知识写成规则 <button class="pd-ts" data-t="04:37" data-who="Kitsa" data-en="the skills that you have as a human yeah the knowledge you have as a human combined with how much of that knowledge is written as skills rules memories and other stuff that the agent actively reads from i think many people are just even as you said like even senior engineers and people who know architecture and stuff they still are" aria-label="回原文"></button>。在智能体文件、[[技能文件|技能文件]]里，你想要的行为必须被捕捉到某个地方 <button class="pd-ts" data-t="06:19" data-who="Kitsa" data-en="Thank you for watching! In agent files, in skill files, wherever you can, the behavior that you want, you need to capture it somewhere. That for me is the kind of newer engineering practice, is the question of where do you do that?" aria-label="回原文"></button>。对 Kitsa 来说，这是一种全新的工程技能——不是输入英文然后代码就出来，而是设计[[循环|循环]]和规则 <button class="pd-ts" data-t="06:32" data-who="Kitsa" data-en="This is like a completely new skill. And people like, my entire talk is that people see this as typing English and code comes out. This is like a completely different skillset that most engineers don't want new skills." aria-label="回原文"></button>。

## 别追模型，深耕一套工具

Kitsa 的第一条建议很反直觉：坚持用一个提供商、一个模型，别追 <button class="pd-ts" data-t="41:25" data-who="Kitsa" data-en="Pivot into plumbing or whatever it is, you know. But on a serious note, I think my number one advice would be to stick to one provider and to stick to one model." aria-label="回原文"></button>。你会看到无数推文说"我们刚切换到 Composer 2.5，一切都变了"，然后你把整个心态从 [[Claude|Claude]] Code 搬到另一个完全不同的工具，子智能体工作机制不一样，你之前积累的练习全部归零 <button class="pd-ts" data-t="41:37" data-who="Kitsa" data-en="But on a serious note, I think my number one advice would be to stick to one provider and to stick to one model. Even though you're going to see so many tweets of like, we just switched to Composer 2.5 and it changed everything from us." aria-label="回原文"></button>。

他认为那些在所有人涌向 [[Codex|Codex]] 时还坚持用 Claude 的人，因为打磨出了完美的 Claude 设置，实际交付可能比迁移的人更好 <button class="pd-ts" data-t="42:08" data-who="Kitsa" data-en="So I think this was happening back and forth with Codex and Claude and Codex and Claude. I think the people who stuck with their Claude, let's say, when everyone moved to Codex because GPT 5.5 is smarter, I think there are people with perfect Claude setups that are actually outshipping and outdoing everyone who moved in Codex because" aria-label="回原文"></button>。类比以前那些精通 Angular 并按自己方式做事的人，比不停跳到 React、Svelte 的人更有生产力 <button class="pd-ts" data-t="42:45" data-who="Kitsa" data-en="Thank you for watching! 他自己的工作流主要在 Codex 应用里，用 GPT 5.5 开到超高 <button class="pd-ts" data-t="23:41" data-who="Kitsa" data-en="Whatever I tried, I'm coming back to just manually being in the workspace of a folder of a project and just juggling the chats there. ## 启动新项目的关键：永远指向现有代码库

Kitsa 从不从零开始。启动新项目时，他要么 fork 自己已有的东西，要么指向一个现有代码库说"做成跟那个一样的" <button class="pd-ts" data-t="19:27" data-who="Kitsa" data-en="I think the skills are reused across all my projects. So any agent, like when I start something new, I always point to an existing code base. So I either fork my own thing, which is zero to shipped, if it makes sense, if I need like a full stack app with a mobile and blah, blah, blah." aria-label="回原文"></button>。

如果从空白开始，智能体会走自己的路，选它想选的技术栈 <button class="pd-ts" data-t="19:46" data-who="Kitsa" data-en="Or if I need something simpler, it's like the Vite Plus with React, with Tailwind, with ChatCN, but I always try to point it like, hey. we're making let's say a budget tracker and i want it to be like x whatever app i have and it's like very good at like taking the boilerplate out and just making a clone i would never start just like if you start fresh with nothing it would just go its own way and just maybe do a you know choose whatever stack it wants yeah" aria-label="回原文"></button>。他的底层假设是：代码需要简单且易于更改。

如果不为此做工程化，以前你可能四五年后需要重写，现在这个时间线会加速到六个月 <button class="pd-ts" data-t="20:09" data-who="Kitsa" data-en="For me, my running hypothesis is that code needs to be simple and easy to change. If we don't engineer for that, then maybe in your organization or in your project, you would have needed a rewrite four or five years down the line." aria-label="回原文"></button>。所以你要通过技能文件、agent MD 文件、钩子、静态代码分析来确保代码保持简单可变，而且这些东西做好了可以从一个项目搬到另一个项目 <button class="pd-ts" data-t="20:30" data-who="Kitsa" data-en="And now we're gonna engineer around that, right? How can you engineer either in your skills, your agent MD files, your hooks, static code analysis in such a way that that stays true." aria-label="回原文"></button>。

## 行业正在被拉平

Kitsa 的观点很直白：这个行业大多数人是"薪水过高用来瞎搞"的，用 React 移动几行代码就配吃五顿 LinkedIn 午餐，这从来就没道理 <button class="pd-ts" data-t="11:40" data-who="Kitsa" data-en="Welcome to... I think that engineers and people in IT need a rude awakening and I've been saying this for years and people hate it. I think that most people in this industry are overpaid to fuck around, to have like five lunches at LinkedIn." aria-label="回原文"></button>。以前门槛很低，懂点 HTML 和 CSS 就能找到工作，特别是 COVID 之后到处缺人 <button class="pd-ts" data-t="12:50" data-who="Kitsa" data-en="And most people don't. Like the bar for a job for me got like way too high right now. It was super easy." aria-label="回原文"></button>。

现在门槛非常高了——一个掌握了如何管理智能体和编写规则的中级工程师，可以胜过五个顽固坚持"我要按我的方式来"的高级工程师 <button class="pd-ts" data-t="13:16" data-who="Kitsa" data-en="You need to bring not only engineering knowledge, but some, let's say, mid-engineer, medium-level engineer, I want to say, with... A genetic knowledge of how to juggle agents and write rules can outperform, I would say, five stubborn seniors who are like clinging to their, no, I will do it my way and blah, blah, blah." aria-label="回原文"></button>。10 人的团队可以变成 2 人 <button class="pd-ts" data-t="13:35" data-who="Kitsa" data-en="So it's like, which combo can you, I think we need to rethink everything, like the interview process and all of that, like the old values of how you write clean code and blah, blah, blah don't matter." aria-label="回原文"></button>。

但同时，新模型出来时所有人同时拿到，竞争环境是平等的 <button class="pd-ts" data-t="14:08" data-who="Kitsa" data-en="But for me, the fun thing is there is an equal level of playing field, right? New model Fable 5 came out. When you're listening to this, it's probably weeks ago." aria-label="回原文"></button>。初级工程师没有历史包袱，反而可能加速超越 <button class="pd-ts" data-t="14:49" data-who="Kitsa" data-en="That if you're early in career, you can learn a lot and you can accelerate. You don't have the same baggage, which is a downside or an upside, depending on how you look at it." aria-label="回原文"></button>。以前那些通过盗版 Photoshop 做烂 PHP 网站、看 jQuery 教程混进行业的人，和有硕士学位能写 C++ 的人是两类人——后者反而是受伤害最深的，因为他们的深度技能正在被稀释 <button class="pd-ts" data-t="09:47" data-who="Kitsa" data-en="I had this in a joke in a talk that I just gave once and never again that most of us listening to what I'm saying here have clawed their way into this industry by pirating Photoshop and doing some shitty PHP website and then watching some jQuery tutorial and then by some luck landing an internship somewhere where they let you fuck around with like Angular or whatever and somehow you just hop from one thing to the other and you end up where you are?" aria-label="回原文"></button>。

## 智能体会从助手爬到管理者

在团队协作层面，Kitsa 看到智能体在组织里正在从结对编程的助手，往上爬到三人团队的管理者，再到 CDO 级别 <button class="pd-ts" data-t="38:22" data-who="Kitsa" data-en="In organizations and in teams, I see the agents crawling from like the helper that's doing peer programming with you to eventually the manager of your three-person programming team to eventually the CDO to eventually to other positions where your job is to be on the lower levels just unblocking." aria-label="回原文"></button>。最终人类的工作是在低层级解除阻塞。

他甚至问 Fable：怎么逆转这个过程，让智能体当 CEO，只给他分配解除阻塞的任务 <button class="pd-ts" data-t="38:34" data-who="Kitsa" data-en="I see it in my solo work. I asked Fable yesterday, like, how do we inverse the process where you're the CEO, you run everything, and you just assign me tasks of how to unblock you and the sub-agents moving forward." aria-label="回原文"></button>。这不会顺利，会有人反抗，但他认为是不可避免的 <button class="pd-ts" data-t="38:48" data-who="Kitsa" data-en="It's just gonna take some time. There's going to be people who are going to rebel, throw molotov cocktails, set data centers on fire. It's not going to be smooth, but I think it's inevitable." aria-label="回原文"></button>。

有意思的是，他提到一位 VP 说最好的工程师就是能"先解除自己的阻塞，再解除别人的阻塞"的人 <button class="pd-ts" data-t="39:06" data-who="Kitsa" data-en="And I asked him what distinguishes really good engineers. And he said the best engineers at our company, they are the people that, first of all, are able to unblock themselves and then unblock others." aria-label="回原文"></button>——这个模式在智能体时代反而更成立，只不过"别人"可能变成了智能体。

他对当前工具的不满也很具体：所有编排器——Cursor、Copilot——迭代了这么久，最好的 UI 就是左边文件夹列表、右边聊天框 <button class="pd-ts" data-t="21:32" data-who="Kitsa" data-en="Even at companies like, I don't know, OpenCode or whatever, they'll be like, our team of 13 designers iterated on 17 iterations and like the best they can come up with is a sidebar on the left and chat on the right." aria-label="回原文"></button>。但他要同时处理 140 个项目，这种 UI 完全不够用 <button class="pd-ts" data-t="21:51" data-who="Kitsa" data-en="Two projects with two chats, maybe this makes sense. But I'm trying to juggle literally 140 projects here. Not all of them are active." aria-label="回原文"></button>。他认为智能不是瓶颈，GPT-5、Opus 都够用了，瓶颈在编排——你没有在智能体周围放对循环、规则和[[护栏|护栏]] <button class="pd-ts" data-t="17:41" data-who="Kitsa" data-en="Even I realized this with Fable 5. I'm like, I realized the intelligence wasn't really the problem. Like cool, it's intelligent, but GPT-5, Opus, whatever, they're good enough." aria-label="回原文"></button>。

## 本集带走

- **把每次挫折写进规则文件**：被智能体气到时，别骂完就完，把那条规则加进 police 文件，让智能体每轮结束自动跑一遍自我纠正循环，目标是每轮归零。
- **新项目永远指向现有代码库**：不要从零开始，fork 自己的项目或指向一个现有代码库作为参照，否则智能体会自己选技术栈、走自己的路。
- **别追模型，深耕一套工具**：切换工具意味着丢掉你积累的所有规则和练习，精通一套的人比不停跳的人产出更高。
- **代码工程化的目标不变：简单且易于更改**：智能体时代这个原则没有变，变的是时间线——不做好这点，重写周期从四五年缩短到六个月。
- **核心竞争力从"写代码"变成"写规则和解除阻塞"**：能设计好循环和规则的中级工程师，产出碾压不适应变化的高级工程师。

<script>
(function(){
  function fmt(s){
    if(!isFinite(s)||s<0) s=0;
    var m=Math.floor(s/60), x=Math.floor(s%60);
    return (m<10?'0':'')+m+':'+(x<10?'0':'')+x;
  }
  function wire(box){
    if(box.dataset.wired) return; box.dataset.wired='1';
    var a=box.querySelector('audio'), pb=box.querySelector('.pb'),
        bar=box.querySelector('.bar'), fill=box.querySelector('.bar > i'),
        tm=box.querySelector('.tm'), t2=box.querySelector('.t2');
    if(!a||!pb||!bar||!fill||!tm) return;
    var total=0;
    function paint(){
      var cur=a.currentTime||0;
      fill.style.width=(total?(cur/total*100):0)+'%';
      tm.textContent=fmt(cur)+(total?' / '+fmt(total):'');
    }
    a.addEventListener('loadedmetadata',function(){
      total=a.duration||0;
      if(total&&t2) t2.textContent=Math.round(total/60)+' 分钟 · AI 合成朗读';
      paint();
    });
    a.addEventListener('timeupdate',paint);
    a.addEventListener('play',function(){ pb.textContent='❚❚'; pb.setAttribute('aria-label','暂停'); });
    a.addEventListener('pause',function(){ pb.textContent='▶'; pb.setAttribute('aria-label','播放'); });
    a.addEventListener('ended',function(){ pb.textContent='▶'; });
    pb.addEventListener('click',function(){ if(a.paused) a.play(); else a.pause(); });
    function seek(ev){
      if(!total) return;
      if(ev.clientX==null) return;
      var r=bar.getBoundingClientRect();
      var x=Math.min(Math.max(ev.clientX-r.left,0),r.width);
      a.currentTime=(x/r.width)*total;
      paint();
    }
    bar.addEventListener('pointerdown',function(ev){
      seek(ev);
      function mv(e){ seek(e); }
      function up(){ document.removeEventListener('pointermove',mv); document.removeEventListener('pointerup',up); }
      document.addEventListener('pointermove',mv); document.addEventListener('pointerup',up);
    });
    a.addEventListener('error',function(){
      box.classList.add('pd-play-dead');
      box.textContent='本集中文精华音频还没生成好,稍后再来听。';
    });
  }
  function all(){ document.querySelectorAll('.pd-play').forEach(wire); }
  document.addEventListener('nav', all);
  if(document.readyState==='loading') document.addEventListener('DOMContentLoaded', all); else all();
})();
</script>
