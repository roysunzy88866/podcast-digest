「[[送出你的乐高|送出你的乐高]]」是 [[Molly Graham|Molly Graham]] 十三年前写下的经典职业建议：随着公司长大，你要主动把项目、团队、职责交给别人，而不是本能地抓住不放。她 20 多年在 [[Google|Google]]、[[Facebook|Facebook]]、Quip、Chan Zuckerberg Initiative 做领导工作，见过太多人围绕「我拥有的那个东西」建立身份认同，然后在规模化面前痛苦挣扎。

但在这场对话里，她做了 13 年来最大的一次修正：**当你要把乐高交给 [[AI|AI]] 时，这条建议不再完全成立**。有些乐高就是不该送出去。

## 原版建议的来龙去脉

建议诞生于她在 Google 和 Facebook 亲历的疯狂扩张：她的部门九个月内从 25 人涨到 125 人；Facebook 从她加入时的 500 人、8000 万用户（比 MySpace 还小）涨到她离开时的 5500 人、十亿多用户。她看着人们围绕自己建造的东西建立身份，然后经理走过来说「把它交出去」，第一反应全是抗拒。她用幼儿园小朋友的隐喻讲这件事：有人往你面前倒一堆乐高，你搭了塔，别人想把塔拿走时，本能反应是「走开」——但实际上有人接手，意味着你可以去做新的、好玩的东西。

文章发出去后她收到了来自世界各地的邮件——Safeway 的员工、尼日利亚一个团队从两人涨到四人的创始人。她的第一反应是「这不是写给你的」，第二反应才是：这讲的是比快速扩张大得多的东西——**变化本身**。

一句话总结这篇文章：「面对快速增长，你的主要工作是让自己变得不再被需要，因为这是你为接下来任何事情做好准备的唯一方式」，外加一句安慰：「别担心，一切都会好起来的。」

## 哪些至今仍然成立

**变化很可怕、很难，这是正常反应。** Molly 说她收到的邮件里大量是[[悲伤|悲伤]]、不堪重负、倦怠——「变化很糟糕。

它也可以很棒，但我们不必装可爱的小兔子，我们也可以直说这很难」。她举例：一位产品负责人说现在「人人都该成为全能构建者」，却感到孤独，因为协作被剥夺了，整天和机器人工作。

Molly 的回应不是打鸡血，而是「是啊，这确实很糟，我们先在这里待一会儿」。把感受直说出来有巨大的力量——她发誓 Legos 文章最大的作用就是团体治疗。

**未来属于学习的人，不属于知道的人。**「你到明天为止能学到的东西，远比你今天已经知道的东西重要得多」——她说这句话在 AI 时代前所未有地真实。

她在 Facebook 头两年在 HR，能真真切切看到：某一年的最高绩效者，如果没跟上变化，不到一年就落水了。原地不动感觉安全，实际上是最不安全的——你注定落后。

**拥抱变化仍然是对的事**，即使它比以往任何时候都更可怕。

## 哪些变了：交给 AI ≠ 交给人类

Molly 做过的乐高演讲里，人们最爱问「送出乐高的最好方式是什么」。她的经典答案是：「把它们扔到他们脸上，然后朝另一个方向跑」——因为人的倾向是控制，是要求别人完全按你的方式重建那座塔。交给一个资深人类工程师，你真的能放手。

**但对 AI 做不到。她最大的领悟是：把事情委托给机器人，不等于把它送出去，因为你无法摆脱监督。

**「把一块乐高转让给别人、你真正摆脱了它」和「委托给别人」是两回事。工作 AI 做了，但监督权和最终产品仍在你手里，精神税也留在你身上——心理上你仍然背着所有机器人在做的所有事。

这意味着你没有腾出空间去做新事情，而这恰恰是原版建议的全部意义。她猜测这正是倦怠数据的来源之一：突然之间你要监督所有这些机器人。

而且管理 AI 就像管理初级员工——「AI 现在是相当初级的员工」，需要背景信息、需要入职引导、需要不断纠正。太多人当年主动选择不当[[管理者|管理者]]，如今「世界上每个人都是管理者了」。她说一个人最多应该管理 10 到 12 名员工，把机器人也算进去，她为人们的心理状态担心。

## 恐惧叙事在毒化一切

现在的主流叙事是：「我们雇了这位新员工，他比你聪明十倍，你要把知道的一切倒给他，然后六个月后他会抢走你的工作。谁他妈愿意这么干？」Molly 认为这个叙事不符合现实：目前没有太多数据表明 AI 真在夺走工作，她对所有打着 AI 旗号的裁员有很多不满——「它们是胡扯，是经营不善的公司贴上 AI 标签捞股价，而不是承认『我们雇了太多人』」。

她从记者 Manoush Zomorodi 那里得到一个换角度的问题：不是「如果你相信工作会消失你会怎么做」，而是**「如果你相信你的工作会永远存在、只是每六年完全变一个样子，你会怎么做？」**——你是否想成为设计那个未来的一员，还是想留在这里保护你所知道的？Molly 立场鲜明：在数据真正说反之前，尤其在科技行业，你应该迎上去。

## 哪些乐高不该送出去（13 年来最大的修正）

这是 Molly 为这期节目准备的最新结论。过去有人问她「有没有后悔送出去的乐高」，在快速扩张的语境里她的回答总是「不，都他妈送出去」。**但在 AI 领域，她现在要加限定条件：有些乐高机器人不配得到，我们应该抓住不放**：

- **需要判断力和战略的事情。** 对那些向 AI 要一份战略、复制粘贴发给全公司的 CEO：那是一个人类大脑——你作为 CEO——必须亲自掌控的事情。发一封明显 AI 写的备忘录，是在向组织示范「把思考外包出去没关系」，是在示范你不需要对发出的工作负责。
- **需要信任的、对关系根本性的东西**，不该外包给机器人。
- **你还不理解什么是「好」的东西。**「如果你不知道质量的定义，你怎么能把它交给你的暑期实习生？」
- **人类独擅长、本来就不该人做的事之外的核心**——她的参照系是 [[Waymo|Waymo]]：开车从根本上就是代码和系统，人类真不擅长被自动化，这种事该交出去。

配套的心智模型是 Corey Doctorow 的「半人马 vs 反向半人马」：半人马是人头控制马身——AI 听我们指挥，很好；反向半人马是马头控制人身——AI 在利用我们做事，DoorDash 和 Uber 的人已经活在那个世界里，而且它可能扩展到知识型工作。要把 AI 放在事情中间：你在顶层出方向和想法，AI 干活，你审查、迭代——「AI 三明治」。

人类的角色是引导产品走向我们想要的世界，而不只是最优化的 AI 版本：[[Booking.com|Booking.com]] 把每一次互动优化到极致（各种追加销售、紧迫感），非常有效；[[Airbnb|Airbnb]] 的选择是不变成那样。**[[品味|品味与愿景]]是人的工作——把世界的未来外包给一群暑期实习生，我们就有麻烦了。**

## AI 垃圾、生产力幻觉与倦怠

[[Lenny|Lenny]] 的调查数据印证了情绪面的代价：2025 年 44% 的科技从业者感到倦怠，今年升到 55%；但同时有一半人感到职业生涯中最幸福，最强相关性是「AI 放大了他们」的人，幸福感集中在小团队和更有权限的人身上。设计师是最不开心的群体——设计没法像代码那样加速迭代，得获取反馈、得思考，而且现在「人人都是设计师」，人人拿 Gemini 或 Claude 生成的东西来指导你。

Molly 认为倦怠的一大来源是**叙事本身的变化速度**：[[OpenAI|OpenAI]] 内部花了六个月从「token 榨到极致、到处用 AI」变成「等等，这真的有差别吗？它太贵了」。

还有一种被占便宜的感觉：「我明白为什么这对利润有好处，但提醒我一下，这对有什么好处？」

核心区分是**[[生产力|生产力 vs 效率]]**：生产力是能不能生成更多——已证明我们都能生成一堆垃圾让别人去趟；效率是有没有真的往某个地方去。有一份工程报告：AI 确实让人更有生产力，但必须重写的代码行数涨了 8 倍。

Lenny 那条流行推文是同一个意思：「每个人工作中越来越大的一部分，是在清理别人试图干你的活时产生的 [[AI 垃圾内容|AI 垃圾]]。」而垃圾泛滥的根源，是人们把问责甩掉了——把实习生交的演示文稿直接转发给老板，从来不是好工作产生的方式。

## 给管理者的三句话

IC 的世界反而清晰，最难的是管理者和领导者。Molly 的建议：第一，明白你是榜样，你怎么用 AI、怎么身处这个时刻都会向下渗透；多谈论悲伤和情绪，仅仅是承认这种变化速度对人心理的影响，就能让人们好受一些。

第二，守住问责和「什么是好」的定义——Clay 发布的 AI 写作政策是个好范例：为你的产出负责，无论你怎么做出来的。第三，别跟着大公司取消管理层级的潮流走——那是巨大的错误；调查数据显示**管理者是工作幸福感最强的杠杆**，而现在大多数人的管理者并不好。她还有一句忠告：你一生只会遇到几个好管理者，找到一个就拼了命抓住。

## 本集带走

- **变化可怕是正常的，别对情绪装傻**：悲伤、倦怠、怀念旧工作都是身体对变化的真实反应，说出来、甚至为逝去的工作方式「办一场葬礼」，然后再问「我能再次以那种方式热爱什么」。
- **分清「转让」和「委托」**：交给人类你可以彻底放手，交给 AI 你仍背着全部监督的精神税——所以要有意识地把 AI 当实习生对待，想清楚什么给实习生、什么绝不给。
- **有几类乐高不要送**：战略与判断、信任与关系、你还没能力判断好坏的领域，以及你真正热爱、不想让它接手的部分。
- **换一个问题框架**：不问「工作会不会消失」，问「五年后我的工作会变成什么样、我想不想参与设计它」。数据并未支持「AI 抢走工作」的叙事，恐惧大多被夸大。
- **从生产力转向「什么是好」**：生成更多不是目标，问「它好吗、值得别人的时间吗、能长存吗」才是现在的差异化机会。
- **你没落后**：大实验室的共识是现在还在第一局，从新手到专家的距离很短；最值得培养的新技能是做每件事前先问一句「AI 能帮我做这件事吗」。

<script>
(function(){
  function fmt(s){
    if(!isFinite(s)||s<0) s=0;
    var m=Math.floor(s/60), x=Math.floor(s%60);
    return (m<10?'0':'')+m+':'+(x<10?'0':'')+x;
  }
  function wire(box){
    if(box.dataset.wired) return; box.dataset.wired='1';
    var a=box.querySelector('audio'), pb=box.querySelector('.pb'),
        bar=box.querySelector('.bar'), fill=box.querySelector('.bar > i'),
        tm=box.querySelector('.tm'), t2=box.querySelector('.t2');
    if(!a||!pb||!bar||!fill||!tm) return;
    var total=0;
    function paint(){
      var cur=a.currentTime||0;
      fill.style.width=(total?(cur/total*100):0)+'%';
      tm.textContent=fmt(cur)+(total?' / '+fmt(total):'');
    }
    a.addEventListener('loadedmetadata',function(){
      total=a.duration||0;
      if(total&&t2) t2.textContent=Math.round(total/60)+' 分钟 · AI 合成朗读';
      paint();
    });
    a.addEventListener('timeupdate',paint);
    a.addEventListener('play',function(){ pb.textContent='❚❚'; pb.setAttribute('aria-label','暂停'); });
    a.addEventListener('pause',function(){ pb.textContent='▶'; pb.setAttribute('aria-label','播放'); });
    a.addEventListener('ended',function(){ pb.textContent='▶'; });
    pb.addEventListener('click',function(){ if(a.paused) a.play(); else a.pause(); });
    function seek(ev){
      if(!total) return;
      if(ev.clientX==null) return;
      var r=bar.getBoundingClientRect();
      var x=Math.min(Math.max(ev.clientX-r.left,0),r.width);
      a.currentTime=(x/r.width)*total;
      paint();
    }
    bar.addEventListener('pointerdown',function(ev){
      seek(ev);
      function mv(e){ seek(e); }
      function up(){ document.removeEventListener('pointermove',mv); document.removeEventListener('pointerup',up); }
      document.addEventListener('pointermove',mv); document.addEventListener('pointerup',up);
    });
    a.addEventListener('error',function(){
      box.classList.add('pd-play-dead');
      box.textContent='本集中文精华音频还没生成好,稍后再来听。';
    });
  }
  function all(){ document.querySelectorAll('.pd-play').forEach(wire); }
  document.addEventListener('nav', all);
  if(document.readyState==='loading') document.addEventListener('DOMContentLoaded', all); else all();
})();
</script>
