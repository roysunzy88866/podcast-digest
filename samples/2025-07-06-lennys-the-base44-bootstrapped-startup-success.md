# 一个人六个月做出八千万美元公司

<div class="pd-tldr"><b>一句话</b>独立创始人零融资，六个月从零到以八千万美元被 Wix 收购，全靠 AI 写代码。</div>

[[Maor Shlomo|Maor Shlomo]] 做了一个叫 [[Base44|Base44]] 的 AI 应用构建平台——你用自然语言描述想要的东西，AI 帮你写代码把它做出来。六个月后，他以超过 8000 万美元的价格把公司卖给了 [[Wix|Wix]]。

整个过程只有他一个人，没融过一分钱，三周就达到了 100 万美元 ARR，用户到了 40 万。过去三个月里，他没写过一行 HTML 或 JavaScript，全靠 AI 写 <button class="pd-ts" data-t="33:27" data-who="Maor Shlomo" data-en="But then, throughout time I saw that I'm able to keep the pace, if not even have like a faster pace and have like a different angle and it's not changing over time so nobody is like... And so I think it's a different ballgame because even if you're a very small team or even if you're solo, you're, literally, managing teams of AIs, like writing code." aria-label="回原文"></button>。

## 不做大，先做自己喜欢的

Base44 的起点非常具体：女朋友需要一个小网站获取客户，他去用传统的拖拽建站工具，觉得痛苦得要命；同时他在帮以色列童子军做志愿，这个大组织没有任何内部工程师，每次找外包报价都是上百万美元。而他之前的公司就在跟 [[LLM|LLM]] 打交道，他知道模型完全有能力写这些代码，缺的只是一个合适的基础设施——让模型能直接访问数据库、用户管理、集成这些东西，把自然语言翻译成真正能跑的应用 <button class="pd-ts" data-t="08:18" data-who="Maor Shlomo" data-en="Okay, so how did this start? There were two things I think that drove me to it. One, my girlfriend needed a website to capture leads." aria-label="回原文"></button>。

他上一家公司 Explorium 融了 1.3 亿美元，他当了七年 CEO。但这次他的心态完全不同：他不打算做最大的东西。

他和女朋友从亚洲旅行回来的飞机上，他说如果年底前 ARR 到 150 万就买辆好车，结果四周就到了 <button class="pd-ts" data-t="37:50" data-who="Maor Shlomo" data-en="I don't care if it's going to become really big or not. I remember when me and my girlfriend got back from like the trip to Asia, and we were on the plane, I told her, &quot;Hey, you know what?" aria-label="回原文"></button>。「Base44 在我生命中第一次不是试图建造有史以来最大的东西。」<button class="pd-ts" data-t="00:05" data-who="Maor Shlomo" data-en="In six months, he went from zero, basically nothing to selling this company for 80 million plus dollars to Wix. The funny thing is that Base44 for the first time in my life was not trying to build the biggest thing ever." aria-label="回原文"></button>

## 独立创业的边界和代价

他认为独立自力更生不适合所有场景。做 B2B、特别是企业级销售的公司，你得雇销售团队、花钱做营销，一个人扛不住。但如果你的产品有病毒传播的潜力，面向大众，那独立自力更生一旦跑过产品市场契合的临界点，从财务结果来看反而更好 <button class="pd-ts" data-t="15:25" data-who="Maor Shlomo" data-en="How do you get stuff done as a solo founder using AI? One solo founder and specifically bootstrapping, I don't think it's suitable for every use case. If you're building a B2B company, especially if you're doing a B to enterprise company, you'll need to hire a salesperson or sales team." aria-label="回原文"></button>。

压力小是实打实的好处——醒来就是盈利的，不需要对投资人交代。但代价也真实：没有 DevOps 团队、没有 on-call（值班），出了事只能自己扛。

他在哥哥婚礼上接到朋友电话说 Base44 被黑了、变成了加密骗局，他找了个借口溜出去打开笔记本电脑，度过了一生中最可怕的两个小时。最后发现只是 LLM 用了一个叫 cryptography 的包——这是 Node.js 的普通包，跟加密货币没关系，非技术用户看到报错就慌了 <button class="pd-ts" data-t="18:10" data-who="Maor Shlomo" data-en="I had a few accidents that really, I'm joking about that, but I was saying it to my friends, shorten my life a bit with just the stress. I had one funny, now I look at it as a funny moment, where I was at my brother's wedding and we were doing the photo shoots and I was actually the one actually was supposed to also do the ceremony and then doing the photo shoots." aria-label="回原文"></button>。

每天的痛苦是「无情的优先级排序」：他想写代码、改进产品，但很多时候瓶颈不在产品，而在营销和获客。他必须逼自己做不想做的事 <button class="pd-ts" data-t="20:40" data-who="Maor Shlomo" data-en="And obviously nowadays with AI and everyone can build software, you have to go extremely fast on one side and on the other side figure out marketing along the way and how to do that." aria-label="回原文"></button>。

## 用 AI 写 AI：他的技术栈和效率体系

他有严重的 ADHD，所以第一步是管住自己的注意力。用 RescueTime 之类的工具锁死 Twitter 和 LinkedIn 的访问 <button class="pd-ts" data-t="23:11" data-who="Maor Shlomo" data-en="What else did you use day-to-day that helped you be more efficient? So I have severe ADHD, and so it can also be like a superpower. But then you have to like, first, the first thing you want to do is make sure that your workday looks that you can be focused and that you get a lot of like deep work and so." aria-label="回原文"></button>。

技术栈上：基础设施全部在 [[Render.com|Render.com]] 上，他评价极高，说比自己上一家公司那整个 DevOps 团队搭的流程还好用 <button class="pd-ts" data-t="68:40" data-who="Maor Shlomo" data-en="Just what are the tools and infrastructure used to build Base44? Render.com, oh, my God. Honestly, they're not paying me anything." aria-label="回原文"></button>。数据库用 [[MongoDB|MongoDB]]，因为 [[vibe coding|vibe coding]] 场景下数据结构（schema）变化极快，LLM 经常改来改去，文档数据库更灵活 <button class="pd-ts" data-t="69:51" data-who="Maor Shlomo" data-en="It's a whole thing. MongoDB is really good when you're vibe coding, especially when you're building a vibe coding platform because schemas change a lot and it's not necessarily users." aria-label="回原文"></button>。后端用 Python，虽然有人嫌弃性能，但他没遇到问题，甚至扛过 DDoS <button class="pd-ts" data-t="72:42" data-who="Maor Shlomo" data-en="Besides that, so my stack is the back end is in Python. I feel like people can be very judgmental about that. In terms of performance, I haven't gotten into performance issues." aria-label="回原文"></button>。

几个关键的技术判断：第一，别用 TypeScript，用纯 JavaScript 和 JSX——对模型来说写代码更容易出错，少一层类型系统反而更顺畅 <button class="pd-ts" data-t="71:46" data-who="Maor Shlomo" data-en="And obviously, everything that has to do with rule set does one. Controversial take for me working with LLMs is don't use TypeScript, use plain JavaScript, use JSX." aria-label="回原文"></button>。第二，前后端放在同一个代码仓库里，这样给 AI 的上下文更完整 <button class="pd-ts" data-t="72:20" data-who="Maor Shlomo" data-en="Part of the reason why I haven't written a single line of HTML or JavaScript in the past, just it does this really well. And another thing that works really well working with AI is try to push as much as possible in the same repository itself." aria-label="回原文"></button>。

第三，也是最重要的——花 20% 到 30% 的时间优化代码仓库，让 LLM 能写出尽可能少的代码。他搭了一套高度抽象的基础设施层，把增删改查、认证、数据库操作全封装好了，LLM 实现新功能时只需要写很少的代码。代码越少，出错的地方越少，上下文也越省 <button class="pd-ts" data-t="70:24" data-who="Maor Shlomo" data-en="Obviously Kelso, but again, I was spending 20, 30% of my time just optimizing for making the whole repository LLM suitable. By the way, those are concepts that I also implemented in Base44, but one thing that I kept doing is I tried making the LLM write as least code as possible." aria-label="回原文"></button>。

Base44 内部用了多模型路由：Claude 擅长从零开始写应用和 UI 设计，Gemini 擅长处理复杂算法或者 Claude 陷入 bug 循环时的兜底。他会根据用户输入自动判断该派给哪个模型 <button class="pd-ts" data-t="73:20" data-who="Maor Shlomo" data-en="And another maybe interesting take is because there's many of the new apps and products that are being built to some degree around LLMs. So one of the things that I use is for the LLM that actually writes code in Base44, I use a mix of different models for different tasks." aria-label="回原文"></button>。

他还用 Base44 自己给自己搭了内容生产工具：输入高层次的内容想法，自动拆解成 LinkedIn 帖子（保持他本人的语调，参考历史帖子），再拆成 Twitter 串。整个流程 vibe coding 出来，流程变了就改两个提示词就行 <button class="pd-ts" data-t="24:28" data-who="Maor Shlomo" data-en="Base44, not only did the work for the front end side, but also a lot of the business apps that I used, well, on top of Base44, so where I'd manage users and give credits and where write content." aria-label="回原文"></button>。

## 从三个朋友到四十万用户

前三个用户是亲密的朋友，其中两个当时正好失业。他让人家隔天来他家，坐在桌前用，东西坏了就看日志、改代码、推到生产环境，直接帮他们修好。

他的原则是：在确认用户真的喜欢之前，不花一分钱在营销上。怎么确认？看他们会不会主动分享给别人 <button class="pd-ts" data-t="40:22" data-who="Maor Shlomo" data-en="So let's start with 10. How'd you get your first 10 users? Just begging people close to me that I feel like that they have really good connections with to use it." aria-label="回原文"></button>。

当第 11 个用户出现——一个不认识他的人——他知道可以开始投营销了 <button class="pd-ts" data-t="42:29" data-who="Maor Shlomo" data-en="People loved it and all liked it and started sharing it with that. And so once I started seeing that this works, and we got to like 10 users where all my friends, and then the 11th user or something like this started seeing people that don't really know me, that's why I knew, okay, now it's time to invest in marketing or try to launch this thing or try to get more people to use it." aria-label="回原文"></button>。第一次 Product Hunt 发布很失败，但他不把它当成败关键，只当成「拿到下 30 到 50 个用户的工具」，确实拿到了 15 个新用户和第一个付费用户 <button class="pd-ts" data-t="43:19" data-who="Maor Shlomo" data-en="At some point, I saw it's starting to look like it's viral. Then I did a very failed, very bad ProductHunt launch, but also now looking back and saying, &quot;This is completely fine.&quot;" aria-label="回原文"></button>。

付费广告花了两千美元找网红、又试了几千美元的投放，全部没用 <button class="pd-ts" data-t="34:53" data-who="Maor Shlomo" data-en="Even distribution nowadays it's very different and also in favor of the solo, not necessarily the solo, but it's like not necessarily that you're going to pull a lot of money on paid campaigns like a Base44 goal with close to zero marketing budget." aria-label="回原文"></button>。真正起作用的是两件事：

**[[公开构建|公开构建]]**：一个朋友建议他分享独立创业的故事，因为他的受众就是构建者。他在 LinkedIn 上老老实实写好的坏的丑的，不装、不吹指标，分享技术栈细节、LLM 优化方法、增长数据、图表。他押注 LinkedIn 这一个渠道，看到有效果就全部精力扑上去，Twitter 反而觉得浪费时间 <button class="pd-ts" data-t="45:18" data-who="Maor Shlomo" data-en="At the end of the day, it's like you're going to have the same, like your audience or builders, they're trying to build their own products or maybe even businesses, and it will likely resonate with them.&quot;" aria-label="回原文"></button>。

**分享送额度**：在 Base44 里做了一个机制——用户只要在社交媒体上分享自己用 Base44 做的东西（甚至不需要提到 Base44），就送额外的构建额度。早期是用户发邮件给他手动处理，后来自动化了 <button class="pd-ts" data-t="46:30" data-who="Maor Shlomo" data-en="I didn't have an ability to do that or resources or money to pay for developers.&quot; And then the other thing that I did, it worked really well, is I've noticed that people really like sharing what they're building on top of Base44." aria-label="回原文"></button>。

这两招叠加，一周之内从每天 20 个新用户飙到每天 4000 个，直接把产品冲垮了——他不是 DevOps 工程师，不会扩数据库，虚拟 CPU 也扛不住 <button class="pd-ts" data-t="47:23" data-who="Maor Shlomo" data-en="I think there was two weeks between... no, a week between being on a pace of 20 users a day to seeing 4,000 users come into your product, like new users a day, break the product." aria-label="回原文"></button>。

还有一个增长引擎是 4Good 黑客马拉松：拿出利润做 5000 美元奖金，号召大家用 Base44 做公益应用。最终 3000 个团队参加，Amazon、Google、MongoDB、Deloitte 主动来赞助，他觉得这可能是职业生涯最棒的时刻之一 <button class="pd-ts" data-t="64:33" data-who="Maor Shlomo" data-en="We were at the 5,000- ish, 10,000-ish users. And so I said, &quot;Okay, well you know what? Let's do a hackathon where we open up for everybody to build apps that do good in the world.&quot;" aria-label="回原文"></button>。

速度本身就是增长引擎。产品隔天就更新，人们会说「它发展得太快了，我现在就得试试」<button class="pd-ts" data-t="67:24" data-who="Maor Shlomo" data-en="It gets them attached to this project if they are saying, &quot;Oh, I wonder what's going to be profit next week,&quot; or &quot;I wonder how much money is it losing and how can you optimize,&quot; and like they get attached to that." aria-label="回原文"></button>。

## 一个反直觉的产品教训

他在激活路径上砍掉了一个「正确但错误」的设计。原来 Base44 在写代码之前，会先生成用户流程（类似轻量版 PRD），让用户确认理解正确了再动手。

这确实能产出更好的应用，但转化率不行——因为 vibe coding 的「啊哈时刻」是「天哪，它真的懂我」，然后直接看到应用。中间加一步确认，惊喜感就打折了。他果断砍掉，让用户更快看到结果 <button class="pd-ts" data-t="76:06" data-who="Maor Shlomo" data-en="Here's one interesting thing that I learned that I think was counterintuitive to me because you always want to build the best product out there for your users, but sometimes it contradicts the aha moment or how fast can you get users to do that." aria-label="回原文"></button>。

## 为什么卖，怎么卖的

Wix 主动找来的，因为社区里很多人在喊「Wix 应该在它变大之前买下来」——同一个以色列生态，用户也在用 Base44 建网站 <button class="pd-ts" data-t="78:41" data-who="Maor Shlomo" data-en="So first of all, just how'd the acquisition conversation start? Wix reached out. I think back then there was a lot of folks from the community were posting saying, &quot;Hey, Wix should definitely buy Base44 before it gets too big,&quot; or something like that, even though we're not playing or competing in the same category, but it was clearly it's going to be-" aria-label="回原文"></button>。CEO Avishai 第一句话就是「大家都在说我们应该买你，至少值得聊聊」<button class="pd-ts" data-t="79:30" data-who="Maor Shlomo" data-en="The management team, Wix's management team is so friendly and such great guys. <script>
(function(){
  function fmt(s){
    if(!isFinite(s)||s<0) s=0;
    var m=Math.floor(s/60), x=Math.floor(s%60);
    return (m<10?'0':'')+m+':'+(x<10?'0':'')+x;
  }
  function wire(box){
    if(box.dataset.wired) return; box.dataset.wired='1';
    var a=box.querySelector('audio'), pb=box.querySelector('.pb'),
        bar=box.querySelector('.bar'), fill=box.querySelector('.bar > i'),
        tm=box.querySelector('.tm'), t2=box.querySelector('.t2');
    if(!a||!pb||!bar||!fill||!tm) return;
    var total=0;
    function paint(){
      var cur=a.currentTime||0;
      fill.style.width=(total?(cur/total*100):0)+'%';
      tm.textContent=fmt(cur)+(total?' / '+fmt(total):'');
    }
    a.addEventListener('loadedmetadata',function(){
      total=a.duration||0;
      if(total&&t2) t2.textContent=Math.round(total/60)+' 分钟 · AI 合成朗读';
      paint();
    });
    a.addEventListener('timeupdate',paint);
    a.addEventListener('play',function(){ pb.textContent='❚❚'; pb.setAttribute('aria-label','暂停'); });
    a.addEventListener('pause',function(){ pb.textContent='▶'; pb.setAttribute('aria-label','播放'); });
    a.addEventListener('ended',function(){ pb.textContent='▶'; });
    pb.addEventListener('click',function(){ if(a.paused) a.play(); else a.pause(); });
    function seek(ev){
      if(!total) return;
      if(ev.clientX==null) return;
      var r=bar.getBoundingClientRect();
      var x=Math.min(Math.max(ev.clientX-r.left,0),r.width);
      a.currentTime=(x/r.width)*total;
      paint();
    }
    bar.addEventListener('pointerdown',function(ev){
      seek(ev);
      function mv(e){ seek(e); }
      function up(){ document.removeEventListener('pointermove',mv); document.removeEventListener('pointerup',up); }
      document.addEventListener('pointermove',mv); document.addEventListener('pointerup',up);
    });
    a.addEventListener('error',function(){
      box.classList.add('pd-play-dead');
      box.textContent='本集中文精华音频还没生成好,稍后再来听。';
    });
  }
  function all(){ document.querySelectorAll('.pd-play').forEach(wire); }
  document.addEventListener('nav', all);
  if(document.readyState==='loading') document.addEventListener('DOMContentLoaded', all); else all();
})();
</script>
