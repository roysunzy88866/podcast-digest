# Stripe 一号员工为什么去买了一家银行

<div class="pd-byl"><b>Darragh Buckley</b> · Increase 创始人 · 2026-10-16</div>

[[Darragh Buckley|Darragh Buckley]] 是 [[Stripe|Stripe]] 的第一位员工。2010 年加入这家由 Limerick 同乡 Collison 兄弟创办的公司时，他负责的是银行相关事务。

如今他创办的 [[Increase|Increase]] 每年处理超过 5000 亿美元的支付流水，而他在一年多前做了一件更彻底的事：买下了一家真实的银行。

他在 The Peel 播客里聊了这整段经历，以及他在 Stripe 学到的那些东西。

## 在 Stripe 造产品，为什么总像穿着别人的鞋

Stripe 早期建在一批合作银行之上，Darragh 的感受是：始终像穿着别人的鞋，尺码总有点不对。

一个例子：Stripe 从 Visa 收到钱，要打给平台上的商户。

大额转账最自然的方式是电汇，但 Stripe 一直很犹豫——因为电汇失败时，银行伙伴会发一封邮件说这笔电汇没送出去，请你自己去修。

你没法在这种手工流程上造出一个让自己骄傲的产品 <button class="pd-ts" data-t="03:02" data-who="Darragh" data-en="You know, so it was always... You knew you weren't in the right place. You knew you were building on top of someone else's product." aria-label="回原文"></button>。

更典型的是 [[ACH|ACH]](美国的银行转账系统)的退回对账。ACH 文件里有个叫 trace ID 的字段，本该用来标识每笔交易，但经过 Wells Fargo 的处理后传不到 Stripe 手里。

结果 Stripe一度组了一个几十人的团队，专门靠启发式规则去猜哪笔退回对应哪笔交易 <button class="pd-ts" data-t="04:38" data-who="Darragh" data-en="Did Stripe do that for a while? You'd like build around these weird... Oh, certainly, yeah. You end up..." aria-label="回原文"></button>。

不是谁的错——银行系统本来就不是为程序员设计的。

## 他的答案：不是再加一层，而是往下重建一层

在 Darragh 看来，今天的银行业很像 2010 年的支付行业。

当年的模式是：你去银行拿一个商户号，再到 Authorize.net 这类网关获得编程接口——两个公司干一件事。

Stripe 的洞见是把它们合并成一个产品，开发者周日晚上就能注册开通。

而今天的金融科技公司建在银行之上，中间隔着 [[API|API]] 层，结构一模一样。

Darragh 认为这是错的：「**我们需要的是一家有技术肌肉的银行，而不是继续在银行技术上叠加层级**」<button class="pd-ts" data-t="14:02" data-who="Darragh" data-en="And my view is that's probably wrong, right? What we need is a bank with a technology muscle. We don't need to keep adding layers up on top of bank technology." aria-label="回原文"></button>。

Increase 做的就是替换掉银行的核心系统(记录余额和交易的那套东西)加上外面的 API 层，就像 Stripe 当年做的那样。

关键差别在于产品哲学。Stripe 为普通开发者造漂亮的[[抽象层|抽象]]；

Increase 面向的是 Ramp、Gusto 这类本身就是支付公司的客户，他们要的是原样透传——API 参数的名字都和网络层的叫法一致，不做任何包装 <button class="pd-ts" data-t="35:02" data-who="Darragh" data-en="Like we do not try to be creative and to create an abstraction there because you want High-fidelity pass-through of that data and information. And that's what I wanted while building Stripe." aria-label="回原文"></button>。

## 直接连美联储，比想象中靠谱

Increase 的系统直接和美联储的 FedACH、Fedwire、FedNow 等网络对话，而不是通过中间银行转一手。

中间商转手时，数据可能被改动；Stripe 拿不到的数据，也没法暴露给自己的客户——别人的抽象限制了你能做的事 <button class="pd-ts" data-t="30:49" data-who="Darragh" data-en="It wasn't Stripe's gift to give unless it had been given that gift, right? Someone else's abstraction places a limit on what you can do. And that can be frustrating from product, right?" aria-label="回原文"></button>。

美联储这一层本身质量出奇地好。

一年半前，Fedwire 系统整体切换到国际标准 ISO 20022,需要全美金融机构同一时刻硬切换——听起来像 Y2K 级别的灾难，结果靠几个月的规划和测试平稳完成，外人根本没听说过这件事 <button class="pd-ts" data-t="32:27" data-who="Darragh" data-en="Like, I know the fun fact here is about a year and a half ago, the Federal Reserve ran an update to its messaging specification to do with wires, right? Fedwire system bumped over to an international standard called ISO 20022." aria-label="回原文"></button>。

他的结论：**美国的底层存款网络其实很棒，缺的是最后一公里**——把它产品化、暴露出来的那一层。

## 怎么买一家银行：先开一场谁都不承认的会

买银行比买公司古怪。银行不能公开说自己要卖——一旦消息传开，放贷的员工会先跑光，而贷款是银行的核心资产。

于是行业里有个名字很妙的年会，叫「Acquire or Be Acquired」,去的每家银行都声称自己只买不卖 <button class="pd-ts" data-t="19:05" data-who="Darragh" data-en="And so the industry has this humorously named conference called Acquire or Be Acquired. You know, so like, let's allow ambiguity. Oh, you might be here to acquire." aria-label="回原文"></button>。

Darragh 最早在 2023 年想买华盛顿州的 Washington Business Bank,走到监管审批后期，监管方的回复大意是：

你人不错，但你先去银行董事会坐一阵子，我们互相了解一下。

他照做了，在董事会学到了很多——比如银行必须守住自己的放贷专长，别去追风口。

2010 年前后一批社区银行盲目上马金融科技合作，最后引来监管整顿，教训就是能力跟不上野心 <button class="pd-ts" data-t="22:17" data-who="Darragh" data-en="Yes, it would be the short answer. We ended up with a bunch of banks in like the 2010 timeframe, for example, chasing financial technology partnerships. And so a lot of community banks around the nation saw it as a growth mechanism and didn't have the appropriate like capability or capacity to be able to do so safely and soundly." aria-label="回原文"></button>。

最终他买下的是 Twin City Bank——一家华盛顿州特许的小银行，离他在俄勒冈州中部的家不远，上个月刚改名为 [[Increase Bank|Increase Bank]]。

但他强调，买下只是开始：不能简单贴个 API 就完事，[[合规|合规]]体系必须从一开始就写进代码里。

## 把监管检查当成每天跑的自动化测试

==合规怎么和工程结合==？Darragh 举了个例子：汇款超过 3000 美元时适用一条叫旅行规则的监管要求，规定哪些数据必须随钱一起传输。

正确做法是在建汇款系统的第一天就把它写进去，而不是等第一次审计时再打补丁 <button class="pd-ts" data-t="26:39" data-who="Darragh" data-en="If, for example, you are, there's a compliance regime that has to do with the data elements that need to traverse when you're sending a wire, and they apply at a threshold, dollar amount threshold of $3,000, and it's called the travel rule." aria-label="回原文"></button>。

他的方法论来自工程：怎么擅长做难事？多做。

就像工程师每天部署几十次，监管检查也应该每天对自己跑多遍，让那种「检查通过后松一口气」的感觉趋于零 <button class="pd-ts" data-t="28:03" data-who="Darragh" data-en="And I think you should try to make that sigh of relief asymptote to zero. I think that sigh of relief should be as small as possible. And the way in which you can get there is by running the examination on yourself more frequently." aria-label="回原文"></button>。

这也是 Increase 团队极小的原因——据 LinkedIn 大约 33 人撑起超过 5000 亿美元的年流水。

很多金融机构的运营团队，本质上是在为底层抽象的漏洞打补丁；把底层修好，人就不用那么多 <button class="pd-ts" data-t="43:16" data-who="Darragh" data-en="But the preamble aside, I'd go to, it's fascinating how much you can scale when you're just like building on top of the Federal Reserve, when you don't have those abstractions." aria-label="回原文"></button>。前提是安全，他特意强调。

## Stripe 早期教会他的事：跑着搬箱子

Darragh 和 Collison 兄弟在爱尔兰 Limerick 长大，在美国读大学时走得更近，2010 年以第一号员工身份加入。

他之前在 Lehman Brothers 工作过——按现在的标准看，那根本不算懂银行。

有两个场景他印象最深。

一次是早期接入信用卡网络，对方说下一个认证窗口在六周后，团队问有没有更早的——明天上午十点，但你们肯定准备不好。

他们要了那个时间，通宵干完 150 个测试用例，早上八点跑去 Fry's 买电话线零件，十点接上，十点全部通过 <button class="pd-ts" data-t="51:57" data-who="" data-en="Hang up the phone, kind of look around. It's like, okay, we've got 18 hours to get this like, you know, 150 test cases done. I guess I know what I'm doing." aria-label="回原文"></button>，当天跑通了公司第一笔真实交易 <button class="pd-ts" data-t="51:57" data-who="Darragh" data-en="Hang up the phone, kind of look around. It's like, okay, we've got 18 hours to get this like, you know, 150 test cases done. I guess I know what I'm doing." aria-label="回原文"></button>。

另一个更小：搬进第一个办公室，去宜家买了六套桌椅。

卸货时，别人搬一箱走回去搬下一箱；John 和 Patrick 放下箱子之后是小跑着回去的。「==如果周围的人都在跑，你会是唯一一个走路的吗==？」

<button class="pd-ts" data-t="58:08" data-who="Darragh" data-en="Why would we not just do it faster? Just run. We run." aria-label="回原文"></button> 他认为 Collison 兄弟最厉害的能力之一，就是用友善而非施压的方式制造这种紧迫感。

## 防欺诈没有捷径：先人肉看每一笔交易

有位金融业高管曾点破：Stripe 表面上是支付公司，实际上是防[[欺诈|欺诈]]公司。

支付天然吸引坏人，而欺诈的根源是身份问题——在线身份验证没解决，欺诈就解决不了 <button class="pd-ts" data-t="61:24" data-who="Darragh" data-en="Why has it been so hard to solve the fraud problem? If you're able to tell me how to properly solve the identity problem, I will be able to tell you how to solve the fraud problem." aria-label="回原文"></button>。

他给支付创业公司的建议很朴素：**在每天 5000 笔交易之前，应该有人肉眼看每一笔**。

你可以提前设计各种风控系统，但没见过数据之前你不会知道模式长什么样。你脑子里有一个很有效的神经网络，去用它 <button class="pd-ts" data-t="63:43" data-who="Darragh" data-en="But you're not even going to know what the patterns look like until you start seeing the patterns. You have a pretty effective neural net between your ears. You should go use it." aria-label="回原文"></button>。

## 他连 AI 助手都配了银行账户

Darragh 现在给自己的 AI [[智能体|智能体]]发支付卡。

智能体有自己的银行账户，账户里有多少花多少，花完了会来要：「给我的 100 美元用完了，能再给点吗？」<button class="pd-ts" data-t="66:36" data-who="Darragh" data-en="Like, I went through the $100 you gave me. Can I have more, please? And so you give them $100 more." aria-label="回原文"></button>

他刻意不坐在同步审批环节里——如果每笔交易都要他确认，智能体就会因超时陷入循环。

控制手段很简单：只能花账户里的钱。

而且智能体不需要加密货币或专门的接口，给它一张卡、16 位卡号，互联网上现有的结账页面就全能用了。

## 银行业最好的状态，是无聊

谈到启发他的人，Darragh 提到 Anthropic 联合创始人 Tom Brown 早年的一篇文章：用无聊的技术。别为每个场景挑最精巧的工具，复杂性本身是有代价的 <button class="pd-ts" data-t="70:03" data-who="Darragh" data-en="Tom Brown, who's one of the Anthropic founders previously at OpenAI, has this like remarkably impactful Like a technical essay from early on of like, just use boring technology widely, right?" aria-label="回原文"></button>。

他把这条原则用到极致：如果朋友是空管员，见面时说今天上班特别刺激，你会害怕。

银行也一样——「我想让你希望你的银行家度过平淡无奇的一天」<button class="pd-ts" data-t="72:01" data-who="Darragh" data-en="I think you want your banker to have an uneventful day. I think you want your banker to, in fact, enjoy uneventful days. There to be a quiet satisfaction of that." aria-label="回原文"></button>。基础设施就该像水和电，无事发生，就是最好的状态。

## 本集带走

- 建在别人系统上，别人的抽象会限制你能造的产品——Stripe 当年为 ACH 退回对账养了数十人团队，根因是一个传丢的数据字段
- Increase 的打法不是在银行技术上加 API 层，而是替换掉[[银行核心系统|银行核心系统]]本身，再直接对接美联储等底层网络
- 买银行要过 10% 和 25% 两道持股审批门槛；银行不能公开说自己要卖，行业靠名为「Acquire or Be Acquired」的年会和投资银行家牵线
- 合规要像工程测试一样从第一天写进代码、每天自动跑，而不是等审计时打补丁
- 防欺诈的起点是人工：每天 5000 笔交易之前，应该有人看每一笔

<script>
(function(){
  function fmt(s){
    if(!isFinite(s)||s<0) s=0;
    var m=Math.floor(s/60), x=Math.floor(s%60);
    return (m<10?'0':'')+m+':'+(x<10?'0':'')+x;
  }
  function wire(box){
    if(box.dataset.wired) return; box.dataset.wired='1';
    var a=box.querySelector('audio'), pb=box.querySelector('.pb'),
        bar=box.querySelector('.bar'), fill=box.querySelector('.bar > i'),
        tm=box.querySelector('.tm'), t2=box.querySelector('.t2');
    if(!a||!pb||!bar||!fill||!tm) return;
    var total=0;
    function paint(){
      var cur=a.currentTime||0;
      fill.style.width=(total?(cur/total*100):0)+'%';
      tm.textContent=fmt(cur)+(total?' / '+fmt(total):'');
    }
    a.addEventListener('loadedmetadata',function(){
      total=a.duration||0;
      if(total&&t2) t2.textContent=Math.round(total/60)+' 分钟 · AI 合成朗读';
      paint();
    });
    a.addEventListener('timeupdate',paint);
    a.addEventListener('play',function(){ pb.textContent='❚❚'; pb.setAttribute('aria-label','暂停'); });
    a.addEventListener('pause',function(){ pb.textContent='▶'; pb.setAttribute('aria-label','播放'); });
    a.addEventListener('ended',function(){ pb.textContent='▶'; });
    pb.addEventListener('click',function(){ if(a.paused) a.play(); else a.pause(); });
    function seek(ev){
      if(!total) return;
      if(ev.clientX==null) return;
      var r=bar.getBoundingClientRect();
      var x=Math.min(Math.max(ev.clientX-r.left,0),r.width);
      a.currentTime=(x/r.width)*total;
      paint();
    }
    bar.addEventListener('pointerdown',function(ev){
      seek(ev);
      function mv(e){ seek(e); }
      function up(){ document.removeEventListener('pointermove',mv); document.removeEventListener('pointerup',up); }
      document.addEventListener('pointermove',mv); document.addEventListener('pointerup',up);
    });
    a.addEventListener('error',function(){
      box.classList.add('pd-play-dead');
      box.textContent='本集中文精华音频还没生成好,稍后再来听。';
    });
  }
  function all(){ document.querySelectorAll('.pd-play').forEach(wire); }
  document.addEventListener('nav', all);
  if(document.readyState==='loading') document.addEventListener('DOMContentLoaded', all); else all();
})();
</script>
