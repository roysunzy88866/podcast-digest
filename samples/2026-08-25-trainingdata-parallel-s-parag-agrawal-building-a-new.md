# Parag：给智能体用的搜索，为什么不能是给人类用的

人类在 Google 搜东西，打两个错别字就等着结果出来——[[智能体|智能体]]不会这么干。它不偷懒、不打错字、查询描述更精确，而且一次深度研究任务可能发出几百上千次搜索请求。[[Parag|Parag]] 创立 [[Parallel|Parallel]] 的前提就是：智能体搜索的量级会是人类的一千倍，而为人类设计的搜索技术栈，根本扛不住这个规模 <button class="pd-ts" data-t="01:50" data-who="Parag" data-en="So just like humans forever have figured out how to use browsers and search engines and clicking and browsing on the web to access information, agents need to do the same things." aria-label="回原文"></button>。

## 先造搜索智能体，再养索引

传统搜[[索引|索引]]擎的架构是三步：[[爬取|爬取]]整个网络，把所有页面存进索引（一种预先整理好的信息库），用户查询进来后做检索和排名，从数千亿页面里筛出最相关的几个 <button class="pd-ts" data-t="04:10" data-who="Parag" data-en="Now, in order to do this, what is the search engine doing? The search engine is going and crawling the web, which is finding every URL that's out there. trying to read it trying to organize that information in what might be called an index so that by having all of this stuff in memory in one location you don't have to once the query comes in you don't have to spend time loading up pages because you already have them you've already done pre-processing to organize them and then when the query does come in" aria-label="回原文"></button>。这套东西极贵，历史上只有 Google 和 Bing 搞得起全量爬取 <button class="pd-ts" data-t="05:21" data-who="Parag" data-en="That sounds like an enormously expensive infrastructure challenge. And I think for the longest time, basically only Google and Bing had done full web scale crawls and indices." aria-label="回原文"></button>。

Parallel 没有第一天就砸钱建索引。他们先做的是[[搜索智能体|搜索智能体]]——查询来了之后，智能体实时去网上爬取页面。

深度研究场景下用户能等一分钟甚至十分钟，这段时间够爬大量页面了，前提是你有足够好的地图来决定优先爬哪些 <button class="pd-ts" data-t="08:01" data-who="Parag" data-en="We launched a search agent product first. Our search agent could go essentially crawl the web after a query arrived. So if you're doing deep research, you have patience to the extent of a minute." aria-label="回原文"></button>。本质上是用[[推理|推理]]时的算力去换预先建索引的成本 <button class="pd-ts" data-t="10:12" data-who="Andrew" data-en="I see. You're trading off the crawl for inference time compute effectively. Yeah." aria-label="回原文"></button>。

早期客户是保险承保、销售数据丰富、金融建模这些人——之前他们把数据收集外包给人工，现在用 Parallel 的搜索智能体替代。这同时解决了两个问题：有真实用例跑起来，而不是靠理论评估来猜智能体需要什么搜索；而且每次搜索都在帮 Parallel 积累数据，逐步把索引建起来 <button class="pd-ts" data-t="09:07" data-who="Parag" data-en="Well, there's some examples of what people built with your search agents. In the very early days, there were search agents being built with us for doing some kinds of insurance underwriting workflows and claims processing workflows." aria-label="回原文"></button>。

## 智能体搜索和人类搜索到底差在哪

接口层面就不同。人类搜索依赖关键词，智能体可以发给搜索引擎更丰富、更明确的查询指令，搜索引擎要猜的东西少了很多 <button class="pd-ts" data-t="15:21" data-who="Parag" data-en="The other interesting thing to observe is the interface actually changes when you think about serving agents versus humans. Humans rely on keyword search. With agents, we've had to innovate quite a lot on the what does an agent tell our search engine." aria-label="回原文"></button>。

内容质量层面也有根本差异。Google 搜索结果里大量充斥着"前 AI 时代的人类垃圾"——比如搜一家公司最新营收，最权威的来源是 SEC 备案文件里 PDF 的第 73 页，但那个 PDF 加载要三秒多，人类没耐心翻。

于是出现了大量"帮你把关键数字提取到首屏"的中间页面，99.99% 准确，SEO 极好 <button class="pd-ts" data-t="17:07" data-who="Parag" data-en="Let's work through a simple example. If you ask for a public company's most recent financials, like just the headline revenue number, we can sit here and know that there exists an authoritative filing with the SEC which has that number, perhaps on page 73 of a PDF." aria-label="回原文"></button>。这类内容对人类有用，对智能体完全是噪音。

Parallel 的做法是直接从最权威的来源提取段落，塞进智能体的上下文窗口。智能体不需要"看到页面"，它需要的是精准的一千个 token <button class="pd-ts" data-t="19:00" data-who="Parag" data-en="The good news is with agents, we're not making the agent click around and fumble around and grab a PDF, right? We're taking a excerpt from the most authoritative place on the web and trying to bring it to the agent's context window." aria-label="回原文"></button>。

一次查询的实际处理流程是：先用模型理解并丰富查询，然后并行发给多个不同类型的索引（大索引、新鲜索引、类似知识图谱的结构化索引等），每层做检索→排名→更细的排名，从数千亿 URL 缩到数万篇文档，再缩到具体段落，最后选出信号最强的约一千个 token 返回 <button class="pd-ts" data-t="19:45" data-who="Parag" data-en="Can you walk us through what actually happens when one of your developers sends a query off to your agentic search API? It's in some sense pretty standard. So we run some models to figure out what this query is and enrich it to figure out how it will flow into the rest of our system." aria-label="回原文"></button>。上周他们把延迟从三秒压到了 200 毫秒 <button class="pd-ts" data-t="12:13" data-who="Parag" data-en="Like I think if you go back to my framing around like this 100 billion to 100 billion matching problem, every query is essentially give me a thousand tokens from..." aria-label="回原文"></button>。

## 为什么模型公司不会直接吃掉这个赛道

有人认为模型公司做预训练时已经爬了整个网，搜索基础设施对他们来说是顺理成章的事。Parag 的反驳很直接：预训练爬取和搜索索引爬取是两套不同的需求 <button class="pd-ts" data-t="23:52" data-who="Parag" data-en="What do you think of that? I don't see empiric data on the ground to support that view. To build a fresh web index, I don't think that crawl is particularly useful." aria-label="回原文"></button>。

模型公司为预训练爬数据时，遇到加载慢的 JavaScript 渲染页面，算力回报率可能差两个数量级，直接跳过。但搜索索引必须是"完成主义者"——如果一个页面里有权威信息，哪怕加载慢也要拿到。而且如果模型已经训练过某个页面的内容，那个页面对新索引就没用了；Parallel 反而要去找那些模型没见过的、新鲜的、难爬的内容 <button class="pd-ts" data-t="24:18" data-who="Parag" data-en="We like to crawl things that people don't like to crawl for pre-training. Because like if the model already was trained on it, like it's not useful. Model companies for the training aren't patient enough to go in a completionist way, try to wait for really slow random JavaScript to load." aria-label="回原文"></button>。

他的判断是：买 LLM 做工作的客户，十个用例里有九个需要让模型访问网络。这是 LLM 推理的毗邻业务，模型公司可以自建、可以购买、可以合作——而 Parallel 已经和 Google Cloud 达成合作，作为其企业智能体 API 的搜索和 Grounding 提供商，在 GCP 上使用 Gemini 模型时，网络搜索选项可以是 Parallel Search <button class="pd-ts" data-t="25:56" data-who="Parag" data-en="we want to we will i can't share anything on that we did announce and i don't know how your definitions of model companies uh we announced today actually that we are working with uh google cloud to be a search and grounding provider for their enterprise agent apis so if you think of" aria-label="回原文"></button>。

## 搜索量的一千倍乘数效应

一个典型的搜索智能体，即使不做深度研究，回答一个问题也会发 5 到 20 次搜索。在 ChatGPT 里调高模式，一次提示词可能触发几百到几千次 <button class="pd-ts" data-t="28:14" data-who="Parag" data-en="Let's go back to for a moment on search agents, right? If you run a typical search agent, and even without doing deep research, it'll do somewhere between five to 20 searches, even if it answers within a few seconds, which is why not, right?" aria-label="回原文"></button>。

但更大的乘数来自[[后台智能体|后台智能体]]。比如一个信贷组合有 10,000 家小企业，之前每个月人工跑一次风险评估流程，现在用智能体每周跑，每次要发大量搜索来生成仪表盘和行动项——这里的搜索乘数是几十万甚至一百万 <button class="pd-ts" data-t="29:22" data-who="Parag" data-en="Now, a lot of our initial takes on the product and the market were to go after bigger multipliers than even that. So we were much more interested when you said, I have a portfolio of 10,000 small businesses where I have given out credit to." aria-label="回原文"></button>。Parag 自己用 Notion 搭了一个会议准备智能体，每次开会前自动做几十到几百次网络搜索 <button class="pd-ts" data-t="30:36" data-who="Parag" data-en="I was going to say James Flynn, but he's one of our great young guys. So I use Notion's agent and you can build custom agents which look into all the internal data that we have at Parallel plus all of the web data using Parallel's APIs to" aria-label="回原文"></button>。

他认为现在智能体查询总量还没超过人类，但像他自己这样的"异常值"已经在一百到一千倍的量级运作了 <button class="pd-ts" data-t="33:08" data-who="Parag" data-en="So we are very, very early. I think there are now people like me who are probably operating at the thousand X. I don't know." aria-label="回原文"></button>。

## 互联网经济学的崩塌与 Shapley 值

广告之所以能支撑免费互联网，核心是它极其擅长差异化定价——大多数查询 Google 是亏钱的，靠少数高价值查询赚回来 <button class="pd-ts" data-t="35:51" data-who="Parag" data-en="Right? So, most queries, Google loses money on. Some of them make it up and it's an extraordinary business with extraordinary margins." aria-label="回原文"></button>。但这个模型的根基是"有限的人类注意力"。如果上网的不再是人的眼睛而是智能体，广告模式就断了——内容方无法从智能体访问中变现，自然想把智能体挡在门外 <button class="pd-ts" data-t="36:29" data-who="Parag" data-en="Now, the core assumptions, as you noted, going into it around limited human attention to translate into outcomes. If humans don't show up and their agents show up on the web, like what does this mean?" aria-label="回原文"></button>。

现有的替代方案也很脆弱：高质量内容方只能和模型实验室签固定费用的训练数据协议，而且当推理量每年增长 7 倍时，合同金额不会跟着涨 7 倍，续约时份额必然下降 <button class="pd-ts" data-t="38:25" data-who="Parag" data-en="It's a very head phenomena. And even for the head, it is a broken business model because when AIs or inference grows, let's say 7x this year and another 7x the next year." aria-label="回原文"></button>。

Parallel 的方案是借鉴广告系统的差异化定价思路，用 [[Shapley 值|Shapley 值]]（一种博弈论概念，用于在合作中公平分配共同创造的价值）来计算每个内容来源的增量贡献 <button class="pd-ts" data-t="42:21" data-who="Parag" data-en="Now, the formalization of this kind of an intuition is the core framework we use. It's called Shapley values. Yes, let's go." aria-label="回原文"></button>。具体做法是：从语料库中移除某个来源，看智能体输出质量下降多少，再算要用多少额外算力才能弥补这个质量损失——那个算力成本就是该来源的"价值" <button class="pd-ts" data-t="41:16" data-who="Parag" data-en="Before we try to build a model, let's try to figure out if you were going to try to do this intellectually, theoretically, how would you go do it? So you have to ask the question of, OK, how much incremental value did somebody's content add?" aria-label="回原文"></button>。

精确计算 Shapley 值的成本比要付给出版商的钱还高，所以实际是用模拟数据训练模型来估算。但核心逻辑成立：如果银行家的智能体读取你的数据（高价值工作），就比退休老人的人工浏览付得多；内容越独特差异化，报酬越高 <button class="pd-ts" data-t="46:00" data-who="Parag" data-en="It takes a moment. but ultimately once once you pull out the properties right that you participate in the value if you have unique differentiated data you get paid more if a banker in an expensive job reads your data versus my retired dad reads your data" aria-label="回原文"></button>。按他的测算，如果从知识工作的 LLM 推理支出中拿出 2% 到 10% 分配给网络数据，总量已经远超目前除围墙花园之外的所有网络数据商业模式 <button class="pd-ts" data-t="46:31" data-who="Parag" data-en="And the macro math also seems to work. Like if you're going to spend a lot of money on inference on LLMs for knowledge work, if we allocated like what two to ten percent of it to data on the web that's way bigger than all web data business models today outside of like walled gardens like facebook and linkedin like so the macro math supports it" aria-label="回原文"></button>。

公司最初注册名就是 Shapley Inc.，后来因为 B2B 产品名字太学术才改成了 Parallel——寓意为智能体构建一个并行的网络 <button class="pd-ts" data-t="47:50" data-who="Parag" data-en="Why is the company called Parallel? The company's original name was Shapley Inc. Really? It was." aria-label="回原文"></button>。

## 从"拉"到"推"：网络的下一层

Parag 把智能体使用网络的演进分三层。第一层：智能体把网络当工具，像人一样调用搜索，这已经是现在大多数用例的样子 <button class="pd-ts" data-t="51:05" data-who="Parag" data-en="What's your role in it? three levels in this journey level one is people are building simple agents that use the web more as like a tool like a web search tool because it's familiar because the first set of agents we built to your point was just like model and give it the same tools because these models have been trained to use all the tools human have been humans have been used to and let them do work" aria-label="回原文"></button>。

第二层：多智能体系统，子智能体之间互相唤醒、编排，比如 AI 科学家类系统，长时间运行、投入大量算力去啃难题 <button class="pd-ts" data-t="51:35" data-who="Parag" data-en="By and large, if you think of like most work, it's there today, of our influence, it's there today. We have now started seeing some subset of customers who are in this world where they're building more sophisticated multi-agent systems which use sub-agents and have agents wake each other up or orchestrate in interesting ways." aria-label="回原文"></button>。第三层：网络从"拉"变成"推"——不是智能体去问"现在帮我找这个"，而是"网络上发生了这个变化，通知我，我来跑智能体处理" <button class="pd-ts" data-t="52:16" data-who="Parag" data-en="Some of those systems are very interesting, very sophisticated, very long-running, and just throw large amounts of compute and data at a really hard problem. And I think the third layer for the web specifically is the web goes from pull to push." aria-label="回原文"></button>。

> 【背景】Shapley 值由诺贝尔经济学奖得主 Lloyd Shapley 提出，在机器学习领域常以 SHAP 值的形式用于解释模型特征重要性。

## 本集带走

- **先做搜索智能体再建索引**：用推理时算力换预建索引的成本，从有真实付费需求的用例起步，边服务边积累索引数据。
- **智能体搜索的核心优化维度是质量、成本、延迟**：Parallel 前两年先忽略延迟，把质量和成本做到每个价格点的最优，第三年再攻延迟（从三秒压到 200 毫秒）。
- **预训练爬取 ≠ 搜索索引爬取**：前者跳过难加载的页面，后者必须拿到；前者要模型没见过的数据，后者要权威且新鲜的段落。两类需求天然不同。
- **用 Shapley 值估算内容增量价值**：移除某个来源→看质量下降多少→算弥补质量需要的算力成本→这就是该来源该得的报酬。精确算太贵，用模拟数据训练模型来逼近。
- **后台智能体是搜索量的真正倍增器**：不是人在用 AI 时多搜几次，而是程序化任务（每周跑 10,000 家企业的风险监控）把搜索量推到百万级。
- **网络将从"拉"走向"推"**：未来智能体不是主动去搜，而是订阅"网络上发生了什么变化"，变化触发工作。
