# Meta 新模型 Muse Wonder 实测:干活的能手，做设计的差生

<div class="pd-byl"><b>Claire Vo</b> · 产品负责人 · 2026-10-14</div>

[[Claire Vo|Claire Vo]] 是 How I AI 节目主持人、产品负责人，也是 AI 工具的重度用户。

这期她把 [[Meta|Meta]] 刚发布的前沿模型 [[Muse Wonder|Muse Wonder]](分 Wonder 和 Wonderful 两版)丢进自己的测试集里跑了一遍，涵盖写产品文档、做原型、写代码、跑[[智能体|智能体]]任务和创意工作。

她的结论很干脆：该用在哪、不该用在哪，一听就明白。

## Meta 想让这个模型干什么？

Muse Wonder 是 Meta 的新前沿模型家族，官方把它和 Fable、GPT-6 Astra、[[Claude Opus 5.5|Claude Opus 5.5]] 放在同一梯队 <button class="pd-ts" data-t="00:41" data-who="Claire Vo" data-en="DX found that spend on AI tools has grown 28x over the last year. The share of AI authored code is climbing, but overall innovation has remained flat. As teams generate code faster," aria-label="回原文"></button>。

Meta 主打的不是写代码，而是「个人和专业场景的智能体工作」——这和他们的个人 AI 助手 Muse 的方向一致。

Meta 特别强调三个能力。一是领域专业知识，比如法律分析、金融这些知识工作；

二是[[主动记忆|主动记忆]],能把关于你的重要信息跨对话带下去，这对个人助手很关键；

三是[[主动专注|主动专注]],即模型会为有挑战的目标反复尝试不同做法。

剧透一下：这个能力在她的长任务测试里确实赢过了其他模型 <button class="pd-ts" data-t="04:18" data-who="Claire Vo" data-en="We did see active focus. Actually come into play and outperform on some of our long running tasks in the benchmark. So our bench is showing that this active focus investment" aria-label="回原文"></button>。

## 测评怎么做的？

她的测试集有近 20 个任务：写产品需求文档(PRD)、做原型、重新设计 ChatPRD 网站、长时间操控电脑、智能体研究、代码修复，还有创意任务 <button class="pd-ts" data-t="06:16" data-who="Claire Vo" data-en="And just a reminder on how AI Bench works, we run against almost 20 different tasks. That's everything from writing a PRD, to doing a set of prototypes," aria-label="回原文"></button>。

先让一个大模型当评委打分，她自己再用语音笔记补充评判，最后汇总成报告。

不过这次只是第一眼快评，不是完整基准测试——她刚跑完 Opus 5.5 等模型，不想整套再来一遍，==只想回答一个问题：Muse 到底行不行==。

## 最烦人的一步：先装 Muse Code

要上手这个模型，她不得不订阅 Muse 服务、拿到 Meta 的模型接口，还下载了 [[Muse Code|Muse Code]] 工具 <button class="pd-ts" data-t="04:53" data-who="Claire Vo" data-en="but this did force me to subscribe to the Muse subscription, get access to the meta model APIs and download Muse code, which I will say in my very light experience was deeply unimpressive," aria-label="回原文"></button>。

她坦言自己已经好几个月没打开过终端应用，而 Muse Code 本身给她的印象很一般。她实际的做法是给 Claude Code 接上 Muse Code 去跑，自己没怎么碰它。

## 干活是真行：智能体任务全场最佳

四个智能体任务——账单工单处理、客户回复、收件箱分诊、长线研究——它全是她的心头好，另外声音助手的角色也很讨喜 <button class="pd-ts" data-t="08:01" data-who="Claire Vo" data-en="So here are the results. It is the best at agentic work. So I tested four tasks." aria-label="回原文"></button>。

最出彩的是账单工单任务。

这个测试故意埋了坑：工单挂错了账户、退款金额奇怪、还有一笔重复扣款，说明文字里甚至藏了一个提示注入攻击。

Muse Wonder 一层层排查：找到正确客户、因为重复扣款退了正确的金额、改了套餐、回复并标记解决。**它是所有模型里做得最好的**<button class="pd-ts" data-t="12:37" data-who="Claire Vo" data-en="It made the plan change and then it replied and marked solve. The best of all of them. It worked through that in a clear way." aria-label="回原文"></button>。

写邮件她也放心交给它，给打了满分五分——毕竟她的邮件本来就只有两句话。

声音助手测试里，它接近平常霸榜的 Sonnet,语气像个正常人，不腻不烦。

## 代码：后端能打，前端拉胯

后端功能实现它排第一，和头部模型在同一档，做后端编程和架构审查完全够用 <button class="pd-ts" data-t="09:05" data-who="Claire Vo" data-en="the bottom, but like it's in the ballpark. So it's totally a viable option for backend coding and architecture review. So no complaints on agents or coding." aria-label="回原文"></button>。

但前端就是灾难现场。她测了一个日程应用，点进去发现很多交互根本没反应；

一个事故管理平台，她明确要求深色模式，它偏偏做成浅色还加了个糟糕的遮罩层 <button class="pd-ts" data-t="16:07" data-who="Claire Vo" data-en="That was even worse in this incident management platform where I told it specifically to be dark mode because it was a dev tool and all developers need dark mode." aria-label="回原文"></button>。

她总结：**这个模型给出的前端代码，错误比其他模型很长一段时间里见过的都多**。

设计品味也很成问题。

她用了个词叫slop,意思是千篇一律的模板味儿——Muse 出品清一色是粗衬线字体加圆角组件的软件即服务风格。

最惨的是重设计 ChatPRD 网站：原本刚被 Opus 5.5 刷新过的漂亮网站，被它做得图片都是坏的，连拿到手的品牌设计规范都没遵守 <button class="pd-ts" data-t="17:36" data-who="Claire Vo" data-en="We love the Chat Purdy website and Muse obliterated it. Like it is so ugly. The images are broken." aria-label="回原文"></button>。

## PRD 和创意：能用，但别指望

PRD 写得短、也照了模板，这两点她喜欢；但格式乱、细节少，不如其他模型。创意任务里，SVG 插图画得挺可爱，但八个模型里排第七；

短视频剪辑找对了 40 秒素材、卡点几乎全对，可字幕盖在脸上、叠加装饰很丑，音频还出了怪问题，总分 2/5 <button class="pd-ts" data-t="21:05" data-who="Claire Vo" data-en="So I have to double down there and figure out what's going on. So I gave this a two out of five. It found the right 40 seconds." aria-label="回原文"></button>。

## 到底该不该用？

一句话结论：**智能体工作很强，代码和后端够用**，写邮件、当语音助手都靠谱；

设计品味差一大截，她不会拿它做前端或创意工作，继续用 Opus 5.5 干这些 <button class="pd-ts" data-t="22:28" data-who="Claire Vo" data-en="And I think it has a nice voice. It definitely just falls short on design sensibility, which is so much of my work. So much of my work is creative front end design." aria-label="回原文"></button>。

速度上也有个有趣的分裂：小任务快得飞起，智能体大任务却跑很久——可能正是那个主动专注模式在花时间磨。

她接下来打算把 Muse Wonder 塞进自己在搭的几个智能体里，实际跑跑看。

## 本集带走

- Muse Wonder 主打个人和专业智能体场景，主动记忆和长任务的持续专注是它的差异化卖点。
- 智能体任务表现全场最佳：账单排查、收件箱分诊、语音助手都接近或超过头部模型。
- 后端代码够用，但前端代码错误多、设计审美停留在模板风格，重设计网站直接翻车。
- 想上手得订阅 Muse 并下载 Muse Code,上手体验一般。
- 她的选择：干活交给 Muse Wonder,设计和创意继续用 Opus 5.5。
