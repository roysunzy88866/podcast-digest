日程安排工具 [[Cal.com|Cal.com]] 的联合创始人 Pierre Richelson 这次上 Changelog 播客，带来的不是产品宣传，而是一个令人不安的判断：**「现在大多数[[开源|开源]]仓库都已经被攻破了，只是我们还不知道而已。」**<button class="pd-ts" data-t="27:00" data-who="Pierre" data-en="So the whole pendulum of like, oh, we're open source, we're more secure, has completely swung in the other direction where it's like, wow, this is so easy to hack any open source repository." aria-label="回原文"></button> 作为一个做了五年开源、在行业里干了十五年的人，他连自己公司都在做的「开源更安全」这个信条，也不再相信了。

## 开源维护者的噩梦：AI 垃圾 PR 淹没仓库

AI 拉平知识图谱之后，最先崩塌的是开源协作本身。以前收到一个 pull request(社区向项目提交代码改动的请求)，一眼就能看出是深思熟虑还是垃圾，该合并合并、该关掉关掉。

如今每个 PR 都长得差不多——都是 Claude、Claude Code 或 Codex 写的。「以前你有一千个开源贡献者，就有一千种观点；现在你只有一千个人在用两个不同的编程助手。」<button class="pd-ts" data-t="10:48" data-who="Pierre" data-en="Like you get a pull request and it's always written by Claude, by Claude Code or by maybe Codex or maybe if you're lucky by some other coding assistant, right? But it's like back in the days you had a thousand open source contributors and you would have a thousand opinions, right?" aria-label="回原文"></button> 更糟的是 AI 生成的 PR 置信度看起来极高，层层剥开才发现连测试都是幻觉、代码里全是硬编码。

后果是真实的：Cal.com 的 PR 收件箱里躺着 356 个开放 pull request。「我们根本不可能把这个彻底处理完。

」<button class="pd-ts" data-t="18:08" data-who="Pierre" data-en="No, there's no chance. There's, there's no chance we're going to get to the bottom of this. It's just" aria-label="回原文"></button> 业内已经有人开始关停外部 PR、建背书系统——System Initiative 的 swamp.club 就走了「开源但不接受贡献」的路线，只收 issue 和文字描述的想法，不收代码。还有人把开源贡献当求职敲门砖：编排 12 个[[智能体|智能体]]扫最热门的仓库、自动找 issue 提 PR,Pierre 说这就像「向几百家公司群发简历，顺便说一句这也是个非常糟糕的策略」。<button class="pd-ts" data-t="20:22" data-who="Pierre" data-en="Basically, the Claude instruction is find the most uploaded issue and then submit a PR in these five different... It's almost like you're spamming your CV, which is also a really terrible strategy, by the way, into like hundreds of companies and trying to hope one of them sticks." aria-label="回原文"></button>

## 「报告文化」之死：从更安全到更脆弱

开源更安全的老逻辑是：全世界懂行的安全研究员帮你找[[漏洞|漏洞]]、报漏洞、拿赏金。「曾经有一种报告文化。

这种报告文化已经不存在了。」<button class="pd-ts" data-t="24:01" data-who="Pierre" data-en="The holes, fixing vulnerabilities, reporting vulnerabilities. There was a reporting culture. The reporting culture no longer exists." aria-label="回原文"></button> 现在 Cal.com 的安全收件箱里 99% 的漏洞报告是 AI 生成的，其中一半是幻觉——去复现根本不存在，或者用错了 API 端点。而维护者还得人工区分好坏，工作量已经大到「人力上不可能」。

与此同时，攻击成本暴跌。自主攻击工具已经强到「攻击一个仓库所需的知识量，基本上就是：你能在终端里运行一条 shell 命令吗」。<button class="pd-ts" data-t="24:56" data-who="Pierre" data-en="And then at the same time, the autonomous attacking tools have gotten so good that the amount of knowledge needed to attack a repository is basically can you run a shell command in your terminal, right?" aria-label="回原文"></button> 

以前渗透测试要海量工具、逆向工程、中间人攻击；现在一条提示词就行。Firefox 有约 12 个由 AI 报告的 P0 漏洞,React、Next.js 也都有 AI 找到的漏洞。

安全研究员告诉 Pierre:**开源仓库被黑的可能性比闭源高 5 到 10 倍**——因为闭源是黑盒攻击，要靠猜；开源直接能看到后端和函数调用。而且黑帽黑客往往比白帽更快，因为「他们有即时的敲诈动机」。<button class="pd-ts" data-t="34:52" data-who="Pierre" data-en="The black hat hackers usually fast because they have an incentive. They have an immediate extortion incentive to hack and blackmail. That's a big problem, right?" aria-label="回原文"></button>

最阴险的一招：黑客会对你的 PR 跑代码扫描，一旦检测到某个 PR 是在修复漏洞，「在那一秒钟里，我会利用那个漏洞给他们发一封勒索信」。<button class="pd-ts" data-t="53:38" data-who="Pierre" data-en="You would scan the PR, you would identify this PR is fixing the vulnerability. And in that second, I would abuse that vulnerability and send them an extortion letter, right?" aria-label="回原文"></button> 所以他的建议是：修复漏洞要在私有状态下做，合并时压成一个 commit,「不要给他们一条通往改动的路径」。

> 【背景】文中提及的 LightLLM、NPM 供应链攻击等事件，是嘉宾在节目中举的近期真实案例：LightLLM 被供应链攻击攻破，攻击者通过社会工程拿到密钥、利用受信任的发布流水线注入恶意代码。

## Cal.com 的答案：内部 fork,商业版转私有

从 4 月 15 日起，Cal.com 把运行在 app.cal.com 上的商业版转为私有——[[GitHub|GitHub]] 上看到的代码从此不再是生产环境跑的代码。社区版保留、完全开源，改名 cal.diy,自担风险地自托管。

做法是在内部 fork 现有代码，重写所有涉及认证、数据库调用、中间层的敏感部分；前端组件之类不敏感的照旧开源。「我们对开源有承诺，但我们也对每一位客户有承诺。」<button class="pd-ts" data-t="32:19" data-who="Pierre" data-en="But the same code base that runs on app.cal.com will no longer be publicly accessible because it's just, it's too risky for us. Like we have, we have a commitment to open source, but we also have a commitment to every single of our customers." aria-label="回原文"></button>

他特意强调这不是商业决策：Cal.com 每月环比增长 7%-12%,不缺钱，「资金方名单上有最支持开源的投资人，我们不得不说服他们这是一个正确的决定」。<button class="pd-ts" data-t="45:33" data-who="Pierre" data-en="We have no investors who are bullying us to go private source. We have the most open source friendly investors on our cap table. We had to convince them this is the right decision." aria-label="回原文"></button> 「这对[[商业开源|商业开源]]来说就像一个核级别的问题。」——他希望这只是自己一家的事，但它影响整个行业。

为什么不完全闭源？他的答案是「靠分散性实现安全」：自托管理发店版 Cal 的邻居不会成为目标——黑客先得找到那台服务器，还得知道目标是谁，「黑你邻居的理发店在商业上是完全不划算的」。<button class="pd-ts" data-t="43:35" data-who="Pierre" data-en="Like when you're self-hosting, you're not going to be the target unless it's like a very easy to attack multiple nodes in a way. Like if every node runs the same software, then you do like this mass attack, but it's just not commercially viable for hackers to hack your neighbor's barbershop." aria-label="回原文"></button> 而且，拥有私有代码并不能保证不被黑——只是把被黑概率从 5-10 倍降回去而已。

他的「药方」：①别慌，小项目大概率不是目标；②跑一遍 AI 扫描工具看看爆炸半径——他聊过的每个项目，AI 工具的报告量都涨了约十倍；③至少暂时转私有修完漏洞，再 squash 成一个 commit 合并回去。

## 谁该紧张：日志 SDK、CMS、支付

不是所有开源都危险。框架和纯工具库没事；危险的是「任何最终会发起数据库调用的开源项目」。<button class="pd-ts" data-t="31:24" data-who="Pierre" data-en="Let's call it this way. Any open source project that's eventually makes a database call, you are in trouble. And I'm saying this after five years of being open source and 15 years in the industry, you should probably take your project private and rewrite everything that touches off database and encryption." aria-label="回原文"></button> 

受冲击最重的是几类：记录用户行为的日志类 SDK——它们必须开源才能当开发者包用，但被 AI 黑掉后攻击者能拿到你所有用户的事件数据；开源 CMS——想象有人拿到某 CMS 的写权限，就能往 nike.com 上发内容；还有自称「开源版 Stripe」的支付服务商，以及各类加密项目。「外面就是个狂野西部。」<button class="pd-ts" data-t="49:06" data-who="Pierre" data-en="I don't even want to talk about crypto because I really don't like crypto, but all of these crypto projects are being cracked open at open source. It's a wild west out there." aria-label="回原文"></button>

## 连 GitHub 都要重新想自己是谁

顺着这个逻辑，Pierre 认为如果源代码变得没人读——维护者看过自己代码库的部分，可能还没社区加起来多——「GitHub 除了作为分享 zip 文件的 CDN 还有什么意义」。<button class="pd-ts" data-t="58:53" data-who="Pierre" data-en="So if source code, as sad as it sounds, listen, I'm not a fan of this, but if source code becomes unreadable, because nobody knows what the fuck it's doing anyway," aria-label="回原文"></button> 现在维护者用第三方 GitHub Actions 自动关闭未验证者的 PR,「为什么我必须装第三方插件来确保只有合法的人在开 pull request?

那应该是你的工作,GitHub」。<button class="pd-ts" data-t="60:03" data-who="Pierre" data-en="That's all just hacks, you know, that should be first party coming from GitHub. Why do I have to install different third party plugins to make sure only legitimate people are opening pull requests?" aria-label="回原文"></button> 节目里还聊到 Mitchell Hashimoto 那条著名的 X 帖子：如果由他执掌 GitHub,会砍掉一半产品线、关掉 [[Copilot|Copilot]]、收购 Cursor——而 GitHub 曾经是 AI 编程的领跑者，如今却是落后者。

## 「1 美元的 AI 额度卖 10 美分」的生意经

话题最后落到 AI 初创公司的商业模式。Pierre 的毒舌总结：「每个生意都很棒，如果你的商业模式是把价值 1 美元的 AI 额度卖 10 美分。

」<button class="pd-ts" data-t="78:28" data-who="Pierre" data-en="So it's like, I mean, look, every business is great if you're selling like, A dollar worth of AI credits for 10 cents. Every business is fantastic if that's your business model." aria-label="回原文"></button> 一个思想实验：做个落地页卖半价的 Claude API key(你出一半)，发到 Hacker News,第一年就能做到 1 亿美元收入、烧掉 2 亿美元——「然后你可以上各种播客说我们第一年赚了 1 亿美元，不提烧掉的 2 亿」。<button class="pd-ts" data-t="80:34" data-who="Pierre" data-en="So you're going to have, you post this on Hacker News and you're going to make like $100 million in the first year, and you're going to burn $200 million, because that's the amount, you pay 50% of it, but you've got to be a startup making $100 million in the first year, and you can go to every podcast and say, this is how we made $100 million in the first year, without saying you burned $200 million." aria-label="回原文"></button> 所有编程助手都在加限速、砍用量、推 200 美元套餐，因为「AI 领域的经济账不合理，至少现在不合理」。<button class="pd-ts" data-t="78:50" data-who="Pierre" data-en="All of these coding assistants are adding rate limits and reducing usage and trying to upgrade you into $200 plans. The economics don't make sense in the AI space." aria-label="回原文"></button> 

反例是 [[AMP Code|AMP Code]](明确说不低价卖、定价恰当还盈利)和 MidJourney(自研模型、从未融资、一直盈利)——你自己是供应商时，不用买别人的 token,利润率才成立。Cal.com 自己则没有任何走红的 AI 产品，也就不烧 token,「利润率很棒，依然很棒」。

## 本集带走

- **「开源更安全」的钟摆已经摆向反面**：安全研究员的说法是开源仓库被黑难度比闭源低 5-10 倍；以前靠人肉审计 8-20 小时才能找到的漏洞，现在一条提示词就能扫出来。
- **修复漏洞要悄悄做**：黑客会扫描你的 PR、识别哪个是漏洞修复，然后在修复生效前利用漏洞勒索你——所以要在私有状态修，合并时 squash 成一个 commit,不给攻击者留路径。
- **商业开源的生存姿势**：生产环境跑的代码不该和公开仓库是同一套；敏感的认证/数据库/中间层转私有，不敏感的组件保持开源；社区版靠「分散即安全」——没人会为了勒索去黑自托管的理发店。
- **判断你的开源项目危不危险，看它碰不碰数据库**：框架、UI 库没事；日志 SDK、CMS、支付、任何存客户数据的项目都是高价值靶子。
- **识别 AI 时代的补贴生意**：卖 1 美元 AI 额度只收 10 美分、宣称「我们替你承担费用」的公司，本质是在用融资烧钱换增长；不补贴 token、自己控成本的公司(AMP、MidJourney)才是可持续的活法。

      if(!total) return;
      if(ev.clientX==null) return;
      var r=bar.getBoundingClientRect();
      var x=Math.min(Math.max(ev.clientX-r.left,0),r.width);
      a.currentTime=(x/r.width)*total;
      paint();
    }
    bar.addEventListener('pointerdown',function(ev){
      seek(ev);
      function mv(e){ seek(e); }
      function up(){ document.removeEventListener('pointermove',mv); document.removeEventListener('pointerup',up); }

    });
