===标题===
软件工厂翻车实录:为什么 HumanLayer 的 CEO 改口说「必须读代码」
===导语===
HumanLayer 联合创始人兼 CEO Dex Horthy 复盘「关灯开发」实验的失败，聊聊软件工厂、品味编码化与审查的价值
===正文===
让 AI 全自动写代码、人类只看规格说明不看代码——这套「软件工厂」打法，HumanLayer 亲身跑了四五个月，最后发现代码库已经没法用了，只好从零重建整个产品。说这话的人是 Dex Horthy,HumanLayer 的 CEO 兼联合创始人，也是那套流传很广的「12 factor 智能体」原则的作者。这一集，他公开承认自己被现实从原先的立场上「撬了出来」。

## 实验是怎么翻车的

转折点始于 Opus 4 和 Claude Agent SDK 发布——那是你第一次能把 Claude 当作一个小型智能体循环，嵌进更大、更具确定性的软件里。当时整个圈子流行「规格说明是新的代码」的说法，实验室的人说这样做有效，Dex 的态度是：想活在未来，就得照实验室说的试。于是他们保留 pull request,但宣称「读了计划就不用读代码」。

问题立刻暴露：**计划里包含了所有将要写出的代码**——那简直就是一份内联 diff,读计划和读代码工作量差不多。实现还会漂移，导致被推荐这么做的 50 人团队得把几乎同样形状的代码审查两遍，做了更多而非更少的工作。更糟的是放任模型自己定架构：最后长出一个约六个服务的系统——桌面应用经 Rust 连 socket,后端是 Golang 守护进程，再启动 Claude Code 会话，会话再启动 MCP 服务器处理审批，回调写 SQLite 再回到 UI,复杂到没人能维护。四五个月后他们承认：这个代码库不可用了，每处改动都在别处引发回归。重建的头两周，联合创始人 Kyle 在 VS Code 里连 Cursor 都不用，一个字符一个字符手敲新版本的数据架构。

## 计划的本质是杠杆，不是仪式

翻车不等于回到不计划，Dex 现在的框架是「预期痛苦」：你之后要改动某样东西的概率有多大、改起来多痛？按钮颜色不对，一个 prompt 就能修，不值得对齐；数据库 schema 错了，可能得整个扔掉重来，必须先对齐。从「两句 prompt YOLO 一把(约 50% 概率返工)」到「手写五小时详细规格(约 10%)」再到「全部手写(智能体原因返工为零)」，规划就是在为每个任务找这条曲线上的甜点位，每切掉约 50% 的潜在坏结果就是一个好阶段。做错了没关系，要多练。

另一个核心概念是**反压(back pressure)**:给模型一个它能自己衡量的目标去爬山(定性或定量都行)，让它无需人类介入就能拿到关于自己做得多好的反馈——这是让模型长时间无人值守、并行多开的关键。而意图本身不必你干想六小时：最快的方式是打开语音模式随口絮叨 60 秒，让 AI 像面试官一样不知疲倦地追问你「你确定不想要这些备选方案吗？」——Matt Pocock 的 grill me 技能能登上 GitHub 星标前列，就是因为人们太不擅长说明自己的意图。

## 「可维护性没有快速神谕」

为什么不能全交给模型？Dex 给了一个很硬的解释：要在某件事上训练模型，需要 RL 环境(用强化学习让模型从反馈中改进的训练方式)，而 RL 环境需要一个 Oracle——一个能立刻判断结果好坏的验证器。可维护性恰恰没有快速 Oracle:一个东西不可维护，你要两个月后才知道。每个他认识的顶尖构建者都说，新模型在计算机使用、游戏、Blender 上进步飞快，但在写可维护代码上并没有快多少。

有数据佐证：一个叫 slop code bench 的基准(威斯康星大学团队做的，Dex 只是帮忙跑测)让模型在同一个代码库上连续继承、连续加功能。GPT-5.5 在五月拿了 14.8%,Astra 首轮约 16.3%——方向在变好，但远没到大家以为的程度。他还点名了 Steve Yege:一边到处宣扬「还在读代码的人不会成功」，一边上周自己承认用 Fable 构建的系统复杂到 Fable 自己都调试不了。

## 软件工厂和真工厂的根本区别

主持人(Tesla 方，工程团队约 20 人)提出的替代路径是：把品味和策略固化成上下文/技能，跑维护智能体去审查实现智能体的产出，人只对系统做反馈。Dex 部分认同——HumanLayer 内部就有每晚跑在 crons 和 GitHub actions 上的五个工作流(同一个 harness 换不同提示词)，每天早上醒来收到五个让代码库在某个维度变好一点点的 PR。

但他强调一个关键区别：传统工厂产出一辆坏车，损失的是那一辆；**软件工厂产出坏代码，会降低未来每一件经过工厂的工作的质量**——因为智能体会合理地模仿代码库里已有的模式。所以优先级是先「关上窗户再开空调」：不能让垃圾代码进门。而这件事的「废气」恰恰是工厂改进的养料——每当人类不得不在智能体 PR 上留言说「我们不这么做」，把它虹吸出来，分析团队所有人的会话轨迹，找出大家在哪儿沮丧、在哪儿纠正模型，反哺到技能和审查流程里。做好了这个复利，你就从关心位置转向关心速度：从造车转向造工厂。

至于品味能不能交给系统，主持人有个锐利的观点：品味不过是「你懒得写下来的偏好」，让智能体足够频繁地看到它就能捕捉。Dex 也不觉得品味是难以捉摸的人机差异——真正的护城河是比任何人都更理解问题、更理解客户。有些品味确实极难固化，比如他第一份工作在 Sprout Social 学的「三份拷贝，用力按」(endpoint 顶部三行代码，别抽象成函数，就重复它——像修车店的三联单)，这种工程师二十年攒下的判断，还没人知道怎么放进模型。

## 永远要有东西值得你审查

旧金山一场晚宴上的举手调查：AI 写 100% 代码的，全员举手；还在读代码的，约一半。那么还要多久就不用审查任何东西了？在场一位老手的话 Dex 几乎每天都想：**审查某样东西，大概永远都有超额收益(alpha)**——虽然不知道是什么、两年内也会变。因为如果你什么都不审，只是让 AI 去煮，你就会得到和其他所有人一模一样的产品、邮件和公司，沦为没有差异化的「token 农场」。Claude 做的演示文稿就是现成例子：惊艳了半年，现在每份都长一个样。

展望未来，两人押的方向出奇一致：软件开发将围绕技能(skills)展开，代码的角色会像今天的汇编或垃圾回收一样被下沉——主持人提到的 shadow spec(对 LLM 决策的捕捉)和代码的界限，就只是自由度的差异。Dex 补充了一个基础设施判断：软件工厂技术栈会像当年的 Kubernetes 一样分解成开放接口和开放组件，围墙花园(全栈锁在单一厂商上)很诱人，但 DevTools 的历史是越来越开放，「开放的阵营正在以比任何人准备注意到的更快的速度追赶」。

## 本集带走

- **别赌「不读代码」**:HumanLayer 跑了四五个月「只审计划」就废掉了代码库；可维护性没有快速反馈信号，模型在这个维度上的进步远慢于宣传。
- **计划按「预期痛苦」分配**:按钮颜色不值得对齐，数据库 schema 必须先对齐;每个规划阶段的价值就是切掉约 50% 的坏结果，甜点位要多练才有直觉。
- **给模型装「反压」**:让模型能自己衡量做得好不好(测试、验证器)，它才能长时间无人值守、并行多开。
- **坏代码是会传染的**:软件工厂和真工厂不同，一次放行的坏模式会被后续所有智能体模仿;先堵住质量入口，再谈工厂改进。
- **把每次人工纠错虹吸出来**:人类在智能体 PR 上的每条「我们不这么做」、每个会话轨迹里的沮丧点，都是喂给工厂的复利养料。
- **永远审点什么**:审查的对象会变(现在还是代码，将来可能是别的)，但放弃一切审查，你就只能得到和所有人一样的产出。
