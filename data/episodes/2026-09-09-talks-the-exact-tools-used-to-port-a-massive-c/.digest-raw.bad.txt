===标题===
一个周末把几十万行代码从 Python 移植到 TypeScript
===导语===
一位工程师分享他如何用 Claude Code 在一个周末完成传统上没人敢做的整套代码库移植，以及「不讲道理一点」的提示词心态。
===正文===
这一集是一段很短的分享，主题只有一个：在大语言模型的辅助下，过去工程常识里「绝对不该做」的事情，现在可以做了。

开场引用了别人给的一条建议——「要不讲道理一点」(be unreasonable),说话人由此反思：自己在给 AI 写提示词时，是不是足够雄心勃勃？[00:01]

他举的例子是部署。他注意到 Claude Code(Anthropic 的编程智能体工具)用 Bun(一个 JavaScript/TypeScript 运行时)找到了一套更好的部署方案，于是决定把自己手上一整个项目从 Python 移植到 TypeScript。[00:07]

他坦言，如果按 2010 年代、甚至 2020 年代初的工程常识来判断，这是个愚蠢的想法——谁会在项目已经有几十万行代码的时候，把整个代码库换一种语言重写？[00:16] 但他的判断是：「我觉得现在这是可行的」——于是动手了。

具体做法是：他搭建了一套动态工作流，然后在周末连续运转——让 AI 移植、验证、反复检查、对照阅读两边语言的代码，不停迭代。到了周一，一个完成移植、可以部署的版本就绪了。[00:26]

他自己也把这件事归为「比较不讲道理的事情之一」：把整个 Python 代码库移植到 TypeScript、让它跑起来、可部署，全部压缩在一个周末之内。[00:41]

这一集虽然短，但给出的核心判断很清晰：以前「换语言重写整个代码库」是工程师不会考虑的禁区，不是因为技术上不可能，而是因为人力成本太高；当 AI 智能体能承担验证、对照、迭代这些工作时，成本结构变了，禁区也就不成立了——前提是你敢在提示词里提出这种「不讲道理」的要求。

## 本集带走
- **敢提「不讲道理」的要求**：向 AI 下任务时，别被旧工程常识限制住想象——哪些事过去不做是因为人力成本，而不是技术不可能。
- **大规模移植现在可行**：几十万行代码从 Python 移植到 TypeScript 并跑通、可部署，可以在一个周末完成——靠的是动态工作流加持续迭代，而不是一次性指令。
- **让 AI 承担验证环节**：移植过程中关键是让智能体自己验证、反复检查、对照阅读两种语言的代码，人来验收结果。
- **保持对工具方案的敏感**：看到 Claude Code 用 Bun 做出了更好的部署方案，就果断决定把整个项目迁到能享受这个优势的技术栈上。
