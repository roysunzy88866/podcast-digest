## 两条协议,串起从 UI 到推理的整条链路

当你在界面上发出一条消息,中间其实有两段协议:**应用服务器协议**负责 UI 和 harness(驱动智能体运行的"挽具")之间的通信;**responses API** 负责 harness 和模型推理之间的通信 [02:07]。responses API 是去年对传统聊天完成 API 的重新设计,专门针对智能体场景加了网络搜索、图像生成等内置能力,而且它是开放的——你可以把任何兼容 responses API 的模型提供商接入 Codex harness [03:58]。应用服务器协议同样开放,Codex 应用本身、不少第三方社区项目,甚至把 Codex 塞进 Claude Code 的插件,用的都是同一套 [02:56]。

## 上下文构建:既要小、又要全、还要省

这是 harness 接管后最重要的一步。上下文越大,不仅 token 花费越多,还越容易出现互相矛盾的信息让模型困惑 [04:37]。但装少了又不够用——你装了一堆插件和工具,描述自然就越攒越长。Codex 的解法是两手抓:

- **延迟工具(deferred tools)**:从 GPT 5.4 起,responses API 允许把工具标记为"延迟加载",它们不会直接塞进上下文窗口,而是等智能体用"工具搜索"去按需发现 [06:07]。你既可以用内置的工具搜索工具,也可以自己实现一个发现机制。
- **可用技能列表封顶 2%**:把所有可用技能的描述上限设为最大上下文窗口的 2%;一旦超长,就逐步削减每条描述的详细程度 [06:28]。

## 让智能体真正动起来:异步、计算机使用、文件系统

**异步动作**(async actions)的典型场景是"子智能体"。harness 给智能体一个"孵化智能体"工具,它能造出新的智能体实例,把任务委派出去,自己继续干活;之后可以通过"发送输入"工具往子智能体塞新内容、等它跑完、或者把它关掉 [07:29]。后台终端也是同一套机制——启动一个终端,持续通过标准输入喂数据或等它跑完 [07:53]。

**计算机使用**(computer use)的实现经历了一次进化。最早在 responses API 里引入时,它一次只能做一个动作,而且得你提前声明、手动实现动作类型 [08:19]。后来改用**代码执行**来实现:让智能体用 JavaScript 或 Python 自己写脚本,去驱动你提供的任何计算机环境 [08:58]。Codex 的浏览器功能就是这么做的——它启动一个持久化的 Node REPL(一种交互式运行环境),在其中写 Playwright 代码来操作一个 Chromium 浏览器实例 [09:08]。智能体可以先看一页摸清结构,再写脚本对后续页面批量抓取,速度显著提升 [09:53]。

**文件系统交互**上,从 GPT-5 起的模型都专门训练过一个叫"应用补丁"的工具,用给差异(diffs)的方式改文件、建文件 [10:15]。其他文件操作则走 shell 工具,模型会自然而然地用 ripgrep 做文件搜索(这是训练时养成的习惯),harness 也顺手把 ripgrep 打包进去了 [10:42]。在 Windows 上,模型则被训练为原生使用 PowerShell [10:56]。

## 沙箱与自动审查:治好"审批疲劳"

所有文件系统交互都要过沙箱层。Codex 在 Mac OS 上用 Seatbelt,在 Linux 上用 Bubblewrap [11:18]。Windows 上比较特殊,团队自己造了一个开源的 Windows 沙箱,放在同一个 GitHub 仓库里(细节可以看 David 写的深入文章)[11:25]。

但沙箱有个老大难:**审批疲劳**。长任务跑起来,动不动就要你点同意;很多人干脆开"完全访问"模式——可 IT 和安全部门恨透了这个,而且风险实打实:你让模型发封邮件、它发现附件挂不上,可能自作主张把文件传到公共网盘;或者转义搞错、数据删多了,这种事哪怕模型再强也可能发生 [12:51]。Codex 的对策是 Autoreview(自动审查)。当主智能体想在沙箱里做需要升级权限的操作时,harness 会启动一个**完全独立的子智能体**来审 [13:34]。这个审查智能体不能再生子智能体、只有只读权限,但手里拿着用户授权范围、风险分类法、完整转写稿和待执行的工具调用 [14:20]。删一个文件:是你明确要求的吗?删的是 .git 文件夹吗?上下文不同,判决完全不同 [14:31]。这套机制也管网络调用——curl 一下 Google 试试通不通通常没问题,但上传文件就另说了 [15:04]。

## 网络才是真正的瓶颈

推出 GPT-5.3 Codex Spark(在 Cerebras 上跑到每秒 1000 个 token)之后,团队发现:推理已经不是瓶颈了,**网络才是** [15:53]。于是引入了 **WebSocket 模式**:不用传统的服务器端事件加 HTTP,而是走一条持久化的 WebSocket 连接,既省网络开销,又支持有状态的上下文——只有真正变动的数据才传输 [16:02]。比如一次工具调用完成,只回传那一条结果,而不是把一堆历史项重发一遍;时间一长,提速非常明显 [17:04]。

## 循环:让智能体自己跑,但要能收住

`/goal`(斜杠目标)指令背后的机制是:harness 会不断向智能体注入"继续提示",其中包含你设定的目标,直到智能体自己调用"更新目标"工具、声明目标已达成才停 [18:07]。正因如此,你写目标时别写成长篇大论,要写得**具体且可验证**,这样系统才好判断"做完了没有" [18:33]。

## 压缩:跑几天的长任务也得撑住

为了让智能体能连续跑几小时甚至几天,去年底加入了**自动压缩**机制:在服务器端自动把先前的上下文窗口压成一个"压缩项",保留后续轮次需要的必要信息,而且是用模型训练时见过的方式做的,性能不打折 [19:06]。
