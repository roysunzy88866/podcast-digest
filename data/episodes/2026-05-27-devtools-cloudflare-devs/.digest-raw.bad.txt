===标题===
Cloudflare 三人聊：让模型直接写代码、做点傻事
===导语===
Cloudflare 的 Sunil、Matt 和 Thomas 在 AI Engineers Europe 现场聊 code mode 理念、编码智能体体验，以及为什么该「做点傻事」。
===正文===
这一集是 Cloudflare 的三个工程师——Sunil、Matt 和 Thomas——在伦敦 AI Engineers Europe 会议现场的闲聊，聊的是他们正在做的事和对 AI 工程的看法。

## Code Mode：别给模型一堆工具，让它直接写代码

Sunil 做 code mode 的核心理念很简单：不要给模型暴露一堆静态工具，而是只给一个代码工具，让模型自己写代码去调 API、调外部服务。过去三十年，程序员被教育「永远不要执行一段随机代码」——这意味着整个技术方向根本没人探索过。现在基础模型的能力够强了，这条路终于走得通了。

这个想法最早是借了 Apple 的一篇论文的思路——让模型写 Python 然后直接执行，只是当时模型还不太会写 Python、也不太会做工具调用，效果很差。现在不一样了。Matt 认为这不只是 Cloudflare 会做的事，每个云提供者最终都会走到这一步 [06:55 Matt Carey]。

## 编码智能体的体验：越简单越好

Thomas 最兴奋的两件事：一是 PyAgent，一个极其轻量的编码智能体，只有 read、write、bash、edit 四个工具，但它有一个「扩展」机制——你想加功能，直接让智能体自己写。二是把家里的树莓派通过 MCP 接到 Claude 里当持久沙箱用，换机器也不丢状态 [02:28 Thomas Ankcorn]。

Sunil 特别夸了 PyAgent 的终端界面（TUI），觉得比 Claude Code 和 OpenCode 都流畅，而且库本身非常小，做编码智能体的人都该抄它的界面 [04:28 Sunil Pai]。

## 可观测性 + code mode = 自愈基础设施

把 MCP、code mode 和可观测性串起来，能形成一个闭环：基础设施出了问题，智能体自己写代码去修，不需要人在凌晨三点起来改配置。Thomas 说他的可观测性团队在这条线上还落后，今年会追上来 [10:30 Matt Carey] [11:08 Thomas Ankcorn]。

Thomas 还提到一个现实问题：现在用智能体给 Cloudflare 内部各种仓库提 PR 变得特别容易，但难点变成了「怎么让仓库维护者信任你、愿意合并你的 PR」。他说现在的工作重心变成了跟人搞好关系 [08:09 Thomas Ankcorn]。

## 做点傻事，别过度工程

Thomas 的建议很直白：看到别人做了个很聪明的东西，别想着怎么复刻，去做个更蠢的版本然后扔出去。他自己就做了一个 Matt 的 MCP 服务器的简陋版，很不安全，但能用 [12:51 Thomas Ankcorn]。

Sunil 补了一层更深的道理：过去四年他每三四个月就被模型升级「烧伤」一次——辛辛苦苦为模型能力不足而做的工程补丁，模型一升级就全废了。所以现在的原则是：东西能做简单就做简单、能保持轻量就保持轻量，别过度工程 [13:13 Sunil Pai]。

Matt 的两个期望：一是别再拿 AI 去做增量式的 B2B SaaS 了，想做就做有野心的、原创的东西；二是多做一些消费级的、好玩的、怪的东西 [14:19 Matt Carey]。

## 本集带走

- **code mode 的核心做法**：不给模型一堆工具，只给一个代码工具，让它自己写代码去完成所有操作
- **编码智能体选型参考**：PyAgent 只有四个工具，但通过「让智能体自己写扩展」来补功能，终端体验特别好
- **把家里设备接进智能体**：通过 MCP 把树莓派等设备暴露给 Claude，获得一个跨机器持久存在的沙箱环境
- **别为模型短板做过度工程**：模型每几个月就升级一次，你为「模型不够好」做的复杂补丁很快就会被淘汰，保持简单和轻量
- **做蠢版本**：看到聪明的东西，先做个更蠢的版本丢出去试，别一上来就想做完美的
