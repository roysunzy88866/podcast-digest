## 三、实测逮到、并已修掉的三件事(都不是纸面推演)

1. **「常驻嘉宾」这类节目角色混进了职位**。首跑抽出「Ranjan Roy · 常驻嘉宾」——逐字命中原文、长度也合格,
   但卡片上写这个等于没写。→ 加 `SHOW_ROLE` 闸整串拦掉(常驻嘉宾/特邀嘉宾/联合主持/主持人…),宁可留空。
2. **打回后不重试,直接降级成只留人名**。首跑有 2 集(Qasar Younis / Keith Rabois)只是职位差几个字太长,
   本可以让模型改短,却被我的实现一步降级白丢了。→ 改成**把闸门的原话回喂给模型重试(最多 3 次)**,试满才降级。
3. **长度按字符数算,误伤英文公司名**。`Applied Intuition CEO` 21 个字符被判超长,但它在卡片上只有 10.5 个中文字宽。
   → 改成按**中文字宽**算(拉丁字母/数字/空格各算半个),上限 14 字宽。修完这 2 集全部救回。

## 四、职位命中方式的分布(防失真口径的实际代价)

用户 2026-07-26 定的口径:**不必特别严格**,但要短。落地为两级:

- `verbatim`(33 集):整串在本集中文稿里逐字命中 —— 最干净。
- `spliced`(9 集):整串命中不了,拆成「公司名 + 职位」两段、每段各自逐字命中(每段 ≥2 字)。
  之所以需要它:同一集里标题写「Netflix 产品负责人」、正文写「Netflix 的产品与技术负责人」,只认整串会白丢一大半。
  **这 9 条我逐条对了原文,归属全对**(李飞飞→World Labs 创始人、Zico Kolter→Gray Swan 创始人、
  Keith Rabois→Khosla Ventures 董事总经理 等)。每集的命中方式都记在 `meta.guest_source` 的 `title_match=` 里,事后可审计。
- 命中不了 = 判编造 → **留空**,绝不写进 meta。

## 六、怎么复现这份数字

```bash
# 重跑抽取(默认跳过已有结果;FORCE=1 全部重抽,会重新烧 GLM)
node scripts/extract-guest.mjs --all

# 只做统计与独立复核(不调 GLM,不改任何文件)
node -e 'const fs=require("fs");(async()=>{const M=await import("./scripts/extract-guest.mjs");
const all=fs.readdirSync("data/episodes").sort();
const metas=all.map(d=>JSON.parse(fs.readFileSync(`data/episodes/${d}/meta.json`,"utf8")));
const hosts=M.hostNamesByPodcast(metas);let named=0,titled=0,bad=[],usable=0;
for(const d of all){const p=`data/episodes/${d}`;if(!fs.existsSync(`${p}/digest.json`))continue;usable++;
const m=JSON.parse(fs.readFileSync(`${p}/meta.json`,"utf8")),dg=JSON.parse(fs.readFileSync(`${p}/digest.json`,"utf8"));
const hay=M.chineseHaystack(m,dg),n=m.guest_name||"",t=m.guest_title||"";if(n)named++;if(t)titled++;
if(t&&!M.matchTitle(t,hay))bad.push(`${d}:职位回原文命中不了`);
if(n&&!M.namesInMeta(m).includes(n))bad.push(`${d}:人名不在本集说话人里`);
if(n&&(hosts.get(m.podcast)||new Set()).has(n))bad.push(`${d}:主持人被当成嘉宾`);}
console.log(`人名 ${named}/${usable}、职位 ${titled}/${usable};复核异常 ${bad.length}`,bad);})()'
```
