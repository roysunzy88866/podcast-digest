- 状态:**已采纳**(2026-10-08 用户「需求通过」,DIGEST_V3 打开)。原:待「需求通过」(用户 2026-10-08 两轮盲测拍板写手 + 弹框选「重点标注保留少量」「直接切」)
- 类型:**standard-change(用户授权 2026-10-08)** —— 改浓缩写法与模型(ADR 0013 口径「浓缩 = GLM-5.x 按 condense.md 双语稿浓缩」)+ 事实层闸门加查两项(gate-facts 中文数字/约数、polish 引语核对)
- 关联:ADR 0013 / 0027 · drift #108 · 需求共识「精华写法 v3 · 换写手」节 · user-stories C42

## 背景
用户 2026-10-08:「整个的阅读体验还是很差,是你写不出很好的文案,还是说被"金句"束缚了?」
- 实测第五版样张:嘉宾原话占正文 1%(Jev)/ 9%(KCRW),不是金句拖累。
- 病根三条:写手 GLM 被 2 万多字规则(condense.md 17K + condense-style-v2 4K)压着写;读的是机翻中文稿;写完四道补丁工序(编辑通读/拆句/补小标题/标重点),逐节守门导致「有的节改了有的没改」,读起来是补丁。
- 盲测两轮(同一期 KCRW,不标作者,全过 gate-facts):第一轮 Claude 手写 > GLM 一页要求版 > 现流水线;第二轮 12 模型筛 4 版,用户裁「GLM-5.3 与 Claude 手写并列第一,豆包次之,Claude Sonnet 5 最差」。

## 决定
1. 正文写手 = **GLM-5.3**(`WRITER_MODEL`,默认 glm-5.3),读英文原稿(带 [mm:ss 说话人]),按 `prompts/write-digest.md` 一页要求一口气写;输出 `# 标题 / 导语: / 正文`。
2. 金句另一次调用,system 直接切 condense.md 的金句规矩原文(A/A2/B),读双语稿;金句三联逐字闸门不变。两段拼回原分段格式 → 复用 parseSections/validate/styleErrs/缓存;digest.json 格式不变,加 `writer: "v3"`。新写法用单独缓存 `.digest-raw.v3.txt`,不吃旧缓存。
3. 写完轻量修(polish-zh,writer=v3 分支):人名统一 → **引语核对**(整句引语交 GLM 找英文原句,程序核原句真在原稿;对不上/调用失败 → 去引号改转述,字不增删)→ 去模型自加粗/短词引号 → 重点标注(上限沿用 v2)。不再逐节改写、补小标题、拆长句。
4. 事实层(gate-facts)对 writer=v3 的稿加查:中文写的 ≥10 的数字(含百分之X、月份除外)、「几十/数百/几百万」类约数要原稿有 dozens/hundreds/millions 类说法。存量稿不加查(668 集里 89 集会被「几十」打红)。
5. 开关 `DIGEST_V3=1`(pipeline.yml),用户「需求通过」后打开。

## 理由
- 写得好不好归用户判;两轮盲测给了直接答案,且选中的写手不增加费用。
- 防失真底线不降:专名/数字/时间戳/金句逐字闸门全照旧,另补两个盲测暴露的洞。

## 代价 / 已知限制(用户知情)
- 写手调用更慢(实测 KCRW 37 分钟集约 3 分钟;长集更久)。
- 「三十来年」类约数:原稿出现过 30(哪怕指别的)就核不出,靠写作要求禁止自推兜着。
- 引语核对依赖模型找原句;它若找了一句相关但不同的真原句,程序核不出。
