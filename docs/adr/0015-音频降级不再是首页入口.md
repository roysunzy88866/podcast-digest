# ADR 0015 · 音频降级:只在单集页保留播放器,首页与列表不给音频入口

- **状态**:🟡 **草稿,待用户明文确认**(2026-07-26 起草)。确认前 C13e 不得上线。
- **相关**:`需求共创/UI交互重做-2026-07-25.md` 🔒 拍板 #8;`需求共识.md` **US-5「听中文音频」P0**;C4(音频片)、ADR 0002(TTS 额度)、ADR 0014(TTS 自持)
- **⚠️ 这是「砍核心能力」级改动**:它推翻 `需求共识.md` 里标 🔒 的 P0,按项目铁律须**用户明文 + 改共识 + 记 ADR**三件齐全才算生效。本 ADR 只完成第三件。

## 背景

C4 把音频做成了一等公民:单集页顶部第一块就是播放器,私有播客 feed 可订阅,TTS 是流水线固定一环。

2026-07-25 UI 重做的边界确认(10 维度 · #8 使用场景)里,用户**多选**使用场景时:

- ✅ 勾了「电脑 · 坐下来精读」与「手机 · 碎片时间扫」
- ❌ **没有勾「通勤听」,也没有勾「导出到播客 App / 笔记」**

我当时判定这是「砍核心能力」级别的岔路、不自行处置,列为待拍板项。随后用户三选一**明选降级**。

## 决定

1. **首页与所有列表卡片不出现任何音频入口**(不放播放按钮、不放时长以外的音频标识)。版面让给**金句原话**与**嘉宾身份** —— 这两样是卡片承载判断的主体(🔒 拍板 #6)。
2. **单集页保留播放器**,且位置**上移到标题正下方一条撑满宽的播放条**(用户明确要求「靠顶、要显眼」)。
3. **私有播客 feed 保留可用,但界面上不推**(不做订阅引导、不在首页给入口)。
4. `需求共识.md` 的 **US-5 由 P0 降为 P1**,措辞改为「**在单集页能听中文精华**」——去掉"随时随地/通勤"的暗示。

## 为什么

- **口径来自用户自己的场景勾选,不是我的推断**:两个被勾的场景都是"看",两个跟听相关的都没勾。
- **版面是零和的**:卡片上要放金句(3 行)+ 嘉宾(1 行)+ 标签(1 行)+ 封面,再塞音频入口就得砍金句 —— 而金句被调研认定为本站**最该差异化的地方**(同类文摘站的金句只加粗、不可独立检索)。
- **降级不是删除**:能力仍在(TTS 照跑、播放器照在、feed 照能订),只是**不再占据门面**。真有人要听,单集页第一屏就有。

## 代价 / 残余风险(须用户知情接受)

- **TTS 仍然每集都跑**(edge-tts 免费,ADR 0014),但曝光度降低 → 这部分算力/时间的"性价比"下降。若将来想省,得另做决定(比如只给必读集配音),**本 ADR 不含该决定**。
- 私有 feed 的订阅者不会增长(界面不推)。
- 若日后用户改主意要"通勤听",首页需要重新腾出音频入口,而卡片版面已被金句占满 → 届时要重新做取舍。

## 落地位置(C13a/C13d)

- `build-list.mjs`:卡片模板不含音频元素
- 单集页模板:播放条紧随标题
- 原型参照:`需求共创/原型/index.html`(无音频入口)、`ep-*.html`(标题下播放条)

## 待用户确认的一句话

> 「确认:音频降为 P1,只在单集页保留播放器,首页与列表不给音频入口。」

确认后我改 `需求共识.md` 的 US-5 标记,并把本 ADR 状态改为「已定」。
