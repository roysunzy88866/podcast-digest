# ADR 0025 · 精华开场恢复「落地背景」半(修订 ADR 0020 的过砍)

- 状态:已接受(2026-08-25,用户明文:反馈「今天出的文本…莫名其妙、没有任何背景」→ 拿单集真重跑样张验收「方向是对的」+「留着 Watson/披萨盒这句履历这样挺好」拍板)
- 类型:**standard-change(用户授权)** —— 改浓缩标准段「组织骨架」第 1 条 + 输出格式正文描述
- 关联:ADR 0020(本 ADR 修订其「砍导览段」一条)· 🔒 US-4「8-12 分钟掌握一集」(量级不变)· prompts/condense.md「开场」规则 · drift-log 本次记账

## 背景

ADR 0020(2026-08-11「大砍骨架税」)把导读式的四件套(开场钩子 + **口语导览段** + 每节承接 + 收尾复述)大砍,治好了「框架很顺、实质很薄、全是介绍」。其中被砍的**口语导览段**,早期(756960acc)原文是:

> 口语导览(第二段,2-3 句):**这是谁、什么来头**(来头只用本集/集标题真说过的)、**这一集聊什么**、会听到哪几块——让读者带着地图进正文。

2026-08-25 用户反馈:今天出的正文「一上来就扎进内容、不交代背景、莫名其妙」。逐集核实证实:正文开头是个光秃秃的观点/数字(如 eyeonai 集开头「上个月互联网上智能体流量首次超过人类流量…」),读者不知道**这是谁、哪个播客、在聊什么**。

**根因(git 实证)**:ADR 0020 那一刀砍太宽——导览段里其实混着两半:①**有用的落地**(这是谁、聊什么)②**烦人的预告**(「会听到哪几块」「他讲了三件事」目录腔)。0020 想砍②,却把①一起砍了。于是精华从「框架压实质」滑到另一个极端「开场即冷启动」。

## 决定

**恢复导览段被误砍的「落地」半,保留 0020 对「预告」半的砍除。** 具体改 condense.md「组织骨架」第 1 条:

- 开场第一段(2-3 句、点到为止)必须让没听过这集的读者立刻明白:**① 这一集聊什么 ② 主角是谁(名字 + 一句身份)**,再甩钩子。
- **来头一句带过**:「XX 公司创始人」「前 XX 设计主管」即可;**不展开历史履历**(第几家公司/当年被谁收购/早年做过什么——除非它本身就是个好钩子且本集真讲过,如 Watson/披萨盒那句,用户 2026-08-25 明确「留着挺好」),**不写「会听到哪几块」目录式预告**(0020 砍的那半继续砍)。
- 身份/背景若来自世界知识而非本集转写稿 → 照红线 2.1 放 `> 【背景】` 块,不混进正文。

**不推翻 0020 的实质优先**:主体仍是「怎么做/核心主张/关键洞见」,落地只占开场 2-3 句、不与实质抢篇幅;防失真三闸(2.1/2.2/金句逐字)一字不动。三阶段关系再补一档:金句集锦(碎)❌ → 导读讲解(框架压实质)❌ → 实质优先·全砍骨架(开场冷启动)❌ → **实质优先 + 落地开场(实质为主 + 读者不掉空)✅**。

## 理由

- 这是体验/文案判断,判断权在用户;用户拿单集真重跑样张验收方向与丰度后拍板。
- 「落地」与「实质优先」不冲突:落地只借开场 2-3 句,砍掉的「目录预告/串场/收尾复述」才是真占篇幅的介绍税——两半分开处置,不是回到 0020 前。
- 存量集用云端 refresh 通道重跑(重浓缩→闸门→败者回滚老版),不污染;going-forward 由 cron 自动生效。
