# ADR 0015 · 自动品味判官(还 D44③)

- **日期**:2026-07-25
- **状态**:已接受(用户 2026-07-25 拍板「先做逐集判官,把 D44③ 还了」)
- **切片**:C12(Gherkin 见 `docs/user-stories.md` C12 段)

## 背景:为什么原来没做,为什么现在做

D44③ 当初明确记账缓办,理由写得很清楚:

> 「本切片靠『源已被筛成高对味』省掉判官(源级预筛=硬过滤)。**等真出现『绿源里漏进不对味集』再做 per-集判官**」

也就是说,品味把关**一直是有的,但在「选源」那一层**——人肉把源筛成 🟢 高对味(砍 Latent Space、不接 MLST/Lex 等),然后假定绿源里每集都对味。逐集判官被有意省掉。

**2026-07-25,那个触发条件真的发生了**:`2026-07-24-bigtech-what-happens-if-ai-fails-…`(Big Technology 的周五**新闻回顾体**)走完整条链、过了所有防失真闸门、**自动上线** voice.solomind.cc。

根因是源级预筛的前提在 bigtech 上不成立:**该源一周 2-3 集,混着「单主题深度访谈」和「每周新闻讨论」两种形态,源级粒度切不开**。同一个源里既有要的也有不要的 → 只能逐集判。

## 决策

新增 `scripts/judge-taste.mjs`:读**标题 + 简介**,对照 `需求共创/内容品味档案.md`,判 `publish` / `skip` / `undecided` 三档,接进编排器。

### 1. 判官跑在**转写之前**

只需标题+简介就能判,不必等 whisperX。判掉一集省 **~2 小时 runner**(实测 whisperX 转 66 分钟音频要 119 分钟)**+ 整条付费链**(翻译+浓缩 ≈ ¥1.5/集)。

前置可行性已实测(2026-07-25 本机真抓):六源 feed 的 item 简介长度 562-3107 字符,判官输入充足;bigtech 新闻回顾体的简介首句即 "Ranjan Roy from Margins is back for our weekly discussion of the latest tech news",一眼可判。

### 2. 判官用**付费档 GLM-4.6**,不用免费档

- 输入仅标题+简介几百 token → **≈¥0.005/集,≈¥5/月**(按白名单全接的 960 条/月估)。
- 免费档实测在**判断类**任务上不可靠:`judge-faithful.mjs` 头注记录「免费档判官两次跑否决的是不同的 3 条(5 条好金句随机毙 3 条),否决不可复现≈随机」,并因此被降为提醒层。
- **为省 ¥5 冒判官随机的险不划算。** 这与共识里「判官=免费档」那条不冲突——那条是在**忠实度判官**语境下给的,品味判定是本片新增角色。

### 3. 三档而不是二档:`undecided` 是安全出口

用户 2026-07-25 拍板:拿不准的**进待裁清单攒着集中裁**,不自动发也不静默杀。

理由:二档判官必然在边界上犯错,而两种错的代价不对称——误发一条不对味的会脏站(且钱已花),误杀一条好的则**永远不知道丢了什么**。第三档把「不知道」这件事显式化,成本只是用户偶尔扫一眼清单。

`内容品味档案.md` 的「🔄 更新机制」原本就是这么设计的(发布/跳过/待裁三档),本片把它从设计变成实现。

### 4. fail-safe 方向:坏了就待裁,既不放行也不杀

判官超时、返回非法值、额度用尽、JSON 解析失败 —— **一律落 `undecided`**,`parseVerdict` 结构上不可能返回三档之外的值,也不可能把解析失败当成 `publish`。

这条比标准本身更重要:**判官坏掉时系统应该停下来问人,而不是替人做主。** 单测里专门有一组 fuzz 守这件事。

### 5. 人工翻盘入口

`--force <id>[,<id>]`(workflow 同名 input):点名的集绕过判官直接进付费链。
⚠️ 已知的坑,写在这里免得以后踩:**被判「待裁」的集 cutoff 已经推进**,日常 cron 不会再选中它 → 救它得走 `--backfill`(backfill 无视 cutoff,且待裁集不在 `seen` 里会被重新选中)。

### 6. 存量 39 集只重判、不动站

用户 2026-07-25 拍板「重判,先只出报告不动站」。`--audit` 模式只读,产出 `data/taste-audit.json`,不修改任何已发布内容、不触发部署。

用意是**先验判官准不准**:这 39 集用户都熟,而且有现成的真值锚点——bigtech 新闻回顾集 + Lenny's 那 4 条手动品味排除,判官应该全判 `skip`。判不出来就说明判官不合格,不该接生产。

## 明确不做(防范围蔓延)

- 裁决**自动回写** `内容品味档案.md`(档案的「更新机制」第 2 步)——本片只把裁决记进 state,回写靠人。
- 撤下已上线的不对味集——用户明确「只出报告不动站」。
- 演讲 / YouTube 形态的品味口径——现档案是按「播客访谈」校准的;形态放宽要先走共识修改流程。

## 后果

- ✅ 不对味的集**在花钱之前**被拦掉,省的是大头(whisperX 2h + 付费链)。
- ✅ 品味判断从「靠人记得手动往 skipped 里写」变成机器每集都做,且留痕可查。
- ⚠️ 多了一个 GLM 依赖点:判官挂了会让新集全进待裁(不发布)。这是**有意选的方向**——宁可停下来问人。
- ⚠️ 判官本身的准确率**未经验证**,DoD#2 的存量重判就是第一次真检验,分歧要逐条过用户。
- ⚠️ 判官读的是**简介不是正文**,简介写得含糊或标题党的集子会判不准 → 靠 `undecided` 兜。
