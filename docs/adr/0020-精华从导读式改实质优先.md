# ADR 0020 · 精华从「导读讲解式」改「实质优先」(大砍骨架税)

- 状态:已接受(2026-08-11,用户明文:验收两篇手写新样例——08-09 方法型 + 08-07 观点型——后拍板「把怎么做作为主要的东西」「骨架税大砍」「就这么做」)
- 类型:**standard-change(用户授权)** —— 改浓缩标准段 + C15 机器闸门口径 + 🔒 共识行
- 关联:🔒 需求共识.md「精华 = 导读讲解式(第 11 轮)」行(本 ADR 修订)· 🔒 US-4「8-12 分钟掌握一集」(量级不变)· C15 文稿规范(本 ADR 修订其骨架口径)· drift-log 本次记账 · prompts/condense.md · scripts/condense.mjs styleErrs ④

## 背景

第 11 轮曾把精华方向从「金句集锦式」拨正为「**导读讲解式**」——起因是用户实测金句堆砌「看不懂整篇在讲什么、每段都很突然」。导读式加了必备四件套(开场钩子 + 口语导览段 + 每节承接 + 收尾复述),解决了「碎、跳」的毛病。

2026-08-11 用户验收自动发布的存量集(如 08-09《Cursor 招聘·厄运漏斗》),反馈**「这篇根本看不懂方法究竟是什么,方法全丢了,剩下全是介绍」**。逐段拆解证实:导读式把篇幅大量花在**组织骨架**上——导览段预告(「他讲了三件事」)、每节整段串场承接(「说完 X,接下来 Y」)、「本集带走」再复述一遍主张——加上跑题的行情段,一起把**方法的「怎么做」挤成了梗概**。即:导读式治好了「碎」,却滑向了另一个极端「框架很顺、实质很薄、全是介绍」。

用户判断:**要把「怎么做 / 核心实质」当主体**。这是体验/文案类判断,判断权在用户。

## 决定

精华方向从「导读讲解式」修订为「**实质优先**」:这一集最值钱的东西(怎么做 / 核心主张 / 关键洞见)就是主体、占大头,**给读者实质本身,不是对实质的介绍**。骨架大砍、退居服务位:

1. **主体 = 源里的实质**。方法/工具型 → 主体就是「怎么做」(每步具体做法、门槛、坑,源里讲多少给多少);观点型 → 主张 + 论据/推理链;故事/议题型 → 转折/交锋实质。
2. **开场钩子保留(1-2 句)**,但**砍掉导览预告段**(不再写「他讲了三件事……」);读者靠小节标题 + 每节第一句点题导航。
3. **承接压到半句**:禁止冷启动的初衷(别让读者莫名跳题)保留,但用半句或小节标题解决,**不写整段串场**(这是最大的「介绍税」)。
4. **偏题的行情/背景让位**,精简进一小段,不与实质抢篇幅。
5. **「本集带走」= 可带走的几条具体要点**,允许**要点列表**(每条要具体、能上手/能复述,不是主张复述、不是空话)。
6. **字数放软**:不硬凑 2800-4000,以「把实质讲透」为准(约 2000-3500 字,密度优先);仍对齐 🔒 US-4「8-12 分钟掌握」的量级。

**这不是推翻第 11 轮,是把它再拨正一档**:第 11 轮的**反碎片护栏保留**——仍要一条主线、连贯顺读(没听过也能读明白)、术语首现一句大白话解释、AI 补背景用 `> 【背景】` 明确标注。三个方向的关系:金句集锦(碎)❌ → 导读讲解(框架压实质)❌ → 实质优先(实质为主、框架服务)✅。

**机器闸门联动改(standard-change)**:`scripts/condense.mjs` 的 `styleErrs ④` 原「本集带走不许列表腔」**放开**——实质优先下带走=要点列表反而更清爽;保留「## 本集带走 必在」。质量(是否空话)交判官与用户眼睛,不机器卡。防失真三闸(2.1 专名/数字回源、2.2 时间戳、金句逐字)一字不动。

## 理由

- 用户是精华的第一读者与品味权威,两篇手写样例(方法型 + 观点型)当面验收通过——目标由「样例 approve」坐实,不是我照自己口味改。
- 「实质优先」直接针对实测病灶(方法被骨架税挤没),同时靠保留的反碎片护栏,不回退到第 11 轮之前的「碎、跳」。

## 影响

- **只影响新集**:`refresh-digests` 是手动入口、日常 cron 不自动调它(pipeline.yml 仅在 `REFRESH` 手动派发时跑),故改 prompt/闸门只作用于此后新浓缩的集。
- **存量 100+ 老集维持导读式**:放开 styleErrs ④ 不会把老集判成待刷(老集是连贯段、开头有钩子,照样过闸)。要不要把老集统一翻成实质优先 = 另一个决策 + 另一笔重烧钱,记 tech-debt,不在本 ADR 范围。
- **闸门无法机器区分「导读式 vs 实质优先」**:两者都过 styleErrs;故 `alreadyConformant` 不能据此识别老格式(未来若要按新格式重刷老集,得另立判据)。已在 tech-debt 记。
- 配套:condense.test.ts / refresh-digests.test.ts 的带走列表断言按新口径改（25 项绿）;C15 Gherkin 同步(导览 scenario 退役、承接软化、带走允许要点)。
