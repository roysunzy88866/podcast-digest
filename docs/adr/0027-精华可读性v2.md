# ADR 0027 · 精华可读性 v2:手机每段 ≤50 字 + 长句/中英夹杂/人名/衔接

- 状态:**待「需求通过」**(用户 2026-10-04 弹框拍板;文风部分另需样张验收)
- 类型:**standard-change(用户授权)** —— 改浓缩提示词(prompts/condense.md)写作规则 + 渲染分段口径(修订 C19「每 2–3 句切一段」,仅对新内容)
- 关联:C19(按句分段)· ADR 0020 / 0025(浓缩骨架)· 需求共识「精华可读性 v2」节 · ADR 0026(同轮)

## 背景
用户 2026-10-04:文案「衔接不是很顺畅……可读性很差」「手机上阅读……一个段落这个行数太多」。
实测近 73 集网页正文:每段中位 91 字、P90 150 字、最长 326 字;每段中位 2 句 → 句子过长,C19 按句数切分无效。
古怪感实例(2026-10-01 KCRW 集):中英夹杂(「联邦 funding」「truly 没有任何媒体」)、同一人两种拼写(Farrow/Ferro)、翻译腔长句、节间硬切。

## 决定(用户拍板)
1. 手机上每段约 3 行、**≤50 个汉字**(按长度切,替代 C19 的按句数切)。
2. 文风改写**先看 2 期前后对照**,用户认可后才生效。
3. **存量都不动**:新分段/新写法只对 2026-10-04 之后新上站的期生效(渲染分段按入库日分流,保证老集重建站时不变)。

## 技术配套(📌 Claude 定)
长句(>60 字)机器标出交模型改写;正文普通英文单词自动译成中文(专名与通用技术缩写白名单);同一人名以节目官方信息统一拼写;浓缩提示加「每节开头承上启下、一句一事、不用翻译腔」。

## 补充(2026-10-04 看样张后)
用户:「文风我觉得还行。布局上可能需要加一些重点的下划线和加粗,不用加太多……就加在重点结论和重点问题上。」
实现:**单独一步**(不让浓缩模型边写边加,免得到处加粗)—— 模型只从每节原文**逐字摘**片段,程序校验后机械加标记:结论 `**…**`、问题 `==…==`(Quartz 渲染 .text-highlight,custom.scss 改为主题色下划线)。每节各 ≤1、全篇各 ≤6、片段 ≤40 字、不含句中断点(防分段切断标记)、不碰双链/时间戳/已有标记;正文一字不改。

## 代价(用户知情)
- 段落数会明显变多,页面更长但更好扫读。
- 新旧内容风格会并存(存量不动)。
