# ADR 0018 · Mac mini 抓取代理 + 演讲订阅自动巡航(撤「无常开机器」🔒 之一角)

- 状态:已接受(2026-07-31,用户明文:「Macmini 一直可用…活着的。抓取清单应该也是自动的吧,根据订阅的情况,而不是我口头告诉你」;订阅组合用户选「按推荐订 4 个」)
- 关联:ADR 0017(演讲精选通道)· 需求共识 CONSTRAINTS ①「全云端无 Mac mini」🔒(本 ADR 局部修订)· `调研-新源候选-2026-07-24.md` 📡 频道候选节 · 切片 C17

## 背景

C16 验证批实证「本机抓一手 → 云端接力」全链可用(3 条演讲全链上站,run 30600074547)。但抓取侧仍是人工点名+人工执行;用户拍板:发现新演讲应当**订阅驱动全自动**。YouTube 封云端机房 IP(调研-内容获取可行性),抓取必须住宅 IP;用户的 Mac mini 常开(跑每日新闻项目),具备住宅 IP,是天然抓取代理。

## 决定

1. **共识 CONSTRAINTS ①「全云端、无常开机器」局部修订**:Mac mini 以**抓取代理**身份回归——只做「发现+下载+上传+提交种子」,不做任何内容处理(转写/翻译/浓缩/TTS 仍全云端)。第 27 轮拍板的理由(播客 RSS 不需要它)对播客源仍成立;YouTube 独占内容给了它新的、唯一的存在理由。
2. **订阅 v1 = 4 频道**(用户拍板「按推荐订 4 个」):AI Engineer / Axios / LangChain / Stripe(channel_id 与过滤规则见调研文档 📡 节)。Figma/Vercel/Milken/Hoover 等一波流频道留人工圈选通道(C16 既有)。
3. **发现机制**:优先频道 XML feed;**该端点 2026-07 起大面积 404**(实测+社区佐证),备胎=频道 /videos 页 HTML 解析(调研已验通)。接入时在 Mac mini 实测择通道,两条都实现、可切换。
4. **品味过滤**:新视频先过账本去重,再过 GLM 品味判官(读标题+简介,按 `内容品味档案.md` 口径打分;每条成本分级别),对味才下载。判官打分与放行/拦截逐条留痕(巡航日志),供人工复核纠偏。
5. **云端衔接**:Mac mini 提交种子(seed.json)并推送后,**cron 例行班次自动接管**(activeSources 放开:有待处理种子时 talks 源自动进场)——去掉「人工点火 talks=true」这一步;手动 dispatch 入口保留(人工圈选批次用)。
6. **防钓鱼**:凡按 handle 解析 channel_id 必须校验频道页 title(实测 @BloombergOriginals 是山寨频道)。
7. **运维边界**:Mac mini 侧独立目录+launchd 定时任务,不触碰每日新闻项目;失败在仓库留响亮痕迹(巡航日志文件随种子提交);yt-dlp 版本随 YouTube 反制需人工升级,属已知维护成本(用户知情)。

## 后果

- 演讲从「用户口头点名」变「订阅自动发现」,人工只剩品味纠偏与一波流频道的圈选。
- 新增一台机器的运维面(可控:无内容处理、无密钥进仓、挂了只影响演讲增量不影响播客主线)。
- GLM 品味判官新增小额持续成本(周 5-10 条过滤量级)。
