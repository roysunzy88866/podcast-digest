# 内容流水线全景 · 一篇内容的一生

> 2026-08-21 应用户要求整理(起因:「222 纳米光」偏题集上站 + 下架时延)。
> 真相源口径:本文描述**现状**,与代码对齐;改流程时同步改这里。
> 行为细节的最终真相仍是 Gherkin+测试(CLAUDE.md 真相优先级),本文是给人看的地图。

## 〇、什么时候跑

- GitHub Actions 定时 4 班(北京 00:30 / 06:00 / 12:00 / 18:00)+ 手动触发。
- 单班预算 5 小时(平台硬上限 6h,workflow 另设 5.5h 兜底)。
- **时间预算守卫(C32)**:每开一集前按「音频时长 × 1.9 + 30 分」估这一集要多久
  (feed 不给时长按 220 分最坏算;本地已有转写稿只算 30 分),不够做完就停手,
  已完成的正常发布,没做的登记 retry 留给下一班。

## 一、一集怎么被选中(三条入口)

1. **新集**:每源一条 cutoff(只向前看),feed 里 cutoff 之后的集。
2. **补活**:上一班留下的半成品(有 digest 无集页),连败 3 次停手待人工。
3. **补历史顶量(C23/C31/C33)**:当天(北京日)入库不足 8 集(**只数 2026 年的集**)时,
   从全源候选池(≥2026-01-01、未入库、未隔离)**跨源统一按最新**挑,窗口内有官方稿的优先。

**选集阶段的校验(按顺序)**:
| # | 校验 | 方式 | 拦截力 |
|---|---|---|---|
| S1 | 是访谈(有音频、非 ainews 快讯) | isInterview | 硬 |
| S2 | 没做过/没隔离过(ID 去重) | completedIds + skipped 账本 | 硬 |
| S3 | 跨源同标题去重(同一场访谈只留最新) | dedupeCandidatesByTitle(C33) | 硬 |
| S4 | 题材关键词(仅 doac 源) | topicFilter/isOnTopic | 硬(单源) |
| S5 | **品味判官(C34,全源)**:标题+时长 vs 品味档案,免费 GLM 判「对味/不对味」 | taste-judge | 硬;判官挂了放行(不让故障清零产量);拒的记终态不重判 |
| S6 | 时间预算够做完这一集 | estimateEpisodeMin(C32) | 硬(本班,下一班重试) |

## 二、逐集处理链(processEpisode,任何一步炸 = 留半成品下班重试)

| 步 | 干什么 | 校验 |
|---|---|---|
| ① 取稿 | 三条路:a) feed 自带官方转写稿(srt/vtt/json,秒级) b) Substack 官方 transcription.json c) whisperX ASR 兜底(音频先查中转站 C30,403 登记待搬运→Mac mini 住宅出口代抓) | **transcript-guard 归属校验**(官方稿:稿末时间 vs 官方时长,超容差即死,防拿错集的稿=drift #59 事故);ASR 内置 VAD+专名词表偏置 |
| ② 认人 | infer-speakers:SPEAKER_xx → 真名 | grounding 校验(名字须在稿内出现,不编) |
| ③ 翻译 | GLM-4.6 全译(双语对齐存档) | 内容审查 [1301] 拦 2 次判终态放弃(敏感集不死锁) |
| ④ 浓缩 | GLM-5.3 出中文精华(分隔符分段纯文本→程序化拼 JSON,防坏稿) | styleErrs 机器卡口语体硬伤 → 回喂重试 |
| ⑤ 金句判官 | 免费档 GLM ×3 票,**只投否决票**,一票否决 | 宁缺毋滥(最少 4 条) |
| ⑥ 金句规整 | repair-quotes:snap 回逐字、派生时间戳/说话人,救不回的丢 | — |
| ⑦ 实体抽取 | extract-entities → 双链/类型化属性 | — |
| ⑧ **金句三联闸门** | gate.mjs | **硬拦:引语逐字命中转写稿**(时间戳/说话人降软提醒,ADR 0013) |
| ⑨ **事实闸门** | gate-facts | 硬拦:专名回原文(D17 词形分流)、数字(含 half=0.5)、时间戳区间;**失败自动修一次再验**,仍不过→隔离进 data/skipped(不发布、留人工) |
| ⑩ 嘉宾字段 | extract-guest(人名限说话人候选,职位逐字回稿验) | 硬(字段级) |
| ⑪ 出集页 | render.mjs(**过了闸门才出页**) | — |
| ⑫ 配音 | tts.mjs(项目自持,为何不走全局配音 skill 见 ADR 0014;只念缺音频的集,微软免费引擎 + Azure 兜底) | — |

## 三、全库闸门(gate-all,每班收尾跑一次,五层)

1. **金句层**:全库每集金句仍逐字命中各自转写稿
2. **事实层**:专名/数字/时间戳全库复验
3. **实体层**:实体页死链/一致性/属性事实
4. **关联层**:相关单集 0 死链
5. **音频层**:每集音频存在/时长/源一致/enclosure 真实
+ 软提醒:跨集译名漂移(同一实体多个中文名 → 提示钉词表)

## 四、上站(部署解耦,drift #68/#69)

- `has_new`(有干净新集)**且** `gate_ok`(部署前**独立重跑一遍 gate-all**)才部署 → CF Pages。
- 编排器失败不拖累已完成集上站;闸门没过的内容永远上不了站(手动 deploy 也绕不过 gate_ok)。
- 回仓:产物 + cutoff/skipped 账本 commit 回 main(pull --rebase ×3 重试,失败响亮告警)。

## 五、事后与旁路

- **人工点名下架**:移出库 + 记 skipped 账本(防再抓)+ 重建 + 重部署。⚠️ 时延:重部署要跑
  完整 build(含音频缓存恢复),约 15-30 分钟才在线上消失 —— 2026-08-21 用户看到「没下架」即此窗口。
  ⚠️ 薄弱点(2026-08-22 实测发现):下架若没顺手重跑 build-entities,引用该集的**实体页留死链**
  (「222 纳米光」下架后 57 个实体页挂线上直到重建;两个只此一集的实体页该删没删)。
  下一班 build-entities 会自愈,但下架到下一班之间线上实体页点过去是 404 —— 下架操作应带上实体重建。
- **品味档案是活文档**:用户裁一次边界 → 回写档案 → 判官下一班就按新口径判。
- **演讲线**(支线):Mac mini 巡航 YouTube 订阅 → 品味判官(付费档)→ yt-dlp 抓音频 →
  Release 种子 → 云端同一条处理链。
- **音频搬运工**(支线,C30):runner 被封 IP 拿不到的音频 → 登记清单 → Mac mini 定时代抓 →
  Release 中转站 → 云端优先取,用后清。
- **开发面**:每刀代码改动过 GLM 检查员冷审 + 裁决落账;commit-msg 钩子;1087 单测。

## 已知薄弱点(如实)

- 品味判官只看**标题+时长**,标题含糊的边界集可能误放/误拒(误拒记终态,人工点名补)。
- 转写倍率 1.9 由单样本反推,再出现超时被杀就上调。
- 补活/refresh 不再过判官(操作的是已入库内容,防翻脸下架)。
  **存量不需要清查**(2026-08-21 用户指出后核实):品味筛选一直存在于**源清单层**
  (2026-07-19 用户拍板只留高对味源,两次扩源均逐个调研拍板),存量 166 集里
  Lenny's 76 + 演讲 32(演讲还逐集过了巡航判官)+ 其余高对味源,天然干净;
  仅有的 2 集泛题材源(twentyvc)已人工核对对味。C34 逐集判官补的是
  「泛题材源 2026-08-16 进补历史池 + C33 跨源挑最新大量从它们取」之后才出现的新口子。
