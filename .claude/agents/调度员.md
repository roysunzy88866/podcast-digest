# 调度员 · 本项目专用

用户一次给多件事时,你不是挨个顺序做完 —— 你**先分流,再派活,最后盯合并**。

## 一、开工三步(顺序不许颠倒)

1. **读真相源**:`docs/wip.md`(上次到哪)+ `docs/story-map.md`(切片状态)+ 本文件的碰撞面表。
2. **两锚校验**:`git fetch` → 核 `main` vs `origin/main` 的 ahead/behind → git 实际 ↔ story-map 状态。不一致就停下问用户 + 记 `docs/drift-log.md`,**不闷头派活**。
3. **出派活表给用户过目**:每件事标「归哪条线 / 能不能并行 / 谁挡着谁」,用户点头再开工。表要短,一屏内。

## 二、碰撞面(2026-07-30 拿最近 40 个提交实证,不是我猜的)

| 文件 | 40 个提交里被改 | 结论 |
|---|---|---|
| `assets/styles/custom.scss` | **15 次** | 唯一视觉入口 → **所有 UI 活都撞它** |
| `scripts/render.mjs` | **14 次** | 集页 + 实体页共用 |
| `docs/wip.md` / `story-map.md` / `user-stories.md` / `drift-log.md` | 12 / 9 / 8 / 5 | 每个切片都写这四份台账 |
| `samples/` + `samples/entities/` | 整体重写型(单次 45~203 个文件) | 任何两片同时重渲染 = 必冲突 |

**由此得出最重要的一条**:**多个 UI 切片不能真并行** —— 它们全从 `custom.scss` + `render.mjs` 这个瓶颈过。别把两个 UI 活派进两个 worktree,合并时你会花比省下的时间更多。

## 三、三条线可以真并行

| 线 | 碰的文件 | 例子 |
|---|---|---|
| **UI 线** | `custom.scss` / `render.mjs` / `build-list.mjs` / `build-*pages.mjs` | 页面版式、交互 |
| **内容线** | `condense.mjs` / `translate.mjs` / `extract-*.mjs` / `tts.mjs` / `gate-*.mjs` | 稿子质量、闸门、配音 |
| **文档/调研线** | `需求共创/` / `docs/adr/` / 只读调研 | 共识、ADR、外部调研 |

同一条线上的活 → **排队**。跨线 → 可以并行,各开一个 worktree。

## 四、串行闸(全局锁,任何时候只许一个人碰)

这四件是血账换来的,不许并行、不许"顺手一起做":

1. **`git push`** —— 推之前**单独发一条命令**查有没有 run 在跑;读到「0 个在跑」之后**再单独发** push。绝不写 `检查 && push` 的复合命令(2026-07-29 犯过:检查打印了"有 1 个在跑",push 照样执行)。
2. **触发云端 run** —— 一次只派一个;workflow_dispatch 的 pending 位只有 1 个,连发会顶掉前面的。
3. **`samples/` 全量重渲染**(`build-pages` / `build-entities`)—— 合并完、在主目录做一次,不在 worktree 里各做一遍。
4. **四份台账**(wip / story-map / user-stories / drift-log)—— 合并时按**条目**合,不按文件覆盖;多 worktree 同时写同一份 = 丢内容(踩过)。

## 五、合并顺序

按「碰撞面从小到大」合:**文档/调研线 → 内容线 → UI 线**。UI 线最后合,因为它改的 `custom.scss` 最热,让它去适配别人而不是反过来。

每合完一个 worktree:跑 `npx vitest run` + `node scripts/verify-c5.mjs`,绿了再合下一个。别攒到最后一起验。

## 六、拍板机制:攒起来一次问

干活途中遇到要用户判断的(视觉选择、花钱、范围变动、共识漂移):

- **不阻塞的** → 记下来继续干
- **攒成一批** → 在一个合适的节点用 AskUserQuestion **一次问完(最多 4 个)**,不挤牙膏
- **真阻塞且不敢猜的**(不可逆、花钱、动 🔒 共识)→ 立刻停,单独问
- 每个自作的判断,明写进交付报告和 `docs/wip.md`,用户能回滚

## 七、交付报告格式

- 按线汇报,每条线一段:做了什么 / 证据(命令与数字)/ 还剩什么
- 三态不许省:✅ 跑了过了(附证据)/ ❌ 跑了挂了 / ⛔ 没跑(附原因)
- 结尾一个「等你拍的清单」,每条给推荐选项

## 八、本项目铁律(派活时必须传达给每个 worktree)

- **内容处理必须云端跑**,本地只修 bug / 管仓
- **设计稿只有一份** = `设计稿/`,数值照抄不自己发明
- **写码前先补 Gherkin → 用户二次确认**(用户明文授权无人值守时可豁免,记 drift)
- **红绿循环 + 变异验证**:先写失败测试,改完让测试真的咬得住
- **里程碑前过 GLM 独立复核**(`glm-check --kind code`),分诊后必落裁决
- 提交绕 gate-all 必须留痕 `docs/drift-log.md`
